# execute_code остаётся аварийным люком для отсутствующих инструментов

## Решение

Маршрут `/execute_code/` не убирается, хотя он же — главная дыра в безопасности
проекта. Он исполняет произвольный IronPython внутри Revit с полным доступом к `doc`,
`DB`, `revit`, `clr`, `System` и нетронутым `__builtins__`.

## Обоснование

Это де-факто фолбэк на любую отсутствующую возможность. Когда типизированного
инструмента для задачи нет, ИИ-ассистент пишет нужный код на IronPython прямо в
рантайме и получает результат. Практически это очень мощно: 48 инструментов не
покрывают Revit API даже близко, а `execute_code` покрывает его весь.

## Обратная сторона — и это настоящая проблема

> [!danger] Давление на добавление нормальных инструментов снимается самым опасным путём
> Каждая дыра в возможностях, меняющая модель, закрывается отправкой нетипизированного
> кода по HTTP. Без схемы, без валидации, без аудита сложнее одной строки в логе.

То есть архитектурный долг здесь **самоподдерживающийся**: пока люк удобен, стимул
писать типизированный маршрут отсутствует.

## Предложенное решение

Не удалять, а **переставить стимулы**:

1. Закрыть маршрут за env-флагом `REVIT_MCP_ALLOW_EXEC`, по умолчанию выключенным —
   opt-in на этапе загрузки расширения.
2. Требовать заголовок с общим секретом.
3. Постепенно поднимать часто исполняемые сниппеты в типизированные маршруты под
   `revit_mcp/`.

Пункт 3 — самое важное: он превращает люк из замены системе типов в источник данных о
том, каких инструментов не хватает.

## Известные технические дефекты этого файла

- **`sys.stdout` не восстанавливается в `finally`** — см.
  [[sys.stdout может остаться закрытым StringIO до конца сессии Revit]].
- **`traceback.format_exc()` уходит клиенту** — раскрывает абсолютные пути и версии
  библиотек.
- Транзакция открывается **всегда**, даже если код ничего не меняет. Именно поэтому
  сохранение модели через `execute_code` невозможно — см.
  [[Save и SaveAs выполняются вне транзакции]].

## Полезная деталь реализации

`clr` и `System` предымпортированы в пространство имён специально, чтобы вызывающий
мог использовать 2027-безопасный паттерн `DB.ElementId(System.Int64(id))` — хелперы из
`revit_mcp/utils.py` внутри `exec` недоступны. Комментарий в коде объясняет это прямо.

См. [[Bare DB.ElementId(int) в Revit 2027 падает на неоднозначности перегрузок]].
