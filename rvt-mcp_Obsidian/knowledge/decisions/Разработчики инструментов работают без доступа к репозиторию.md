# Разработчики инструментов работают без доступа к репозиторию

## Решение

Пользователь явно отклонил модель «отдельный репозиторий-приёмник с PR» и
модель «доступ в основной репозиторий»: разработчики инструментов не имеют
доступа к репозиторию вообще. Они собирают самодостаточный `.zip`-пакет
(два модуля, манифест, заметки) и кладут его в папку `inbox\` на общей
папке. Сборкой, ревью и коммитом занимается сопровождающий — единственный,
у кого есть доступ.

## Почему это стало возможно только сейчас

Модель работает исключительно благодаря
[[Регистрация — автообнаружение вместо рукописных списков]]: возможность —
это ровно два файла, не трогающих ни одного общего. До автообнаружения
пакет пришлось бы либо давать разработчику права на два барреля, либо
сопровождающему вручную дописывать в них строки за каждого — оба варианта
не масштабируются на нескольких независимых людей.

## Три компонента

- **`contrib-kit/`** — набор на чистой stdlib, без `uv` и `pytest` (у
  разработчика их может не быть; у него штатно есть Revit + pyRevit +
  RevitMCP). Команды `new` / `check` / `probe` / `pack`. `probe` — ключевая:
  прогоняет обработчик маршрута на **собственном** Revit разработчика через
  `/execute_code/`, то есть разработчик видит реальное поведение на реальной
  модели, ни разу не клонировав репозиторий.
- **`scripts/intake_package.py`** — приёмка у сопровождающего: белый список
  файлов, коллизии имён, статический скан опасных конструкций, прогон
  полного `pytest` в изолированной копии дерева.
- **`scripts/build_contrib_kit.py`** — копирует `scripts/conventions.py` в
  набор при сборке, чтобы проверка на стороне разработчика была
  байт-в-байт той же, что приёмка. Расхождение здесь — худший сценарий:
  разработчик видит «всё хорошо», сопровождающий отклоняет пакет,
  доверие к инструменту падает.

## Явный предел автоматики

Зафиксировано текстом в `AGENTS.md`, `INSTRUCTION.md` набора и в выводе
`intake_package.py`: автоматические проверки могут **только отклонять**.
Пройденная приёмка означает «можно читать», не «можно брать». Принимаемый
код — это IronPython, исполняющийся внутри процесса Revit с полным доступом
к API и файловой системе на каждой станции отдела; ни одна статическая
проверка не оценивает намерение. Одобрение — решение человека, прочитавшего
оба модуля.

## Проверено

Три сценария на реальных пакетах: чистый пакет принят и прогнал 544 теста
с применённым кодом; пакет с правкой `deploy/install.cmd` отклонён явно
(«files outside the allowed layout»); пакет с `import subprocess` помечен
для решения человека, не пропущен молча.
