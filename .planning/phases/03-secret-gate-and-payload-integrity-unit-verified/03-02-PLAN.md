## Decision reconciliations (adopted from 03-RESEARCH.md)

- **C6 (SC7 "config.cmd or equivalent generates"):** a `.cmd` cannot produce a CSPRNG token
  reliably. `deploy/config.cmd` will only define `MCP_SECRET_FILE` (plan 03-07); generation is this
  CPython tool, which satisfies "or equivalent".
- **C5 (threat-model honesty):** the secret ends up in `ext\` and in the payload on a
  department-readable share, so it is a network barrier against LAN callers, not protection against
  anyone who can read the share or an installed payload. The tool's module docstring says so in one
  plain sentence; plan 03-07 repeats it in `deploy/config.cmd` and CLAUDE.md.

## Execution rules for every task in this plan

- `deploy/` and `scripts/` are CPython-side and not dialect-checked, but these two tools must run
  under pyRevit's embedded CPython, which is 3.8 on pyRevit 4.8 hosts: write them for Python 3.8+
  (no annotations, no `match`, no 3.9+ string or dict methods), standard library only.
- Tests must never create a file in the real repository: every secret path is under `tmp_path`.
- Run `uv run pytest tests/unit -q` before every commit. Task 1 commits in two steps:
  `git add -- deploy/secret_tool.py tests/unit/test_secret_pipeline.py` (both are brand-new, and a
  pathspec commit alone rejects an untracked file with "did not match any file(s) known to git"),
  then `git commit -m "<message>" -- deploy/secret_tool.py tests/unit/test_secret_pipeline.py`.
  Task 2 uses the dirty-tree protocol below, whose `git update-index --add` already registers the
  new `scripts/dev_secret.py`. Never `git add -A`, `git add .` or a directory pathspec. End the
  message with the attribution line your session specifies.

## Dirty-tree commit protocol (Task 2 only: `.gitignore` carries the user's uncommitted edits)

`.gitignore` already has an uncommitted user hunk (the GSD block commented out). A pathspec commit
would sweep that hunk into this plan's commit, and the index also holds unrelated staged files.
Commit Task 2 through a temporary index whose `.gitignore` is HEAD's content plus only this task's
lines. `$SCR` is a scratch directory outside the repo (your session's scratchpad).

```bash
SCR="<your scratchpad>/p03-02"; mkdir -p "$SCR"
git show HEAD:.gitignore > "$SCR/gitignore.head"
# Append exactly this task's block to $SCR/gitignore.head (Read it, then Edit it) - the same
# lines Task 2 appends to the working-tree .gitignore.
export GIT_INDEX_FILE="$SCR/index"
git read-tree HEAD
git update-index --add --cacheinfo "100644,$(git hash-object -w --path=.gitignore "$SCR/gitignore.head"),.gitignore"
for f in scripts/dev_secret.py tests/unit/test_secret_pipeline.py; do
  git update-index --add --cacheinfo "100644,$(git hash-object -w "$f"),$f"
done
git diff --cached --stat HEAD      # must list exactly these three paths
git commit -m "<message>"
unset GIT_INDEX_FILE
git reset -q -- .gitignore scripts/dev_secret.py tests/unit/test_secret_pipeline.py
git diff -- .gitignore             # must show only the user's pre-existing hunk
```
