# Requirements: revit-mcp-server — milestone v0.1 «Доверенный мост»

**Defined:** 2026-09-21
**Core Value:** Ассистент может достоверно читать и изменять модель Revit — и инженер может доверять тому, что ответ сервера описывает то, что действительно произошло.

## v1 Requirements

Требования этого milestone. Каждое отображается в фазу дорожной карты.

### Идентичность (IDENT)

- [x] **IDENT-01**: `/status/` возвращает идентичность процесса Revit — PID, версию Revit, порт и токен сессии, выданный один раз при запуске процесса
- [x] **IDENT-02**: Каждый ответ мутирующего маршрута называет документ, который он изменил (заголовок и путь), а не только результат операции
- [x] **IDENT-03**: Идентичность документа разрешается на момент запроса, а не берётся из кэша — остаётся корректной после `OpenAndActivateDocument` и при смене активного документа пользователем в UI
- [x] **IDENT-04**: Два документа с одинаковым заголовком (два `Project1`) различимы по полям ответа
- [x] **IDENT-05**: Порт pyRevit Routes настраивается переменной окружения `REVIT_PORT`, как сейчас настраивается только хост

### Разрешение неоднозначности (AMBIG)

- [x] **AMBIG-01**: Наличие двух слушателей на одном порту обнаруживается до отправки запроса
- [x] **AMBIG-02**: При обнаружении двух слушателей сервер отказывает явной ошибкой вместо обращения к недетерминированно выбранному процессу
- [x] **AMBIG-03**: Инженер видит в сообщении об отказе, какие именно процессы конфликтуют (PID), чтобы закрыть лишний
- [ ] **AMBIG-04**: Репродукция `param-write-rolls-back` повторно проверяема при видимой идентичности — гипотеза «отвечал другой процесс» становится подтверждаемой или опровергаемой

### Мультидокумент (MDOC)

- [x] **MDOC-01**: Инженер может получить список открытых в сессии Revit документов с идентичностью каждого
- [x] **MDOC-02**: Мутирующий инструмент принимает явный идентификатор документа в вызове
- [x] **MDOC-03**: Мутирующий вызов без явного документа не угадывает молча — поведение по умолчанию явно определено и описано в докстринге инструмента
- [x] **MDOC-04**: Инженер может переключить активный документ отдельным инструментом
- [x] **MDOC-05**: Обращение к документу, закрытому после получения списка, даёт понятную ошибку, а не работу не с тем документом

**Уточнение области гарантий фазы 2 (решение пользователя, 2026-10-16, D-15):** MCP-инструмент `execute_revit_code` и наш HTTP-маршрут `/execute_code/` остаются включёнными как доверенное выполнение произвольного кода. Для эффектов такого кода не обещаются изоляция одного документа и полнота атрибуции фактически изменённых документов (IDENT-02/03, MDOC-02/03/05): проверка внедрённого `doc` не ограничивает доступ через `revit`, `DB`, `clr`, `System` и builtins. Это явное исключение из исходной общей формулировки, не выполненная защита и не основание отмечать требования завершёнными. Гарантии типизированных операций сохраняются; контракты и тесты downstream-планов подлежат согласованию с D-15 до исполнения. Требования секретов/целостности фаз 3/5 этим решением не отменяются. См. `02-CONTEXT.md`, раздел Preflight decision amendment.

**Уточнение MDOC-04 (решение пользователя, 2026-10-16, G4):** на первом этапе разрешается только измеренная активация уже открытого сохранённого документа с пригодным существующим файловым путём. Несохранённые и отсоединённые документы без такого пути получают явный отказ; нельзя автоматически сохранять, повторно открывать или подставлять исходный путь вместо текущего документа. Неизмеренные случаи, включая сохранённую workshared-модель, не разрешаются по аналогии. Это принятое ограничение области, не завершённая реализация MDOC-04 и не одобрение общего checkpoint; наблюдение диалогов остаётся отдельной проверкой. См. `02-CONTEXT.md`, раздел G3/G4 preflight measurements.

### Секрет и сеть (SEC)

- [x] **SEC-01**: Мутирующие маршруты требуют общий секрет; запрос без верного секрета отклоняется до открытия транзакции
- [x] **SEC-02**: Секрет едет в теле запроса по уже доказанному пути `text/plain` + `parse_request_data()`, без нового непроверенного кода разбора
- [x] **SEC-03**: Отказ по секрету возвращает не-200 и доходит до модели как видимая ошибка, а не как ложный успех
- [x] **SEC-04**: Сравнение секрета выполняется за постоянное время на обеих половинах моста
- [x] **SEC-05**: Читающие маршруты и `/status/` остаются доступны без секрета — диагностика не блокируется рассогласованием секрета
- [x] **SEC-06**: Секрет не попадает ни в журнал аудита, ни в лог, ни в текст ошибки
- [x] **SEC-07**: Расширение обнаруживает бинд Routes не на loopback и сообщает об этом как о небезопасной конфигурации
- [x] **SEC-08**: Секрет генерируется и внедряется в payload на этапе сборки; обе половины моста получают согласованную пару

### Целостность (INTG)

- [x] **INTG-01**: Манифест файлов расширения с хешами формируется при сборке payload
- [x] **INTG-02**: Расхождение файлов `revit_mcp/` с манифестом обнаруживается при загрузке расширения
- [x] **INTG-03**: Проверка целостности не пишет файлы — только обнаруживает и сообщает
- [x] **INTG-04**: При обнаружении расхождения мутации отклоняются, чтение и диагностика продолжают работать
- [x] **INTG-05**: `/status/` называет конкретные разошедшиеся файлы, чтобы инженер знал, что переустанавливать
- [x] **INTG-06**: Проверка не даёт ложных срабатываний на `__pycache__`, `.pyc`, переводах строк и артефактах редактора
- [x] **INTG-07**: Недоступность источника эталона не приравнивается к повреждению — состояние сообщается отдельно и не блокирует запуск
- [x] **INTG-08**: На машине разработчика, где расширение это junction на репозиторий, проверка не мешает работе

### Сериализация (SER)

- [x] **SER-01**: Мутирующие вызовы этого MCP-сервера не уходят в Revit параллельно
- [x] **SER-02**: Удержание очереди не блокирует `/status/`; все остальные вызовы, включая чтения, ждут своей очереди — решение d27-b после стенда 01-04, где общий обработчик pyRevit перепутал ответы перекрывающихся запросов
- [x] **SER-03**: Исключение, таймаут или отмена внутри сериализованного участка освобождают очередь
- [x] **SER-04**: Ожидание в очереди не приводит к тому, что вызов получает меньше своего бюджета времени
- [x] **SER-05**: Область действия сериализации документирована честно — она покрывает вызовы этого процесса и не является гарантией против второго клиента

### Честный результат (TRUTH)

- [x] **TRUTH-01**: Все мутирующие маршруты сообщают реальный `TransactionStatus`, а не предполагаемый успех
- [x] **TRUTH-02**: `delete_elements` и `export_ifc` переведены на `commit_and_report` — закрытие двух известных оставшихся пропусков
- [x] **TRUTH-03**: Пакетные операции возвращают пропущенные и сбойные элементы рядом с успешными, а не только счётчик
- [x] **TRUTH-04**: Частичный отказ пакетной операции имеет собственный явный статус, отличимый и от успеха, и от полного отказа

### Аудит (AUDIT)

- [x] **AUDIT-01**: Каждая мутация записывается в локальный структурный журнал JSONL
- [x] **AUDIT-02**: Запись содержит время, инструмент, маршрут, идентичность документа, затронутые элементы и исход
- [x] **AUDIT-03**: Записывается фактический исход, а не намерение — откат пишется как откат, частичный пропуск как частичный пропуск
- [x] **AUDIT-04**: Один вызов инструмента связывается со своими записями общим идентификатором
- [x] **AUDIT-05**: Журнал не ломает stdio-транспорт — ничего не пишется в stdout
- [x] **AUDIT-06**: Журнал не повреждается при двух одновременно работающих экземплярах Revit
- [x] **AUDIT-07**: Рост журнала ограничен
- [x] **AUDIT-08**: Журнал не содержит секрета и не содержит лишних персональных данных

### Безопасность мутаций (SAFE)

Phase 7. Формализовано при планировании 2026-10-25 по `07-CONTEXT.md` (D-05…D-27) и `07-RESEARCH.md`.

- [ ] **SAFE-01** (SC1; D-05): Защищённая операция уровня confirm не выполняется без положительного ответа клиента через MCP elicitation; согласие агента в тексте и аргумент `approved=true` не принимаются.
- [ ] **SAFE-02** (SC1, SC5; D-05, D-07): Отсутствие capability, отказ, cancel, ошибка клиента и таймаут блокируют операцию и различимы в ответе и в журнале.
- [ ] **SAFE-03** (D-07): Ожидание подтверждения идёт до захвата очереди и не держит транзакцию Revit; срок задаётся политикой (по умолчанию 300 с).
- [ ] **SAFE-04** (D-08): Один положительный ответ разрешает ровно один вызов с этими аргументами; «на сессию»/«всегда» и параллельные окна не расширяют охват.
- [ ] **SAFE-05** (SC2; D-09): Окно на русском показывает инструмент, документ, нормализованные аргументы, причины и точные read-only факты Revit; неточное показывается как «неизвестно».
- [ ] **SAFE-06** (SC2): Каждый инструмент и маршрут классифицирован в базовой политике; неклассифицированный путь отклоняется; тест-сторож падает на новый инструмент или маршрут без классификации.
- [ ] **SAFE-07** (SC2; D-10, D-11, D-12, D-13, D-23, D-25): Базовая политика по умолчанию подтверждает перезапись параметров типа/непустых/множественных значений, удаление, трансформации, загрузку и правку семейств, выполнение кода, переопределение параметров; создание и чтения разрешены.
- [ ] **SAFE-08** (SC2; D-22): Общие параметры создаются только из ФОП компании (GUID и имя); недоступный ФОП даёт отказ.
- [x] **SAFE-09** (SC4; D-14, D-16, D-27): Политика — TOML, проверяется как данные; база едет в payload, файл оператора читается с share и применяется атомарно; версия/хеш видны.
- [ ] **SAFE-10** (SC4; D-15, D-17): Невалидная, недоступная или частично прочитанная политика оператора ничего не ослабляет; невалидная база блокирует защищённые операции; статус называет источник, версию и причину.
- [x] **SAFE-11** (SC3; D-18): Одноразовое разрешение подписано HMAC и привязано к маршруту, точному телу запроса, процессу (session_token), версии политики, сроку и nonce.
- [ ] **SAFE-12** (SC3; D-18): Каждый закрытый не-GET маршрут расширения отклоняет запрос без действительного разрешения до любого эффекта; разрешение потребляется атомарно в `gate_or_response`; повтор, подмена, просрочка и чужой процесс отклоняются; тест-сторож закрыт по умолчанию.
- [ ] **SAFE-13** (SC4): Подтверждение не переживает смену политики и изменение фактов между «Да» и отправкой.
- [ ] **SAFE-14** (SC3; D-19): Выкладка payload-first; новое расширение со старым payload отказывает понятным текстом; старое расширение игнорирует новый ключ; статус сообщает протокол разрешений.
- [ ] **SAFE-15** (SC5): Журнал и ответ различают denied, expired, rejected_permit, committed, rolled_back, partial и unknown; подтверждение не выдаётся за выполнение; `format_response` не получает новых неявных сигналов ошибки.
- [ ] **SAFE-16** (SC5; D-26): После неизвестного исхода нет автоповтора; одно разрешение не выполняет мутацию дважды; повторная доставка клиента порождает новое окно для confirm; повтор уже выполненной allow-операции в новый процесс сервера — задокументированный остаточный риск, а не гарантия.
- [ ] **SAFE-17** (SC6; D-12): `execute_revit_code` подтверждается на каждый вызов (код или начало, длина, SHA-256, предупреждение), путь остаётся доверенным исключением.
- [ ] **SAFE-18** (SC6; D-25): Границы обхода зафиксированы: произвольный код, ОС-доступ и читаемый секрет, cross-process overlap 999.1, содержимое `load_family`.
- [x] **SAFE-19** (D-06, D-24): Обновление MCP SDK до 1.30.x не ломает регистрацию FastMCP, обёртку аудита и `user_request`, чистоту stdout, три транспорта, cold start и импорт в payload (shim `pywin32`).
- [ ] **SAFE-20** (SC7; D-20): Офлайн негативные и конкурентные тесты зелёные; отдельно разрешённый live bench в Hermes Desktop после полного перезапуска Revit.
- [ ] **SAFE-21** (D-15): ROADMAP-критерий 2 переформулирован: подтверждение — поведение базовой политики по умолчанию, а не неизменяемая гарантия.

## Future Requirements

Признано, но отложено. Не входит в дорожную карту этого milestone.

### Политика и подтверждение (POLICY)

*Заменены SAFE-06…SAFE-12 (Phase 7): подтверждение через MCP elicitation вместо preview + второго вызова с токеном. Оставлены для истории.*

- **POLICY-01**: Конфигурируемая политика разрешений, вшитая в payload при сборке
- **POLICY-02**: Разрушительная операция возвращает preview — точный список того, что изменится — и одноразовый токен
- **POLICY-03**: Применение требует второго вызова с полученным токеном
- **POLICY-04**: Права администратора контролируются автором проекта через конфиг в репозитории на сервере

### Идемпотентность (IDEM)

- **IDEM-01**: Мутирующий вызов принимает ключ идемпотентности
- **IDEM-02**: Повтор вызова с тем же ключом не выполняет операцию дважды
- **IDEM-03**: Клиент может отличить «не дошло» от «дошло, применено, ответ потерян»

### Восстановление целостности (RESTORE)

- **RESTORE-01**: Отдельный скрипт восстанавливает разошедшиеся файлы при закрытом Revit
- **RESTORE-02**: Восстановление атомарно — частично скопированный файл не подменяет рабочий

### Гигиена ответов (HYG)

- **HYG-01**: Traceback не возвращается клиенту (36 мест в 17 модулях); логируется, наружу идёт корреляционный идентификатор
- **HYG-02**: Потолки на размер партии в мутирующих маршрутах
- **HYG-03**: Защита от перезаписи файлов при экспорте и SaveAs
- **HYG-04**: Валидация путей на границе маршрутов

## Out of Scope

Явно исключено. Записано, чтобы не возвращаться без решения.

| Feature | Reason |
|---------|--------|
| Самовосстановление файлов в рантайме | Запись файлов под работающим движком pyRevit — документированный путь к краху Revit; изнутри `startup.py` перезапуск процесса и Reload неразличимы, а на dev-машине с junction восстановление затрёт незакоммиченную работу. Перенесено в RESTORE-01 как отдельный офлайн-скрипт |
| Защита от целенаправленного локального обхода | Модель угрозы — случайная перезапись файлов инженером, не злоумышленник за консолью станции |
| Уникальный секрет на станцию | Секрет вшивается в payload при сборке, один payload на парк. Рубеж сетевой, не локальный |
| Позиция в очереди и ETA при ожидании | Ни одна сопоставимая система (Selenium, Jupyter) этого не делает для одного бэкенда; блокирующее ожидание с таймаутом — норма экосистемы |
| Полная интеграция OpenTelemetry SDK | Одно-процессный настольный инструмент; заимствуется только форма корреляционного идентификатора, не коллекторы и экспортёры |
| Поэлементная история изменений уровня worksharing Revit | Погоня за гранулярностью, которой не даёт сам Revit; маршрутный уровень с ElementId уже не грубее родной истории |
| Подпись кода (Authenticode) вместо манифеста хешей | Проверка подписи в .NET по умолчанию не блокирующая — сама по себе не даёт отказа при подмене; манифест с хешами решает задачу без инфраструктуры подписи |
| Расщепление `revit_mcp/colors.py` | Фоновый долг, не блокирует фундамент |
