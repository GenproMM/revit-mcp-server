# Стек делится на CPython 3.11+ и IronPython 2.7

Один репозиторий, два интерпретатора. Это не переходное состояние, а постоянное
устройство проекта — см. [[Revit-часть написана на IronPython 2.7 и не может делить код с MCP-частью]].

## Языки

**CPython 3 — сторона MCP-сервера:** `main.py`, `tools/*.py`, `tests/*.py`.
Современный `async`/`await`, `typing`, f-строки, `list[str]`.

**Диалект Python 2.7 под IronPython — сторона Revit:** `startup.py`, `revit_mcp/*.py`.
Жёсткие ограничения: `from StringIO import StringIO`, только `"{}".format(...)`,
обязательный заголовок `# -*- coding: UTF-8 -*-`, никаких тайп-хинтов.

**.NET / CLR** — через `clr` и `System` внутри Revit-половины
(`System.Collections.Generic.List` используется по всему `revit_mcp/`).

## Рантайм

- CPython `>=3.11` требуется (`pyproject.toml`), для разработки пришпилен 3.13
  (`.python-version`).
- IronPython 2.7 поставляет сам pyRevit внутри Revit — репозиторий его не
  устанавливает и нигде не декларирует.
- Практически только Windows 10/11 — Revit не существует на других платформах.

## Пакетный менеджер

- **`uv` (Astral)** — основной: `uv sync`, `uv run main.py`.
- Лок-файл `uv.lock` (29 разрешённых пакетов).
- `requirements.txt` присутствует как полностью пришпиленное зеркало.

> [!warning] Два файла расходятся в намерении
> `pyproject.toml` объявляет `mcp[cli]>=1.9.0`, а `requirements.txt` пришпиливает все
> 28 транзитивных зависимостей точными версиями. `uv sync` и
> `pip install -r requirements.txt` могут дать разные окружения. Нужно оставить один
> источник истины.

## Фреймворки

**Ядро:**

- `mcp[cli]` >= 1.9.0 — протокол MCP; `FastMCP` создаётся в `main.py`.
- `pyrevit` (`routes`, `DB`, `revit`, `revit.db.query`) — даёт хост Revit, **не**
  является зависимостью с PyPI.
- `starlette` 0.46.2 + `uvicorn` 0.34.2 — ASGI под транспортами SSE и streamable-http.
- `httpx` 0.28.1 — асинхронный клиент к серверу Routes.
- `pydantic` 2.11.4 — генерация схем инструментов через FastMCP.
- `anyio` 4.9.0 — используется напрямую: `anyio.run(run_combined_async)`.

**Тестирование:** фреймворка нет. См. [[Тесты — это самостоятельные скрипты, а не pytest-сьют]].

**Сборка и разработка:** `mcp dev main.py` поднимает MCP Inspector. Ни линтера, ни
форматтера, ни CI в репозитории нет.

## Конфигурация

Единственная переменная окружения, которую читает сервер, — **`REVIT_HOST`**
(по умолчанию `localhost`). Всё остальное захардкожено:

| Что | Значение | Где |
|---|---|---|
| Бинд MCP-сервера | `127.0.0.1:8000` | `main.py` |
| Порт pyRevit Routes | `48884` | `main.py` |
| Базовый URL | `http://{REVIT_HOST}:48884/revit_mcp` | `main.py` |
| Таймаут GET/POST | 30.0 с | `main.py` (`_revit_call`) |
| Таймаут картинок | 60.0 с | `main.py` (`revit_image`) |
| `stateless_http`, `json_response` | `True`, `True` | `main.py` |

Ни `.env`, ни конфиг-файла, ни секретов в проекте нет.
См. [[Порт 48884 захардкожен, настраивается только хост]].

## Требования к платформе

- Windows 10/11, Autodesk Revit 2024 / 2025 / 2026 / 2027 с открытым документом.
- pyRevit с включённым Routes Server (вкладка pyRevit → Settings → Routes).
- Совместимость версий Revit решается **в коде**, а не пиннингом зависимостей —
  см. [[ElementId читается и создаётся только через хелперы]].
- `uv` в PATH.

> [!note] Revit 2027 работает на .NET 10
> Против .NET 8 в 2025/2026. Совместимость .NET берёт на себя pyRevit, поэтому нужна
> сборка pyRevit с поддержкой 2027. Ни один из 48 инструментов не использует API,
> удалённые в 2027 (импорт AXM/FormIt, члены `Mechanical.Zone`, старое создание
> арматуры, выброшенные свойства `EnergyDataSettings`).
