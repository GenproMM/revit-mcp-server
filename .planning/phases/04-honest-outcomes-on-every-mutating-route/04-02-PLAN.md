## Interface from 04-01 (import from `.utils`; do not edit utils.py or textutils.py here)

- `commit_and_report(t, swallower)` returns `{committed, transaction_status, failures}`.
- `finalize_outcome(commit_result, data, requested, succeeded, failed)` returns `(payload, http)`:
  409 rolled_back (legacy keys dropped, outcome.succeeded []), 200 success, 200 partial, 422 failed
  plus `error`; `data` must not contain `status`.
- `build_outcome(transaction_status, requested, succeeded, failed, revit_failures)` for literal
  branches; `exception_outcome(t, requested, succeeded, failed)` for 500 replies (succeeded kept
  only when the transaction reports Committed); `transaction_status_of(t)`.
- Route pattern, item convention and the `requested` rule: 04-01-PLAN.md sections "Route pattern
  every migration follows" and "Item convention". This world uses: creation routes, id of the created
  element in succeeded; batch creation failed items, the 0-based input index or "INDEX.name";
  single-element secondary steps, the step name; set_parameter, the parameter name.

## Execution rules for every task in this plan

- IronPython 3.4-level syntax in `revit_mcp/` (no f-strings, no `{**a}`, no keyword-only args, no
  `async`); relative sibling imports; never import another domain module.
- Every migrated handler: `t = None`, `requested = None`, `succeeded = []`, `failed = []` before the
  outer `try`; `swallower = suppress_warnings(t)` on the line after `t.Start()`; only
  `commit_and_report` commits; element reads that follow the commit happen after the committed check;
  the 500 reply gains `"outcome": exception_outcome(t, requested, succeeded, failed)` and keeps
  `error` and `traceback`. Pre-transaction validation (400/404/503) and in-transaction validation that
  rolls back and answers 4xx stay exactly as they are, without outcome (D-04).
- A failed secondary step (D-12) is recorded where the route today skips silently: wrap each such
  step in its own `try/except Exception as step_err`; a missing or read-only parameter gives the
  reason "parameter not found" or "parameter is read-only", an exception gives `str(step_err)`.
- Tests: never weaken an existing assertion; arm the fake so success paths are real (TRANSACTING rows
  must still reach 200 success). If a fake document attribute must return a configured object (for
  example `doc.Create` whose `NewMechanicalSystem` returns None), add an attribute-override map to
  the world (consulted by `RouteDocument.__getattr__` before `hooks`) rather than special-casing a
  test. Add `"outcome"` to `EXPECTED_KEYS` rows in the same commit as each module.
- Commit protocol: `uv run pytest tests/unit -q` green before every commit; commit with an explicit
  pathspec only (`git commit -m "<message>" -- <paths>`), never `git add -A`/`.`; the user's staged
  files stay staged. Prefix `feat(04-02):` / `test(04-02):`; end with your session's attribution line.
