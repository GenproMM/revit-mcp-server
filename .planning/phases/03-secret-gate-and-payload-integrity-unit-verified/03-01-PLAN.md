## Decision reconciliations (adopted from 03-RESEARCH.md; CONTEXT.md is not rewritten)

The user should confirm these at plan review. Each keeps the locked part of the decision.

- **C1 (D-01 forward clause superseded):** Phase 2 shipped the target document as a flat top-level
  `document` key (`tools/editing_tools.py`, `revit_mcp/identity.py` `request_document_selector`).
  `_mcp` stays secret-only and `document` stays flat: the two keys are disjoint, so nothing
  collides. The "one envelope carries secret, document and call_id" aspiration is dropped for
  `document` only; `split_envelope` returns the whole `_mcp` dict, so `call_id` (Phase 6) and an
  approval token (Phase 7) can still ride it without a schema change (Open Question 5).
- **C2 (D-02/D-17 wiring shape):** Phase 2 forbids a `startup.py` handler wrapper
  (`tests/unit/test_phase2_inventory.py::test_startup_installs_no_common_handler_wrapper`). This
  phase therefore ships small composable pure functions (`split_envelope`, `envelope_secret`,
  `check_secret`, `auth_failure`, `gate_applies`) that a Phase 5 per-handler guard can call, and no
  decorator. Whether a guard may rewrite `request.data` so handlers never see `_mcp` (D-02's
  "cleaned payload") is a Phase 5 discuss item (Open Question 2); `split_envelope` is built exactly
  as D-02 locks it.
- **C3 (D-04 confirmed by documentation):** `CryptographicOperations.FixedTimeEquals` is listed by
  Microsoft for .NET Core 2.1+, .NET Standard 2.1 and .NET 5+ only, takes `ReadOnlySpan<byte>`,
  and Revit 2024 runs .NET Framework 4.8. That is the documented fallback reason SC2 asks for; it is
  written into the `secret_matches` docstring. The live `hashlib.sha256` check under IPY342 is plan
  03-08 (a blocking human checkpoint) and updates that docstring.
- **Method rule (D-03 made fail-closed):** `gate_applies` exempts GET and HEAD only. For every route
  in the repo today (all GET or POST, measured this session) that is exactly D-03; a route with any
  other verb would be gated rather than silently open.
- **Minimum secret length (RESEARCH A5, Claude's discretion):** a secret shorter than 16 characters
  after stripping is treated as absent on both halves (server side: `server_not_configured`). The
  generated secret is 43 characters.
