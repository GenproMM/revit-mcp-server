# configure_hermes.py писал в файл, которого Hermes на Windows не читает

**Статус:** исправлено, коммит `8825f6d` · найдено на первой пилотной станции

## Симптом

`install.cmd`, шаг `[3/6]`, писал ровно то, что и должен:
`C:\Users\e.ermolenko\.hermes\config.yaml already up to date.` Никакой
ошибки. Но Hermes на этой станции продолжал показывать старую рукописную
запись сервера `revit` (путь на сетевую шару, без `REVIT_HOST`, без
`timeout`) — установленный payload она не использовала вовсе.

## Причина

`configure_hermes.py` резолвил путь конфига жёстко:

```python
cfg = args.config or os.path.join(os.path.expanduser("~"), ".hermes", "config.yaml")
```

Сам Hermes Agent (проверено чтением его исходников,
`hermes_constants.py:53-74`) резолвит домашнюю папку иначе: сначала
`HERMES_HOME`, а платформенное умолчание на Windows — `%LOCALAPPDATA%\hermes`,
и только на прочих платформах — `~/.hermes`. То есть `~/.hermes` **не
является Windows-веткой этой логики вообще** — код чинил файл, который
существующая ветвь `if sys.platform == "win32"` никогда не выбирает.

Результат: `install.cmd` создавал `~\.hermes\config.yaml` с нуля (старый код
не отказывался — при отсутствии файла просто создавал его и возвращал 0),
рапортовал успех, а Hermes продолжал читать `%HERMES_HOME%\config.yaml`
(`%LOCALAPPDATA%\hermes\config.yaml` в дефолтной установке, либо форк-специфичный
путь при заданной `HERMES_HOME` — на пилотной станции форк выставлял её в
`%LOCALAPPDATA%\gena`).

## Обход / исправление

Новая `hermes_config_path()` в `configure_hermes.py` дословно повторяет
резолвинг агента: `HERMES_HOME`, иначе `%LOCALAPPDATA%\hermes` на Windows,
иначе `~/.hermes`. `--config` по-прежнему перебивает вручную.
`--print-only` теперь первой строкой печатает `# target: <путь>` — при
диагностике «Hermes не видит инструменты» половина ответа именно в том,
*куда* лёг блок.

Проверено эмпирически на живой установке, не только по коду: с `HERMES_HOME`
выставленной и с ней очищенной резолвер вернул один и тот же путь,
совпадающий с тем, что реально читает запущенный Hermes (в его `mcp_servers`
лежала ровно ожидаемая запись).

Побочная находка в процессе написания фикса: первая версия help-строки
argparse (`help="... %HERMES_HOME%, ..."`) уронила сборку парсера —
`ValueError: unsupported format character`, потому что argparse
`%`-раскрывает текст help. Поймано смоук-тестом `--print-only` до попадания
в релиз, не постфактум.

## Урок

> «Путь по умолчанию» — не единая константа, а функция от платформы и от
> `HERMES_HOME`, и её нужно резолвить тем же кодом, что и целевая программа,
> а не переоткрывать по памяти. Скрипт, который «создаёт файл при
> отсутствии и возвращает 0», обязан сначала спросить «а тот ли это файл»,
> иначе успех и отказ неразличимы для того, кто читает вывод.
