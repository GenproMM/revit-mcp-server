# MCP-клиенты подключаются четырьмя транспортами

Сервер работает с любым MCP-совместимым клиентом: Claude Desktop, Claude Code, Cursor,
Windsurf, Copilot. Транспорт выбирается флагом в argv при запуске `main.py`.

## Режимы

| Флаг | Транспорт | Эндпоинты | Для кого |
|---|---|---|---|
| *(нет)* | stdio | stdin/stdout | Claude Desktop, Claude Code |
| `--sse` | SSE | `/sse`, `/messages/` | Legacy-клиенты |
| `--streamable-http` (`--http`) | HTTP | `/mcp` | HTTP-клиенты |
| `--combined` | оба | всё перечисленное | Максимальная совместимость |

Бинд MCP-сервера — `127.0.0.1:8000`, с `stateless_http=True` и `json_response=True`
для лучшей совместимости.

## Как устроен комбинированный режим

`run_combined_async` берёт **сначала** streamable-http-приложение, потому что именно у
него правильный lifespan, инициализирующий task group менеджера сессий. Затем к нему
добавляются маршруты SSE-приложения (SSE особого lifespan не требует — он создаёт
task group на каждый запрос внутри `connect_sse()`). Оба поднимаются под одним uvicorn.

Порядок здесь важен: обратный привёл к баге lifespan-контекста, исправленной в
коммите `19a2941`.

## Подключение Claude Desktop / Claude Code

```json
{
  "mcpServers": {
    "revit": {
      "command": "uv",
      "args": ["run", "main.py"],
      "cwd": "/path/to/revit-mcp-server"
    }
  }
}
```

## Подключение Cursor / Windsurf

```bash
uv run main.py --streamable-http
```

Затем клиент указывается на `http://localhost:8000/mcp`.

## Инспектор

```bash
mcp dev main.py     # http://127.0.0.1:6274
```

Единственный способ прогнать инструменты руками против живой модели.

## Правило stdio, которое нельзя нарушать

**Никогда не вызывать `print()` в `main.py` под stdio-транспортом** — это ломает поток
протокола. Единственный существующий `print` защищён проверкой на режим `--combined`.

То же касается логов: в stdio-режиме сервер не пишет ничего вообще.

## Холодный старт

~0.9 с от спавна процесса до ответа на `initialize` — и это пол фреймворка, а не
недоработка. См.

## Схемы инструментов

Генерируются FastMCP из тайп-хинтов и докстрингов через pydantic. Отдельных моделей
нет. Это делает докстринг инструмента настоящим API-контрактом — см.
[[Докстринг инструмента — это контракт для модели, а не для разработчика]].
