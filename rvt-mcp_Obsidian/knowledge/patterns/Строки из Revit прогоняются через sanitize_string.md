# Строки из Revit прогоняются через sanitize_string

> [!success] Обновление 2026-09-04, вторая сессия
> ASCII-фильтрация ниже — уже история. Исправлено: `sanitize_string()` и
> `normalize_string()` теперь сохраняют unicode как есть. Заодно нашлась **вторая,
> независимая** копия того же фильтра в `revit_mcp/parameters.py` (`_safe_str`,
> посимвольный цикл) — тоже исправлена. См.
> [[sanitize_string превращает кириллицу в вопросительные знаки]] и
> [[2026-09-04 — фикс кириллицы и правильный детект общих параметров, новый инструмент list_project_parameters]].
> Текст ниже оставлен как есть — описывает форму бага и урок, актуальный независимо
> от того, исправлен код или нет.

## Паттерн, как он был реализован (до фикса)

Любое имя, полученное из Revit, перед укладкой в JSON проходило через
`sanitize_string()` или `get_element_name()` из `revit_mcp/utils.py`:

```python
def get_element_name(element):
    try:
        name = element.Name
    except AttributeError:
        name = DB.Element.Name.__get__(element)   # для FamilySymbol и др.
    return sanitize_string(name)

def sanitize_string(text):
    """Sanitize a string to be ASCII-safe for JSON serialization."""
    if text is None:
        return "Unnamed"
    try:
        return str(text).encode('ascii', 'replace').decode('ascii')
    except Exception:
        return "Unnamed"
```

Рядом жила `normalize_string()` — то же самое плюс `.strip()`. Сейчас обе функции
просто сохраняют unicode, гвардируя `None` и тип; двойной способ доступа к имени
(`element.Name` / `DB.Element.Name.__get__`) и фолбэк на `"Unnamed"` остались как
были — эта часть паттерна была правильной с самого начала.

Через эти функции проходят **18 из 23** модулей маршрутов, то есть практически весь
вывод проекта.

Полезная часть паттерна реальна: два способа прочитать имя (`element.Name` и
`DB.Element.Name.__get__(element)`) нужны, потому что у `FamilySymbol` и части
элементов свойство доступно только через второй, и фолбэк на `"Unnamed"` вместо
исключения — правильное поведение для сериализации.

## Но обоснование в докстринге неверно

> [!danger] `ascii`/`replace` уничтожает не-ASCII имена
> Кириллица, умлауты, любые национальные символы превращаются в `?`. `Уровень 1`
> становится `??????? 1`. JSON-сериализация **не требует ASCII** — сериализатор
> pyRevit корректно эскейпит юникод в `\uXXXX`.

Это проверено экспериментально на живой русскоязычной модели и разобрано в
[[sanitize_string превращает кириллицу в вопросительные знаки]]. Там же: это
**регрессия форка**, приехавшая попутным грузом в коммите `bb7cda2`, который по
названию занимался совместимостью `ElementId`; в апстриме `get_element_name` возвращает
`.Name` без преобразования.

Косвенное подтверждение из самого кода: `document_title` в ответе `/status/` берётся
из `doc.Title` **напрямую**, минуя эти функции, — и приходит читаемым.

## Как применять сейчас

- **Продолжать** использовать `get_element_name(element)` для чтения имён — двойной
  способ доступа и фолбэк нужны, и теперь результат корректен на любом языке модели.
- Обходной путь через `BuiltInParameter` вместо имён параметров **больше не нужен** —
  это было временным костылём, пока фикс не был разрешён.
- Расширять `sanitize_string`/`get_element_name` на новые поля — теперь безопасно.
  Перед добавлением **своей** ASCII-фильтрующей функции в новом модуле — сначала
  проверить, нет ли уже второй копии того же бага (см. находку в
  `revit_mcp/parameters.py` в заметке сессии).

## Урок паттерна

> Комментарий или докстринг, объясняющий *зачем* сделано преобразование, может быть
> просто неверным. Проверять — воспроизведением обоих путей на одних данных, а не
> чтением обоснования.
