## Design decisions (record each one in SUMMARY.md under "Decisions", with the justification)

- DD-1 Default detach value: keep the value set preserve | discard | none and change the default to
  "none" in BOTH halves (tool signature and route `data.get("detach", ...)`). No new alias: "none"
  already means "do not detach; for a central create a local copy and open that", which is exactly Q1.
  The plugin-diagnostic skills pass detach explicitly and are out of scope.
- DD-2 overwrite_local: KEEP it as a deprecated tri-state alias (default None = not given) and add
  `existing_local: "timestamp" | "overwrite" | "error"` (default None, resolved to "timestamp") as the
  primary parameter. Justification: (a) explicit legacy callers keep their meaning — overwrite_local=true
  is an explicit opt-in to the destructive replace, false still refuses when a copy exists; (b)
  mixed-version safety: the tool always sends `overwrite_local = (mode == "overwrite")`, so a Revit that
  still runs the old route (old default overwrite_local=True) refuses with "A local copy already exists"
  instead of deleting the copy during the window between updating the repo and restarting Revit; (c)
  removing the parameter would break explicit callers for no safety gain. Resolution rule (identical in
  both halves): existing_local given -> must be one of the three (case-insensitive), and an
  overwrite_local that is given must equal (mode == "overwrite") or it is a conflict error; existing_local
  absent -> overwrite_local true = "overwrite", false = "error", absent = "timestamp". The route reads
  existing_local first, so the paired overwrite_local=false the new tool sends is consistent, not a
  conflict. Known transitional residue (document it): an OLD MCP server process (session started before
  the update) talking to a NEW extension still sends overwrite_local=true by its old default, which the
  new route honours as explicit "overwrite" for detach="none" calls — advise restarting the assistant
  session together with Revit.
- DD-3 Stamp format: Revit's exact naming for "Append timestamp to existing copy" could not be confirmed
  offline (web search was unavailable at planning time). Use `<stem>_<YYYYMMDD_HHMMSS>.rvt`, collision
  suffix `_2`, `_3`, ... (bounded), and mark it [ASSUMED] in SUMMARY with manual step (г) comparing
  against Revit's native dialog. Do not spend more than one quick lookup attempt on confirming it.
- DD-4 Backup folder: the existing `<stem>_backup` folder (if present) is renamed to `<newstem>_backup`
  so the renamed copy keeps its own backup folder and the new local starts clean. Order: rename the .rvt
  first (most likely to fail when the file is open in Revit — nothing changed then); then the folder; if
  the folder rename fails, rename the .rvt back and return an error that says whether the restore
  succeeded and where every file now is. Never delete anything on the timestamp path. If CreateNewLocal
  fails after a successful rename, do not try to restore; the error reply carries renamed_existing_local
  so the user knows where the old copy went.
- DD-5 Workset fallback eligibility: only when the model is workshared AND the caller did not supply
  close_worksets_matching (key absent or null). An explicit list — even ["__ALL_USER_WORKSETS__"] —
  keeps today's behaviour with no retry ("Явный close_worksets_matching работает как сейчас"). Trigger:
  the first open attempt raised OR returned no document. Exactly one retry, on the same open path (the
  already-created local copy; no second CreateNewLocal, no second rename). Matching: lower-case, "_"
  treated as space, whitespace runs collapsed, substring "оси и уровни"; an exact normalised match is
  preferred, otherwise the first match in Revit's GetUserWorksetInfo order. To make the tool able to
  signal "default", the tool omits close_worksets_matching when the caller passed None (the route
  defaults to the sentinel, as both old and new routes already do).
- DD-6 Error statuses: rename failure, existing_local="error" with an existing copy, and fallback
  failures are 500 with `outcome` (same class as today's local-copy and open failures). Invalid or
  conflicting existing_local/overwrite_local is 400 with no outcome (validation before any action).
