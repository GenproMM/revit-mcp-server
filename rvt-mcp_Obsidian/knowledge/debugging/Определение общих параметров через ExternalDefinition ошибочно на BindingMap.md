# Определение общих параметров через ExternalDefinition ошибочно на BindingMap

**Статус:** исправлено · собственная ошибка ассистента, найдена пользователем

## Симптом

Пользователь спросил, с какими префиксами есть общие параметры в проекте. Запрос
через `execute_code`:

```python
it = doc.ParameterBindings.ForwardIterator()
it.Reset()
while it.MoveNext():
    definition = it.Key
    is_shared = isinstance(definition, DB.ExternalDefinition)
    ...
```

Результат: `shared_count = 0` из 315 параметров, включая все `ADSK_*`. Ответ
пользователю: «в проекте нет общих параметров вообще».

## Причина ошибки

`ADSK_*` — стандартный набор общих параметров Autodesk, их «нешаренность» была
неправдоподобна с самого начала, но проверка выглядела логичной: `ExternalDefinition`
— реальный класс Revit API для параметров, читаемых напрямую из `.txt`-файла общих
параметров.

Пользователь поправил: как только общий параметр **загружается в проект**, он
приобретает `InternalDefinition` — это системная особенность API, а не свойство
конкретной модели. `ExternalDefinition` существует только при чтении самого файла
общих параметров, `doc.ParameterBindings` никогда его не отдаёт. Проверка была
обречена дать `False` для любого параметра, общего или нет.

## Как найден правильный способ

Пользователь явно попросил использовать Perplexity MCP. `perplexity_search` указал
на `InternalDefinition.GetTypeId()` — возвращает `ForgeTypeId`, строка которого
кодирует происхождение:

```
revit.local.shared:<guid>-<версия>    -> общий параметр
revit.local.project:<guid>-<версия>   -> обычный параметр проекта
```

## Проверка на живой модели

Два независимых метода, оба через `execute_code`:

1. `InternalDefinition.GetTypeId().TypeId` — префикс `revit.local.shared` / `.project`.
2. `FilteredElementCollector(doc).OfClass(DB.SharedParameterElement)` — сверка по
   имени с `spe.GetDefinition().Name`.

Результат: **315/315 совпадений**. Из 315 параметров — 309 общих, 6 обычных.

```
Метод 1 (ExternalDefinition, неверный):  shared=0,   не-shared=315
Метод 2 (ForgeTypeId, верный):           shared=309, не-shared=6
Метод 3 (SharedParameterElement, сверка): согласен с методом 2 на 315/315
```

## Урок

> Проверка типом объекта Revit API (`isinstance`) может быть системно неверной, даже
> если синтаксически выглядит правильно — класс существует и относится к предметной
> области, но в данной точке кода никогда не встречается. Признак: результат
> противоречит очевидному факту о данных (набор `ADSK_*` не может быть «не общим»).
> Не полагаться на память об API — искать актуальное поведение (Perplexity/офиц.
> документация) и **перепроверять на живой модели двумя независимыми способами**,
> прежде чем доверять числу.

Также: пользователь знает модель данных Revit глубоко и поймает неверное
API-утверждение — стоит по умолчанию проверять эмпирически, а не полагаться на
рассуждение по именам типов.
