# Первичная настройка и пилотная раскатка

Инструкция для сопровождающего. От текущего состояния сервера до работающего
RevitMCP у двух-трёх тестовых пользователей.

Читать сверху вниз. Порядок шагов существенен: `install.cmd` физически
появляется на сервере только после шага 4, а работать начинает только после
шага 5.

---

## 1. Как папки выглядят сейчас и как должны

**Сейчас:**

```
\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\
├─ inbox\
└─ revit-mcp-server\
```

**Должно получиться:**

```
\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\
├─ revit-mcp-server\   рабочая копия Git. Ваша. pyRevit её НЕ видит      ← есть
├─ inbox\              пакеты от разработчиков инструментов             ← есть
├─ ext\                Revit-половина, обрезанная. Станции грузят отсюда ← шаг 4
├─ install\            install.cmd, update.cmd, find-python.cmd          ← шаг 4
├─ payload\            CPython-половина + колёса, зеркалится на станции  ← шаг 5
│                      (стажируется в %TEMP%, на шару кладётся готовой)
└─ contrib-kit\        набор разработчика (можно позже)                  ← шаг 9
```

Вручную создавать `ext\`, `install\` и `payload\` **не нужно** — их создают
скрипты публикации. Если создать заранее, ничего не сломается.

Папки `payload.build\` на шаре быть не должно. Сборка стажируется в `%TEMP%` на
машине сборки — это принципиально: приёмочный тест запускает сервер из папки
стажирования, и по SMB он мерит задержку сети на ~1000 файлов модулей, а не
холодный старт (2.30 с с шары против 0.91 с с локального диска на одном коммите
при лимите 2.0 с). Если `payload.build\` на шаре осталась — это след сборки до
этого изменения, её можно удалить.

## 2. Права доступа. Запрос в ИТ

| Папка | Пользователи | Разработчики инструментов | Вы |
|---|---|---|---|
| `ext\`, `payload\`, `install\` | **чтение** | чтение | запись |
| `contrib-kit\` | — | **чтение** | запись |
| `inbox\` | — | **запись** | чтение |
| `revit-mcp-server\` | — | — | запись |

Пользователям достаточно чтения на `827_RevitMCP` целиком — установщик ничего
на сервер не пишет.

**Отдельно стоит запросить ASCII-псевдоним.** Путь содержит русские буквы и
пробелы, и он попадает на `sys.path` IronPython 2.7, в TOML-конфиг pyRevit и в
ключи кэша. Сейчас работает, но это тот класс путей, на котором ломаются
сторонние библиотеки. Просите DFS-ссылку вида `\\srv-dfs\BIM\RevitMCP` на ту же
папку. Появится — впишите её в `deploy\config.cmd` и пересоберите обе половины.
Папку `inbox\` это не касается: она нигде не оказывается на `sys.path`.

## 3. Что должно быть на машине, с которой публикуете

Публикуете вы со своей машины или с билд-сервера — скрипты берут корень
репозитория относительно себя, расположение им безразлично.

| Нужно | Как проверить | Зачем |
|---|---|---|
| Windows x64 | — | |
| `git` | `git --version` | штамп версии берётся из короткого SHA |
| `uv` на PATH | `uv --version` | сборка зависимостей из `uv.lock` |
| Доступ к PyPI или внутреннему зеркалу | `uv --version` и сборка на шаге 5 | скачать колёса |
| **pyRevit установлен** | `%APPDATA%\pyRevit\bin\cengines\CPY*\python.exe` существует | колёса ABI-привязаны к тому CPython, который будет у пользователей |
| Запись в `827_RevitMCP` | создать и удалить файл | |

Последний пункт неочевиден и обязателен: колёса собираются **под интерпретатор
pyRevit**, а не под ваш системный Python. Без pyRevit на этой машине
`build-payload.cmd` откажется работать.

Если pyRevit сюда ставить нельзя — скопируйте папку движка с машины
пользователя и укажите путь до сборки:

```bat
set "MCP_PYEXE=D:\revit-mcp-build\CPY3123\python.exe"
```

## 4. Публикация Revit-половины

Правки в `deploy\config.cmd` **не требуются**: значение `MCP_SHARE_ROOT` по
умолчанию уже равно вашему пути.

Сначала закоммитьте изменения — иначе версия сборки не будет их описывать:

```bat
pushd "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\revit-mcp-server"
git status
git add -A && git commit -m "..."
```

`pushd`, а не `cd`: cmd не умеет держать UNC-путь текущей папкой, молча
откатывается на `C:\Windows` и пишет об этом предупреждение. `pushd` подставляет
временную букву диска; освободить её потом — `popd`.

Затем — **обязательно через `chcp 65001`**:

```bat
chcp 65001 && "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\revit-mcp-server\deploy\publish-extension.cmd"
```

Кодовая страница здесь не косметика. `config.cmd` хранит кириллический
`MCP_SHARE_ROOT` в UTF-8, а cmd по умолчанию разбирает батник в OEM-кодировке
(866 на русской Windows) — литерал приходит искажённым, и `mkdir`, который
создаёт все промежуточные каталоги, строит дерево-двойник с нечитаемым именем
рядом с настоящей папкой. Скрипт при этом рапортует `Published`: его финальная
проверка `dir` использует ту же искажённую переменную и потому себе не
противоречит. `chcp` должен быть выставлен в **той же** сессии cmd — двойной клик
из Проводника по этой же причине не годится, он всегда порождает cmd с кодовой
страницей по умолчанию.

**Первая проверка — строка `to:` в начале вывода**, до всего остального:

```
to  : \\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\ext\revit-mcp-server.extension
```

Если там `01_╨а╨╡╤Б╤Г╤А╤Б╤Л ...` — прерывайте Ctrl+C. На этот момент скрипт сделал
только чтение, записывать ещё нечего.

**Что произойдёт:** создастся `ext\revit-mcp-server.extension\` с четырьмя
вещами — `extension.json`, `startup.py`, `LICENSE`, `revit_mcp\` рекурсивно — и
создастся `install\` с тремя скриптами для пользователей. Всё остальное
(`main.py`, `tools\`, `tests\`, `deploy\`, `.git\`) остаётся в рабочей копии.

**Скрипт откажется публиковать**, если в `extension.json` не стоит
`"default_enabled": "True"` и `"builtin": "False"`. Это защита от самой дорогой
ошибки раскатки: при `False` pyRevit на чистой машине один раз запишет
`disabled = true` и расширение не загрузится никогда — без ошибки и без
диагностики.

**Проверка:** отдельной командой, а не по слову `Published` в выводе скрипта.

```bat
dir "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\ext\revit-mcp-server.extension"
```

Должны лежать ровно `extension.json`, `startup.py`, `LICENSE` и папка `revit_mcp`.
В `install\` — три `.cmd`. Если `dir` говорит «Файл не найден» — смотрите раздел 10.

## 5. Сборка CPython-половины

```bat
chcp 65001 && "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\revit-mcp-server\deploy\build-payload.cmd"
```

`chcp 65001` — по той же причине, что и в шаге 4: этот скрипт читает
`MCP_SHARE_ROOT` из того же `config.cmd`.

Идёт несколько минут: скачиваются и компилируются зависимости.

**Что произойдёт:** соберётся `payload\` — `app\` (main.py, server.py, gate.py,
warm.py, tools\, tests\, libs\), `install-libs\`, `configure_hermes.py`,
`ENGINE` и `VERSION`.

**Скрипт откажется публиковать**, если:

- собранный сервер не импортируется под тем интерпретатором, под который собран;
- не проходит приёмочный тест `gate.py` — холодный старт дольше 2 секунд или
  список инструментов расходится с `tests\unit\tool_manifest.txt`.

Второе — это ваша защита от потерянного инструмента: если домен не
зарегистрировался, релиз не выйдет.

Оба замера идут с локального диска (стажирование в `%TEMP%`), поэтому
`initialize too slow` теперь означает настоящую регрессию старта, а не медленную
шару. Для ориентира: 0.91 с на чистом дереве. Не поднимайте `LIMIT` в
`deploy\gate.py` — разбирайтесь, что добавилось в импорт.

`VERSION` пишется **последним**. Поэтому станция физически не может забрать
полуопубликованный payload: пока файла нет, обновление просто пропускается.

**Проверка:**

```bat
type "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\payload\VERSION"
type "\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\payload\ENGINE"
```

Первое — вида `2026.09.07-1430.b6adde6`. Второе — вида `CPY3123`; запомните,
оно должно совпадать с движком pyRevit у пользователей.

## 6. Выбор пилотных пользователей

Возьмите **двух-трёх**, и не самых удобных, а самых типичных:

1. **Один с обычными правами** — на нём проверяется основной путь.
2. **Один на зажатой машине** (AppLocker/EDR, нет прав на планировщик задач) —
   на нём проверяется откат на ярлык в автозагрузке. Это самая вероятная
   точка отказа: регистрация задачи в планировщике без прав администратора
   запрещена, и установщик обязан это пережить.
3. **Желательно один с русской моделью** и нелатинскими именами уровней и
   параметров — проверить, что кириллица доходит целой.

У каждого должно быть заранее:

- Revit 2024–2027, и **открытая модель** при проверке;
- pyRevit, установленный **для этого пользователя** (`pyrevit.exe` находится);
- Hermes Agent;
- доступ на чтение к `827_RevitMCP`.

Права администратора не нужны — всё ставится в профиль пользователя.

## 7. Что делает пользователь

Отправьте ему ровно это:

> 1. Закрой Hermes полностью.
> 2. Открой в проводнике
>    `\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\install\`
>    и запусти `install.cmd` двойным щелчком.
> 3. Когда попросит — закрой Hermes и нажми любую клавишу.
> 4. Перезапусти Revit **полностью** (не кнопкой Reload в pyRevit) и открой модель.
> 5. Открой Hermes.
> 6. Открой в браузере `http://localhost:48884/revit_mcp/status/` и пришли мне,
>    что там написано.

Установщик сам: скопирует payload в профиль, проверит что сервер запускается,
настроит pyRevit через `pyrevit.exe`, зарегистрирует сервер в Hermes, поставит
автообновление и добавит ярлык «Update RevitMCP».

## 8. Приёмка пилота

Пройдено, если выполнено **всё**:

**На станции, в браузере** `http://localhost:48884/revit_mcp/status/?verbose=true`:

- `"health": "healthy"` — не `degraded`;
- `"domains_registered": 22`;
- нет ключа `failed_domains`;
- `document_title` — имя открытой модели, и если оно русское, то читается
  правильно, а не `?????`.

**В Hermes:** инструменты Revit видны в списке, и вызов `get_revit_status`
возвращает статус.

**Обновление работает.** Проверьте так: соберите payload заново (шаг 5), затем
на станции запустите ярлык «Update RevitMCP» из меню Пуск. В
`%LOCALAPPDATA%\RevitMCP\update.log` появится запись, а
`%LOCALAPPDATA%\RevitMCP\current-version.txt` покажет новую версию.

**Автообновление зарегистрировано.** Вывод установщика на шаге `[4/6]` сказал
либо `scheduled task created`, либо `autostart entry created`. Если сказал
`WARNING: no automatic updates` — на этой машине обновления не будут приходить
сами, и это надо решать с ИТ.

**Откат возможен.** В `%LOCALAPPDATA%\RevitMCP\versions\` лежит больше одной
версии.

## 9. Набор разработчика (можно позже)

Нужен, только когда подключаете разработчиков инструментов.

Из корня репозитория:

```bat
uv run python scripts\build_contrib_kit.py
```

Скопируйте `dist\revitmcp-contrib-kit.zip` в
`827_RevitMCP\contrib-kit\` и дайте разработчикам путь к нему. Внутри — их
инструкция `INSTRUCTION.md`.

**Пересобирайте набор всякий раз, когда меняется `scripts\conventions.py`** —
устаревший набор пропускает пакеты, которые ваша приёмка отклонит.

Приёмка пакета:

```bat
uv run python scripts\intake_package.py "\\srv-dfs\...\inbox\wall_report.zip"
uv run python scripts\intake_package.py "...\wall_report.zip" --apply
```

Без `--apply` только смотрит. Пройденные проверки означают «можно читать», а не
«можно брать»: код будет исполняться внутри Revit с полным доступом к API на
всех станциях, и автоматика не оценивает замысел. Читайте оба модуля.

## 10. Если что-то не так

| Симптом | Куда смотреть |
|---|---|
| Скрипт сказал `Published`, но `ext\` нет | Кодовая страница. Перезапустите через `chcp 65001 && "…\publish-extension.cmd"` (шаг 4) и удалите дерево-двойник с нечитаемым именем рядом с `01_Ресурсы плагинов` |
| В выводе `to:` кириллица нечитаема | То же самое, и это единственный ранний признак. Не «косметика вывода»: `from:` в той же строке читается, потому что берётся из argv, а не из `config.cmd` |
| `initialize too slow`, `ERROR: acceptance gate failed` | Убедитесь, что `staging:` в шапке сборки — локальный путь, а не UNC. Если локальный — это настоящая регрессия холодного старта, ищите новый тяжёлый импорт |
| `install.cmd` ругается на pyRevit | pyRevit не установлен для **этого** пользователя. `where pyrevit` |
| `install.cmd`: «cannot read payload\VERSION» | шаг 5 не выполнен или нет доступа к папке |
| `ERROR: the server will not start under CPY…` | движок pyRevit у пользователя не тот, под который собраны колёса. Сравните с `payload\ENGINE` и пересоберите шаг 5 |
| В Hermes нет инструментов Revit | `%LOCALAPPDATA%\RevitMCP\current\app\warm.py` запускается? Блок попал в тот файл, который Hermes читает? Запустите `configure_hermes.py --print-only` и сверьте строку `# target:` с `echo %HERMES_HOME%` (на Windows умолчание — `%LOCALAPPDATA%\hermes`, а **не** `~\.hermes`) |
| Инструменты есть, но каждый вызов — ошибка | `http://localhost:48884/revit_mcp/status/` пусто → расширение не загрузилось |
| Расширение не загрузилось | Решает лог, а не догадки: `%APPDATA%\pyRevit\<год>\pyRevit_<год>_<PID>_runtime.log`, строки `Found pyRevit assembly:`. Нашей сборки в списке нет — pyRevit его не собирал. Причина почти всегда `disabled = true` в `[revit-mcp-server.extension]` (`pyRevit_config.ini`), оставшийся от старой версии: `default_enabled` читается только при первом появлении секции, а ключ секции — имя папки, оно не менялось. Лечение: `pyrevit extensions enable revit-mcp-server` и полный перезапуск. `install.cmd` с 2026-09-07 делает это сам |
| `/status/` отвечает `Route does not exist` | То же самое: маршруты не зарегистрированы, потому что расширение не загрузилось. Отвечает встроенный Routes-сервер pyRevit, а не наш код — предыдущая строка |
| `health: degraded` | Читайте `failed_domains` — там имя сломанного домена и текст исключения |
| Застряло на старой версии | `%LOCALAPPDATA%\RevitMCP\update.log`, затем ярлык «Update RevitMCP» вручную |

Откат на предыдущую версию:

```bat
rmdir "%LOCALAPPDATA%\RevitMCP\current"
mklink /J "%LOCALAPPDATA%\RevitMCP\current" "%LOCALAPPDATA%\RevitMCP\versions\<старая>"
echo <старая>>"%LOCALAPPDATA%\RevitMCP\current-version.txt"
```

`rmdir` **без** `/s` — иначе удалится содержимое версии, на которую указывает
junction.

## 11. Решить до раскатки шире пилота

**`/execute_code/` — это неаутентифицированное исполнение произвольного
IronPython внутри Revit** с полным доступом к `doc`, `DB`, `clr`, `System` и
файловой системе. Единственное, что его сдерживает, — то, что Routes слушает
петлевой интерфейс. `install.cmd` предупреждает, если не смог подтвердить
`[routes] host = "127.0.0.1"`.

**Проверять это надо по логу, а не по конфигу.** Предупреждение установщика
означает лишь «не смог подтвердить», а факт пишется при старте сессии:

```
Routes server is listening on http://0.0.0.0:48884     ← открыт всей сети
Routes server is listening on http://127.0.0.1:48884   ← только петля
```

Ищите эту строку в `%APPDATA%\pyRevit\<год>\pyRevit_<год>_<PID>_runtime.log`.
На первой пилотной машине (2026-09-07) там оказался **`0.0.0.0`**: порт был
открыт всей корпоративной сети. Через CLI это не чинится — у
`pyrevit configs routes` есть только `enable/disable`, `port` и `coreapi`,
подкоманды `host` нет. Остаются три рычага: дописать `host = "127.0.0.1"` в
секцию `[routes]` файла `pyRevit_config.ini` при закрытом Revit (вопреки общему
правилу не трогать его руками), правило файрвола на входящий 48884, либо
`pyrevit configs routes disable`, когда станция не тестируется.

На двух-трёх пилотных машинах это приемлемый риск. Раскатка на отдел — это
раскатка того же риска на отдел, и её стоит согласовать с владельцем контура.
Обсуждаемое решение: env-флаг `REVIT_MCP_ALLOW_EXEC`, по умолчанию выключенный,
плюс перенос часто исполняемых сниппетов в типизированные маршруты.

Второе: **пилот на реальной зажатой станции ещё не пройден** — AppLocker, EDR,
реальная сеть, реальный парк версий pyRevit. Именно это и проверяет шаг 6.
