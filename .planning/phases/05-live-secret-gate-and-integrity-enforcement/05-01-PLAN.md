## The gate contract (defined here; every later plan relies on it)

`revit_mcp/security.py` is a helper module (no `register_*_routes`, so discovery reports it as a
helper). IronPython 3 at the Python 3.4 language level: encoding cookie on line 1, `"{}".format`, no
f-strings, no annotations, relative sibling imports only (`from . import trust`, `from . import
integrity`). It imports nothing from pyRevit at module level; `from pyrevit import routes` happens
inside the private `_refusal(body, status)` helper only, so CPython tests import the module directly.

- Module state `_STATE = None`. None means "not initialized": the gate answers 401
  `server_not_configured`, so a failed initialization keeps every gated route closed.
- `initialize(root, package_dir)`: sets `_STATE = None` first, then reads the secret with
  `trust.read_secret_file(os.path.join(package_dir, trust.SECRET_FILE_NAME))` and the integrity verdict
  with `integrity.check_integrity(root)` (both read-only and never raise), and assigns
  `_STATE = {"secret": <text or None>, "integrity": <result dict>}`. Idempotent: every call recomputes
  everything (a pyRevit Reload re-runs startup.py while submodules stay cached). Returns nothing that
  contains the secret (return None). An unexpected exception propagates so startup can record it,
  with `_STATE` left None. This plan implements and tests it on temporary trees; 05-16 adds the call
  in `startup.py`.
- `gate_or_response(request)`: returns None when the call may proceed, otherwise a routes response.
  Order: state None gives 401 `server_not_configured`; `trust.split_envelope(request.data)`; verdict
  `trust.check_secret(trust.envelope_secret(envelope), state["secret"])`, not `AUTH_OK` gives
  `trust.auth_failure(verdict)` (401); integrity `state == trust.INTEGRITY_MISMATCH` gives
  `trust.integrity_failure(trust.mismatch_files(result))` (423); otherwise `request.data` is replaced
  by `trust.clean_body(raw, payload)` and None is returned. The whole body is inside `try/except
  Exception`; the except path returns `trust.gate_failure()` (HTTP 500, fixed text, no locals, no
  body) so a request object whose `data` cannot be reassigned fails closed and loudly.
- `strip_envelope(request)` (Task 2): the same split and rewrite for the seven open POST reads, but it
  never refuses, never raises, and rewrites only when the parsed body is a dict that contains `_mcp`;
  any other body (None, invalid JSON, a list) is left exactly as it arrived.
- `trust.clean_body(raw, payload)` (pure): raw bytes gives `json.dumps(payload).encode("utf-8")`, raw
  text gives `json.dumps(payload)`, a raw dict gives the payload dict; `json.dumps` keeps its default
  `ensure_ascii=True`, so Cyrillic survives as `\uXXXX` and round-trips through `parse_request_data`.
  Runtime types come from the `_BYTES_TYPE` / `_TEXT_TYPE` aliases already imported in trust.py (never
  a `unicode` probe).
- `trust.gate_failure()` returns `({"error": "Mutation rejected: the request gate failed before the
  route ran. Nothing was changed.", "gate": "internal_error"}, 500)`; `trust.GATE_FAILURE_STATUS = 500`.
- `trust.OPEN_POST_READ_ROUTES = frozenset((...))` with exactly the seven D-02 keys in the route-key
  form `inventory_support` uses: "/document_summary/", "/document_levels/", "/model_worksets/",
  "/material_quantities/", "/clash_check/", "/ai_filter/", "/list_category_parameters/". It sits next to
  `UNGATED_METHODS` with a comment: adding a key is an edit of this set plus the pinning test (05-06),
  like `UNLOCKED_GET` in bridge.py.

The gated preamble (copied verbatim by every gated handler, before the document guard and before any
other statement except the docstring): `gate_refusal = gate_or_response(request)` then
`if gate_refusal is not None:` / `return gate_refusal`. The variable is named `gate_refusal` because the
Phase 2 inventory test asserts the document guard's own `refusal` by name. A one-line comment above it
is allowed: "Phase 5 gate (D-01): shared secret and integrity, before anything else."
