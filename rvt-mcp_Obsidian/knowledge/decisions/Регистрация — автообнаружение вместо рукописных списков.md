# Регистрация — автообнаружение вместо рукописных списков

## Решение

`startup.py` и `tools/__init__.py` больше не содержат рукописного списка
доменов. Оба сканируют свою папку (`os.listdir` на Revit-стороне,
`pkgutil.iter_modules` на MCP-стороне), находят модули с
`register_*_routes` / `register_*_tools` по regex и регистрируют каждый.

Это закрывает долг, описанный в
[[Регистрация ведётся двумя рукописными списками]] — та заметка фиксировала
проблему и предлагала это же решение как «путь исправления», не сделав его.

## Почему это стало безопасно сделать

Открытый вопрос из старой заметки — «не зависит ли что-то от порядка
регистрации» — закрыт проверкой, а не предположением: ни один модуль
`revit_mcp/` не импортирует другой модуль `revit_mcp/`. Все перекрёстные
импорты идут в плоский `utils`. Порядок можно было заменить на `sorted()` без
риска.

Соответствие «имя файла → имя функции регистратора» **не механическое**
(`rooms.py`→`register_room_routes`, `views.py`→`register_views_routes`,
`colors.py`→`register_color_routes`), поэтому обход ищет функцию по паттерну
имени внутри модуля, а не выводит имя из имени файла.

## Что это даёт при нескольких разработчиках

Оба файла были ровно теми двумя, что правит каждый разработчик при добавлении
домена — и ровно теми двумя, что конфликтуют при `git merge upstream/master`
(репозиторий — форк). После этого изменения добавление возможности — это два
новых файла, ноль правок в общих. Конфликтов между разработчиками и с
апстримом в этих файлах больше не бывает.

## Побочный эффект

Модуль без регистратора (например `utils.py`) больше не исключается по
имени — он классифицируется как хелпер только после того, как в нём не
найдено функции по паттерну. Опечатка в имени регистратора теперь не
теряется молча, а попадает в список пропущенных модулей.
