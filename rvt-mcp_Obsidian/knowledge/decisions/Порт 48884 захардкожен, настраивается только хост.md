# Порт 48884 захардкожен, настраивается только хост

## Решение

Единственная переменная окружения, которую читает сервер, — **`REVIT_HOST`**
(по умолчанию `localhost`). Всё остальное — константы в `main.py`.

```python
REVIT_HOST = os.environ.get("REVIT_HOST", "localhost")
REVIT_PORT = 48884  # Default pyRevit Routes port
BASE_URL = f"http://{REVIT_HOST}:{REVIT_PORT}/revit_mcp"
```

## Обоснование

48884 — дефолтный порт pyRevit Routes. Для локального инструмента одного разработчика
конфигурируемость порта не нужна: сервер и клиент на одной машине, значение известно.

Ни `.env`, ни конфиг-файла, ни секретов в проекте нет вообще — конфигурировать по сути
нечего.

## Полный список захардкоженного

| Что | Значение |
|---|---|
| Бинд MCP-сервера | `127.0.0.1:8000` |
| Порт pyRevit Routes | `48884` |
| Таймаут GET/POST | 30.0 с |
| Таймаут картинок | 60.0 с |
| `stateless_http` | `True` |
| `json_response` | `True` |
| Лимиты пула httpx | 10 keep-alive / 20 всего |

Также читаются `USERPROFILE` / `HOME` — для каталога вывода документации по умолчанию
(`revit_mcp/documentation.py`, фолбэк `C:\`).

## Что это блокирует

**Два сервера рядом не поднять.** Нельзя работать с двумя открытыми экземплярами Revit:
адресация одна, порт один. Нельзя и подключиться к нестандартной конфигурации pyRevit
Routes.

**Нельзя настроить таймауты под операцию.** Clash-детект по большой модели и статус-пинг
делят один бюджет в 30 секунд.

## Обратная сторона: `REVIT_HOST` — это риск

> [!danger] REVIT_HOST переопределяется на любой хост
> Указав его на нелокальную машину, вы отправите неаутентифицированные запросы,
> изменяющие модель и исполняющие произвольный код, по сети в открытом виде.
> Модель доверия проекта — «только петля», но она нигде не форсируется.

См. [[execute_code даёт неаутентифицированное исполнение кода внутри Revit]].

## Путь исправления

Сделать порт настраиваемым по той же схеме, что и хост (`REVIT_PORT`), и добавить
селектор документа в маршруты, которым он нужен. Плюс таймауты на уровне обёртки
инструмента.
