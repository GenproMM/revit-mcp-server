<objective>
Fill the request side of each entry: who asked (the Windows user), what the tool was asked to do
(its arguments, including requested new parameter values and the execute_code text with its hash)
and the user's request as the assistant reported it. Make the secret impossible to land in the log:
one redaction function, applied before any cut and again on the finished line, plus a key scrub on
tool arguments. Prove it by grepping the raw bytes of the audit files after every scenario ROADMAP
criterion 7 and D-13 name.

Purpose: AUDIT-08 (no secret, no excess personal data), AUDIT-02 ("what was requested", affected
elements via arguments), decisions D-04 (execute_code text, length, SHA-256), D-10 (Windows user
only), D-11 (arguments with limits, no body, no read results), D-12 (user_request recorded with
length, missing flag and source), D-13 (single redaction point, the four-scenario grep).

Output: request-content shaping and redaction in `audit.py`, rows in `tests/unit/test_audit_entry.py`,
new `tests/unit/test_audit_secret.py`.
</objective>

<threat_model>
ASVS level 1; block on high. Every high threat below is mitigated in this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model -> tool arguments / user_request / execute_code text | the model may paste the secret or personal data into any argument |
| Revit reply text -> failed reasons, revit_failures, document fields | reply strings are copied into the log and could echo request text |
| MCP server process -> local audit file | everything written persists on disk under the user's profile |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-13 | Information disclosure | secret in args, user_request, code, reply strings | high | mitigate | single redaction function: raw and JSON-escaped secret replaced in every string, before every cut (_clip), structural pass over the entry, final pass on the serialized line, key scrub of secret-named arguments; file-bytes grep over nine scenarios including a straddled cut (Tasks 1-2) |
| T-06-14 | Information disclosure | writer failure path printing the entry | medium | mitigate | `_warn_once` writes only the exception class, once per process; stderr row asserts the secret is absent (Task 2) |
| T-06-15 | Information disclosure | excess personal data | medium | mitigate | only windows_user is collected about the person; schema rows pin the key set (Task 1) |
| T-06-16 | Spoofing | model reports a false user_request | low | accept | recorded as user_request_source "assistant", unverified by design (D-12); never presented as proof |
| T-06-17 | Denial of service | huge arguments or code inflating entries | low | mitigate | code-point caps 500 / 200 items / 2000 / 8192 with recorded true lengths (Task 1) |
</threat_model>
