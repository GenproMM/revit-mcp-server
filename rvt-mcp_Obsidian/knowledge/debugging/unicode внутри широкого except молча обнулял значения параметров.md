# unicode внутри широкого except молча обнулял значения параметров

**Статус:** исправлено, коммит `0e07076` · найдено при аудите импортов после
[[Голый import соседа внутри revit_mcp сломал 22 из 23 доменов]], не самой
пилотной станцией — эта поломка не бросает исключение и ничего не логирует

## Симптом

Никакого. Это и есть суть находки: `revit_mcp/parameters.py` держал
собственную копию `_safe_str()`:

```python
def _safe_str(value):
    if value is None:
        return ""
    try:
        if isinstance(value, unicode):
            return value
        if isinstance(value, str):
            return value.decode("utf-8", "replace")
        return unicode(value)
    except Exception:
        return ""
```

Под IronPython 3 имени `unicode` не существует. `isinstance(value, unicode)`
кидает `NameError`, тот же `except Exception` его ловит вместе со всем
остальным, и функция возвращает `""`. Каждое значение параметра, прошедшее
через эту функцию, тихо превращалось в пустую строку — без исключения в
ответе, без строки в логе, без деградации `/status/`. Внешне сервер выглядел
полностью рабочим.

## Причина

Это уже **вторая независимая копия** ASCII/тип-фильтрующего бага в этом
проекте — первая была [[sanitize_string превращает кириллицу в вопросительные
знаки]] (коммит `bb7cda2`, исправлено 2026-09-04). Тогда фикс сделал
`revit_mcp/textutils.py` с типобезопасными алиасами `_TEXT_TYPE`/`_BYTES_TYPE`
и юнит-тестами, но `parameters.py` эту копию не переиспользовал — она была
списана до появления `textutils.py` и осталась независимой веткой того же
класса ошибки.

Ключевая деталь не в самом `unicode`, а в **ширине обработчика**. Уже
существующий, правильный код в `textutils.py` тоже ссылается на `unicode`
голым именем — но под `except NameError`, который называет именно ту ошибку,
которую хочет поймать. `parameters.py` ловил `except Exception` — синтаксис
выглядит похоже, поведение прямо противоположное: один эксплицитно объявляет
совместимость, второй маскирует любую ошибку как штатный путь.

## Обход / исправление

`_safe_str` в `parameters.py` заменён на alias на
`textutils.sanitize_value()` — новую функцию, разделяющую типобезопасные
алиасы с `sanitize_string`/`normalize_string`, с тем же контрактом пустой
строки для `None`. Теперь одно определение вместо двух, и оно покрыто
тестами (`test_sanitize_value_preserves_cyrillic`,
`test_sanitize_value_renders_missing_as_empty_not_unnamed`).

`scripts/conventions.py` получил проверку: `unicode`/`basestring`/`xrange`/
`long` вне охраны — нарушение, и охрана засчитывается **только** если
обработчик называет исключение явно (`except NameError`), а не любой
`except Exception`/`except BaseException`. Проверено тестом
`test_bare_py2_builtin_is_caught_even_inside_a_broad_except` — именно на
форме этого бага.

## Урок

> Молчаливый отказ опаснее падения. `ImportError` из соседнего домена нашла
> пилотная станция за один день — она видна в `/status/`. Эту находку не
> нашёл бы никто без чтения кода построчно: сервер отвечает 200, JSON
> валиден, просто каждое значение параметра пустое. Правило «широкий except —
> это поток управления» ([[Широкий except Exception используется как поток
> управления]]) имеет предел: он не должен накрывать проверку совместимости
> рантайма, где конкретное исключение — единственный сигнал, что код вообще
> портативен.
