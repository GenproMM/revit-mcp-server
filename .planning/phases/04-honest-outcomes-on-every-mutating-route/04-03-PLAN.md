## Interface from 04-01 (import from `.utils`; do not edit utils.py or textutils.py here)

`commit_and_report(t, swallower)`, `finalize_outcome(commit_result, data, requested, succeeded,
failed)` returning `(payload, http)`, `build_outcome(...)`, `exception_outcome(t, requested,
succeeded, failed)`, `transaction_status_of(t)`, `classify_outcome(...)`. Route pattern, item
convention and `requested` rule: 04-01-PLAN.md. In this plan: batch creation, created ids in
succeeded and input indices (or "INDEX.name") in failed; tag_walls, wall ids; create_dimensions and
create_detail_line, created id in succeeded and step names or input element ids in failed.

## Execution rules for every task in this plan

- IronPython 3.4-level syntax in `revit_mcp/`; relative sibling imports; no cross-domain imports.
- Every migrated handler follows the 04-01 route pattern: `t = None`, `requested = None`,
  `succeeded = []`, `failed = []` before the outer try; `swallower = suppress_warnings(t)` right after
  `t.Start()`; only `commit_and_report` commits; post-commit element reads after the committed check;
  500 replies gain `"outcome": exception_outcome(t, requested, succeeded, failed)` and keep `error`
  and `traceback`; pre-transaction validation and in-transaction validation that rolls back and
  answers 4xx stay unchanged and carry no outcome (D-04). The building routes' inner `except` that
  answers 500 "Transaction failed: ..." also gains the outcome.
- Legacy `errors` string lists stay exactly as they are; each entry gets a structured twin in
  `failed` with `item` = the input index and `reason` = the same text without the "Element N: " or
  "Level N: " prefix.
- Tests: never weaken an existing assertion; arm the fake for real success paths; make the DB
  attributes a route compares against stable by assigning them once in `make_db` (a `MagicMock`
  caches its children, a fresh `_DB.__getattr__` mock per access does not).
- Commit protocol: `uv run pytest tests/unit -q` green before every commit; explicit pathspec
  commits only (`git commit -m "<message>" -- <paths>`), never `git add -A`/`.`; the user's staged
  files stay staged. Prefix `feat(04-03):` / `test(04-03):`; end with your session's attribution line.
