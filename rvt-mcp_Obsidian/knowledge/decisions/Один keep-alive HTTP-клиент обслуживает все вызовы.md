# Один keep-alive HTTP-клиент обслуживает все вызовы

## Решение

Единственный `httpx.AsyncClient` создаётся лениво и переиспользуется всеми вызовами
инструментов. Это **единственный изменяемый глобал** на всём MCP-сервере.

```python
_http_client: Optional[httpx.AsyncClient] = None

def _get_client() -> httpx.AsyncClient:
    global _http_client
    if _http_client is None or _http_client.is_closed:
        _http_client = httpx.AsyncClient(
            base_url=BASE_URL,
            limits=httpx.Limits(max_keepalive_connections=10, max_connections=20),
        )
    return _http_client
```

## Обоснование

Раньше на каждый запрос конструировался новый клиент. Сессия работы с моделью легко
выдаёт десятки вызовов к локальному серверу Routes, и стоимость TCP-рукопожатия на
каждом из них — чистые накладные расходы.

Комментарий в коде фиксирует это дословно: переиспользование одного `AsyncClient`
избавляет от per-request TCP-затрат, «что заметно, когда сессия выстреливает десятки
вызовов».

Изменение попало в коммит `67644ee` вместе с другими правками по эффективности после
живого прогона на Revit 2027.

## Детали реализации

- **Ленивое создание** — клиент не поднимается при импорте, что важно для холодного
  старта.
- **Проверка `is_closed`** — клиент пересоздаётся, если был закрыт, поэтому сервер не
  ломается насмерть после закрытия.
- **`base_url=BASE_URL`** — все эндпоинты в модулях указываются относительно
  (`/clash_check/`), базовый URL не дублируется 48 раз.
- **Лимиты:** 10 keep-alive соединений, 20 всего.

## Что это не решает

**Параллелизма не даёт.** 20 конкурентных соединений на MCP-стороне не превращаются в
параллельную работу — транзакции сериализуются через UI-поток Revit. Конкурентные
вызовы просто встают в очередь за контекстом Revit API.

Хуже того: если `suppress_warnings` не сработал и Revit показал модальный диалог, все
20 соединений блокируются одновременно и навсегда. Правильнее было бы сериализовать
изменяющие вызовы на клиенте, а не надеяться на пул.

**Ни ретраев, ни circuit breaker.** Зависание Revit проявляется как таймаут 30 с (или
60 с для картинок), возвращённый строкой ошибки.

**Единый таймаут на всё.** `_revit_call` по умолчанию даёт 30 с любому вызову — и
статус-пингу, и полному clash-детекту по модели. Только `tools/status_tools.py`
переопределяет его. Нужны таймауты на уровне обёртки для известно медленных
эндпоинтов.
