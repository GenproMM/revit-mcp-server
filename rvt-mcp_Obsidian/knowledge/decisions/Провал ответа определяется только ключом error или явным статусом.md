# Провал ответа определяется только ключом error или явным статусом

## Решение

Словарь считается ошибкой **тогда и только тогда**, когда у него есть непустой ключ
`error` либо `status` из набора `error` / `failed` / `failure` / `exception`. Любой
другой словарь — данные.

```python
has_error = (bool(response.get("error")) or
             status in ("error", "failed", "failure", "exception"))
is_success = not has_error
```

## Обоснование

Раньше логика считала провалом любой словарь без ключа `status`. Но многие маршруты
возвращают чистые данные без поля статуса — например `/model_info/`. В результате
`get_revit_model_info` показывал реальные данные под заголовком `=== ERROR DETAILS ===`.

См. [[get_revit_model_info показывал данные под ложным заголовком ошибки]] — это
именно та бага, из-за которой правило стало явным (коммит `c1231f6`).

> [!important] Не добавляйте новых неявных сигналов ошибки
> Ровно это уже было багой. Правило зафиксировано в `tools/utils.py`, и
> `tests/test_model_info_format.py` его охраняет.

## Как рендерится успех

`format_response` выбирает ключ вывода по порядку:

1. `output` — ответы исполнения кода
2. `message`
3. `result`
4. `data`
5. `status == "active"` — особый случай, красиво форматирует статус-ответ
6. иначе — сброс всех полей кроме `status` / `health` / `success` как
   `Ключ: значение`, отсортировано
7. если и их нет — `"Operation completed successfully"`

Шаг 6 — это тоже часть исправления: структурированные данные без стандартной обёртки
теперь **выводятся**, а не прячутся за общей фразой.

## Как рендерится ошибка

Блок `=== ERROR DETAILS ===` со статусом, сообщением, `details`, затем
`=== TRACEBACK ===`, затем отладочные поля `code_attempted`, `endpoint`,
`request_data`, `response_code`, затем `=== ADDITIONAL RESPONSE DATA ===` для всего
неопознанного.

## Что здесь не так

Это стострочная функция, **угадывающая** и успех, и форму вывода. Маршрут, вернувший
неожиданную комбинацию ключей, даст либо кривой дамп, либо ложную ошибку.

**Правильное решение на будущее:** объявить один конверт ответа на стороне
`revit_mcp/` — `{"ok": bool, "data": ..., "error": ...}` — и превратить
`format_response` в глупый рендерер поверх него.

Функция чистая, без зависимостей, и полностью не покрыта тестами. Это лучший
кандидат на тест во всём репозитории — см. [[Текущие приоритеты]].
