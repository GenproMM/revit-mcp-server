# Пакетные операции возвращают success, скрывая пропущенные элементы

**Статус:** ОТКРЫТАЯ БАГА · системная, в нескольких модулях

## Симптом

Массовый маршрут ловит исключение по каждому элементу, делает `continue` и всё равно
возвращает `"status": "success"`. Вызывающий видит сообщение об успехе, при том что
часть элементов была пропущена. Единственный намёк — количество в ответе, которое надо
сравнивать с ожидаемым вручную.

## Где это есть

- `revit_mcp/building.py:244`
- `revit_mcp/building.py:548`
- `revit_mcp/clash.py:213`
- `revit_mcp/analysis.py:367-382`

Это не полный список — паттерн системный.

## Триггер

Любой элемент в пакете, который выбрасывает: удалённый ID, элемент без геометрии,
заблокированное семейство, элемент из связанной модели.

## Обходной путь

Нет. Количество в ответе — единственный сигнал.

## Исправление

Маршруты должны возвращать массив `skipped` / `failures` рядом с успехами, с причиной
на каждый элемент:

```python
return routes.make_response(data={
    "status": "success",
    "created_count": len(created),
    "created": created,
    "skipped": skipped,          # ← [{"element_id": ..., "reason": "..."}]
    "skipped_count": len(skipped),
})
```

Ровно так уже исправлен `tag_walls` —
[[tag_walls молча пропускал стены и возвращал отмечено 0]]. Осталось распространить
это на остальные пакетные маршруты.

Отдельный вопрос: должен ли `status` оставаться `success`, если пропуски были. Скорее
да — операция состоялась частично, и клиент должен получить и результат, и список
проблем. Но тогда `success` обязан сопровождаться видимым `skipped_count`, иначе он
вводит в заблуждение.

## Почему это важнее, чем кажется

Потребитель этих ответов — языковая модель, которая по «success» строит следующий шаг.
Если 200 из 500 балок не создались, а ответ говорит «успех», модель поедет дальше по
плану на неполной модели, и расхождение обнаружится через десятки операций.
