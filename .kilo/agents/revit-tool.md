# Агент: разработка инструмента Revit MCP

Ты работаешь в репозитории с **двумя рантаймами Python**, которые никогда не
делят интерпретатор. Нарушение регламента здесь не приводит к внятной ошибке —
инструмент просто не появляется, а маршрут отвечает 404. Поэтому порядок ниже
обязателен.

Полные правила — в `AGENTS.md`. Здесь только процедура.

## Шаг 0. Понять задачу, прежде чем писать

Задай пользователю вопросы, если не хватает:

- Что именно инструмент делает — **читает** модель или **изменяет** её?
  От этого зависит всё: читающий маршрут не открывает транзакцию.
- Какие категории Revit затронуты и какие параметры нужны.
- Что должно вернуться и в каких единицах.
- Что считать ошибкой, а что — пустым результатом.

Не начинай писать код, пока не знаешь ответ на первый вопрос.

## Шаг 1. Проверить, не существует ли это уже

51 инструмент уже есть. Прочитай `tests/unit/tool_manifest.txt` и найди
похожее. Часто нужное — это **параметр существующего инструмента**, а не новый
инструмент: лишний инструмент ухудшает выбор моделью для всех остальных.

Если сомневаешься — спроси пользователя, а не добавляй.

## Шаг 2. Сгенерировать каркас

```bash
uv run python scripts/new_tool.py <domain> <tool_name>          # с записью в модель
uv run python scripts/new_tool.py <domain> <tool_name> --get    # только чтение
```

**Никогда не создавай файлы в `revit_mcp/` или `tools/` вручную.** Генератор
гарантирует конвенции по построению: кодировочную куку, точную сигнатуру
регистратора, `ctx` последним, `-> str`, блок `Args:`. Рукописный файл почти
наверняка нарушит что-то из этого, и это выяснится только на живом Revit.

Расширяешь существующий домен — правь его файлы и допиши имя инструмента в
`tests/unit/tool_manifest.txt`.

## Шаг 3. Заполнить TODO

Твоё решение — только алгоритм. Всё остальное уже задано шаблоном.

В `revit_mcp/<domain>.py` (IronPython 2.7 — только `"{}".format(x)`):

- Читаешь? Транзакцию **не открывай**.
- Пишешь? Оставь блок транзакции как в шаблоне: `suppress_warnings(t)` строкой
  после `t.Start()`. Без него Revit откроет модальное окно и повесит сервер
  насмерть.
- Идентификаторы: `get_element_id_value()` / `make_element_id()`. Никогда
  `.IntegerValue`, никогда `DB.ElementId(<int>)`.
- Имена: `get_element_name()` — сохраняет кириллицу.
- Перебираешь много элементов: ловля исключения на каждом, счётчик пропусков,
  и пропуски **в ответе**.
- Размеры на входе — миллиметры, внутрь Revit через `MM_TO_FEET`.

В `tools/<domain>_tools.py` главное — **докстринг**. Это единственное, что
модель увидит перед вызовом: назначение, правила области, форматы значений с
конкретными примерами, форма возврата с единицами, ограничения прямым текстом,
блок `Args:` со всеми параметрами включая `ctx`. Эталон — `check_clashes` в
`tools/clash_tools.py`; прочитай его перед тем, как писать свой.

## Шаг 4. Проверить

```bash
uv run pytest tests/unit
```

Обязательно. Если упало — **нарушено правило, правь код, а не тест**.

Дальше, на живой модели:

1. **Полностью закрыть и открыть Revit.** Reload недостаточно — он валит
   процесс Revit на первом запросе.
2. `http://localhost:48884/revit_mcp/status/?verbose=true` — домен в списке,
   `health: healthy`. Если `degraded` — читай `failed_domains`, там причина.
3. `mcp dev main.py` — вызвать инструмент.

Не сообщай, что готово, пока не выполнены все три пункта. «Тесты прошли» — это
не «работает»: пройденные юнит-тесты ничего не говорят о поведении внутри Revit.

## Шаг 5. Коммит

Ветка `feature/<тема>`, префикс `feat(...)`/`fix(...)`, тело в форме
**симптом → причина → исправление**.

## Чего не делать никогда

- Не реализовывать задачу через `execute_revit_code`. Это люк для разведки;
  рабочее решение — типизированный маршрут.
- Не править `format_response` в `tools/utils.py`.
- Не трогать `deploy/` и отключение `GenproMCP` в `install.cmd`.
- Не менять `routes.API("revit_mcp")` и имя папки расширения.
- Не отключать и не ослаблять тесты, чтобы «прошло».

## Если застрял

Скажи об этом прямо и покажи, что именно не сходится. Не подставляй заглушку,
которая проходит тесты, и не помечай задачу выполненной. Молчаливая заглушка в
BIM-инструменте означает неверные данные в модели, которые заметят месяцы спустя.
