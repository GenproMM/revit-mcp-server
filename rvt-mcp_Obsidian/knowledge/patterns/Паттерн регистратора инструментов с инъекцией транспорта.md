# Паттерн регистратора инструментов с инъекцией транспорта

## Форма

```python
# -*- coding: utf-8 -*-
"""Clash detection tools — hard interference checking for BIM coordination"""

from mcp.server.fastmcp import Context
from .utils import format_response


def register_clash_tools(mcp, revit_get, revit_post, revit_image=None):
    """Register clash detection tools with the MCP server."""
    _ = revit_image  # Acknowledge unused parameter

    @mcp.tool()
    async def check_clashes(
        set_a_categories: list[str] = None,
        set_b_categories: list[str] = None,
        max_clashes: int = 200,
        ctx: Context = None,
    ) -> str:
        """<докстринг — контракт для модели>"""
        data = {
            "set_a_categories": set_a_categories,
            "set_b_categories": set_b_categories,
            "max_clashes": max_clashes,
        }
        response = await revit_post("/clash_check/", data, ctx)
        return format_response(response)
```

`tools/clash_tools.py` — эталонный пример этого паттерна.

## Обязательные элементы

- **`# -*- coding: utf-8 -*-`** первой строкой (в `tools/` строчными, в `revit_mcp/` —
  `UTF-8` прописными; так исторически, оба варианта рабочие).
- Импорты ровно два: `from mcp.server.fastmcp import Context` и
  `from .utils import format_response` — **относительный** импорт, `tools` настоящий пакет.
- **Тело инструмента всегда заканчивается** `return format_response(response)`.
- Тип возврата — всегда `-> str`.
- **`ctx: Context = None` — последним** параметром, всегда.
- Неиспользуемые внедрённые параметры подтверждаются: `_ = revit_image`.

## Параметры инструмента

Только keyword-аргументы с дефолтами. Схему FastMCP выводит из тайп-хинтов и
докстринга через pydantic, поэтому:

- тайп-хинты обязательны и должны быть точными (`list[str]`, `int`, `bool`);
- каждый параметр обязан быть описан в блоке `Args:` докстринга, включая `ctx`.

См. [[Докстринг инструмента — это контракт для модели, а не для разработчика]].

## Логирование через контекст

Прогресс и ошибки — через MCP-контекст, всегда под проверкой:

```python
if ctx:
    await ctx.info("Executing code in Revit...")
if ctx:
    await ctx.error("Failed: {}".format(err))
```

Примеры: `tools/code_execution_tools.py`, `tools/colors_tools.py`.

> [!warning] Никогда `print()` в stdio-режиме
> Это ломает поток протокола. Единственный `print` в `main.py` защищён проверкой на
> `--combined`.

## Асимметрия сигнатур

`tools/__init__.py` вызывает регистраторы с **разным числом аргументов** — часть
модулей объявляет только то, что использует:

```python
register_status_tools(mcp_server, revit_get_func)                   # только GET
register_family_tools(mcp_server, revit_get_func, revit_post_func)  # GET + POST
register_clash_tools(mcp_server, revit_get_func, revit_post_func, revit_image_func)
```

Добавляя модуль, согласуйте и объявление, и вызов — унифицированной сигнатуры нет.
