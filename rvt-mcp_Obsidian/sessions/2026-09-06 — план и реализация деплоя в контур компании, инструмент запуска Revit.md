# Сессия 2026-09-06 — план и реализация деплоя в контур компании, инструмент запуска Revit

## Запрос

Пользователь работает через RDP на удалённый ПК в закрытом контуре компании,
где будет вручную обновлять git-репозиторий на сервере. Нужна архитектура
раскатки MCP-сервера на отдел: минимум настроек при первичной установке,
бесшовное обновление. По ходу сессии добавились два уточнения: клиент у
пользователей — десктопное приложение Hermes Agent (не Claude Desktop), а
станции без прав администратора. Отдельным запросом — MCP-сервер должен уметь
сам открывать Revit, если тот закрыт.

## Что сделано

**Режим Plan Mode → согласованный план.** Разведка подтвердила ключевой факт:
`revit_mcp/` — pyRevit Routes внутри процесса Revit; централизованный сервер
на компании физически невозможен, сервер может быть только точкой раздачи.
См. [[Деплой в контур — сервер раздаёт файлы, оба процесса живут на станции]].

**Реализация и живая проверка каждого шага:**
- `extension.json`: `default_enabled: False → True`, `builtin: True → False` —
  без этого расширение на чистой станции молча не грузится.
- `pyproject.toml` / `uv.lock`: объявлены `httpx`, `anyio`, `uvicorn`
  (импортировались, но не были задекларированы); `ruamel.yaml` — в отдельную
  dependency-группу `deploy`.
- Новый каталог `deploy/`: `build-payload.cmd`, `publish-extension.cmd`,
  `install.cmd`, `update.cmd`, `find-python.cmd`, `config.cmd`,
  `configure_hermes.py`, `server.py`, `gate.py`, `warm.py`, `README.md`.
- `README.md` / удалён `README_UV.md` (противоречил основному README, указывал
  на чужой upstream).

**Пересмотр решения по ходу работы.** Пользователь указал: pyRevit уже
обязателен и несёт свой Python — не нужно тащить отдельный интерпретатор.
Проверено на живой машине и переделано: payload 108 МБ → 34 МБ.
См. [[Деплой в контур — сервер раздаёт файлы, оба процесса живут на станции]]
(раздел «Ключевой пересмотр решения»).

**Новый инструмент по отдельному запросу.** `tools/process_tools.py`:
`get_revit_process_status`, `start_revit`. См.
[[start_revit — единственная пара инструментов без Revit-стороны]].

**Найдены и исправлены два реальных бага** в процессе тестирования нового кода
(не в существующей кодовой базе):
- [[get_revit_process_status различает Revit закрыт от Revit без документа]]
- [[format_response прячет поля ответа за ключом message]]

**Побочный артефакт.** По запросу пользователя опубликована HTML-схема
развёртывания для нетехнической аудитории (не в этом хранилище — Claude
Artifact, приватная ссылка).

## Проверено вживую

- Полный цикл: сборка → публикация → установка → обновление → откат — на
  staged-копии шары, не на реальной сети.
- Гейт холодного старта на движке pyRevit: 0.826-0.938с (потолок 2.0с).
- `start_revit` реально запускал Revit 2027 на машине пользователя (PID
  подтверждён), но полный зелёный путь до ответа моста не пронаблюдён — см.
  открытый пункт в [[start_revit — единственная пара инструментов без Revit-стороны]].
- 47 детерминированных тестов на подставных данных: 25 для `configure_hermes.py`
  (правка чужого YAML-конфига без потери комментариев), 22 для
  `process_tools.py`. Тесты — в скрэтчпаде сессии, не в репозитории.

## Не сделано / открыто

  проверены на неизменённых правах).
- ASCII-алиас для UNC-пути шары (кириллица и пробелы — риск для sys.path
  IronPython 2.7 на локали `ru`) — нужно от IT.
- Сверка версии pyRevit на реальном парке станций (здесь — 6.5.3 WIP).
- Судьба `/execute_code/` при раскатке на отдел — согласовать с владельцем
  контура (см. существующая заметка
  [[execute_code даёт неаутентифицированное исполнение кода внутри Revit]]).
