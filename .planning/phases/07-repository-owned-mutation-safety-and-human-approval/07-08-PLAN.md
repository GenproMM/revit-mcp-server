<objective>
Turn the Revit-side permit check on. Behind a decision checkpoint (D-18 is a one-way door for the fleet once the
extension is published), insert the permit step into the existing explicit gate preamble so every closed non-GET
route refuses a request without a valid one-time permit before any effect, and make the rollout observable:
the extension advertises the permit protocol, `get_revit_status` reports the policy source/version/diagnostics and
whether the extension enforces permits, and an offline test proves the extension as it was before this phase
ignores the new envelope key (the D-19 precondition for publishing the payload first).

Purpose: SAFE-12 (refusal before effect, atomic consumption in gate_or_response, closed by default), SAFE-14
(payload-first rollout signals, mixed-state refusal text), SAFE-10 (status names source, version, reason). D-17,
D-18, D-19.

Output: permit step in `revit_mcp/security.py`, `identity.process_token`, AST sentinel and behaviour tests, the
status block and status lines, the rollout test.
</objective>
