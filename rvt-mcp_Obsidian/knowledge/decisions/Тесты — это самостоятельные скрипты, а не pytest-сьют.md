# Тесты — это самостоятельные скрипты, а не pytest-сьют

## Решение

Тестового раннера нет. Ни `pytest.ini`, ни `setup.cfg`, ни
`[tool.pytest.ini_options]` в `pyproject.toml`, ни тестовой зависимости
(`pyproject.toml` объявляет только `mcp[cli]>=1.9.0`).

Тесты — исполняемые скрипты с голым `assert`, запускаемые интерпретатором напрямую:

```bash
python tests/test_model_info_format.py   # e2e: инструмент возвращает реальные данные
python tests/test_init_latency.py        # перф-гейт: cold start под 2.0 с
mcp dev main.py                          # руками: MCP Inspector
```

Агрегирующей команды «прогнать всё» нет. CI нет — каталог `.github/` отсутствует.

## Обоснование (историческое, не оправдательное)

Оба теста возникли как **регрессионные гейты для конкретных багов**, а не как часть
плановой стратегии: `test_model_info_format.py` появился вместе с исправлением
[[get_revit_model_info показывал данные под ложным заголовком ошибки]],
`test_init_latency.py` — вместе с замером cold start.

Проверять их проще всего было end-to-end, потому что обе баги воспроизводятся только
через настоящее stdio-рукопожатие. Скрипт без раннера — минимальный способ это
зафиксировать.

## Реальное состояние покрытия

| Что | Покрытие |
|---|---|
| 20 модулей маршрутов `revit_mcp/` (~7 000 строк) | **0** |
| 48 обёрток инструментов `tools/*.py` (~1 400 строк) | 1 из 48, только e2e |
| `tools/utils.py:format_response` | **0** |
| `revit_mcp/utils.py` хелперы ElementId | **0** |

Практически: 2 скрипта, трогающих 1 инструмент из 48.

> [!warning] Фактически сьют никогда не прогоняется
> `test_model_info_format.py` требует живой Revit с pyRevit на `localhost:48884` и
> открытым документом. `test_init_latency.py` — таймингового ассерта, чувствительного
> к скорости машины. Ни раннера, ни зависимости `pytest`, ни CI. Оба — просто
> `asyncio.run`-скрипты.

## Что блокирует исправление

Модули `revit_mcp/` импортируют хелперы как `from utils import ...` (верхний уровень),
потому что pyRevit кладёт каталог модуля в `sys.path`. Вне загрузчика расширений они
**неимпортируемы** — ни юнит-тест, ни линтер с разрешением импортов их не увидит.
См. [[Revit-часть написана на IronPython 2.7 и не может делить код с MCP-частью]].

## Прагматичный первый шаг

Вытащить чистые функции в модуль, импортируемый под CPython 3, и накрыть их тестами:

- `get_element_id_value`, `make_element_id`, `sanitize_string` (`revit_mcp/utils.py`)
- `_resolve_bic`, `_resolve_categories` (`revit_mcp/clash.py`)
- `format_response` (`tools/utils.py`) — эта уже импортируема и уже стреляла в
  продакшене

Установление прогоняемого уровня тестов **без Revit** — предпосылка для всех остальных
пунктов покрытия. См. [[Текущие приоритеты]].
