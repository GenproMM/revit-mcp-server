# Открытие центральной без отсоединения шло мимо CreateNewLocal

**Дата обнаружения:** 2026-09-17  
**Где:** `revit_mcp/worksharing.py`, маршрут `/open_model/`

## Симптом

`open_model` с `detach="none"` на модели Revit Server открывал не локальную копию, а саму центральную модель. Явной ошибки при этом не возникало — на файловой центральной открытие проходило успешно, и дефект был виден только по последствиям.

## Механизм

В Revit API **нет** автоматического создания локальной копии. Галочка *Create New Local* в диалоге Open — это отдельный вызов:

```python
DB.WorksharingUtils.CreateNewLocal(central_model_path, local_model_path)
```

Маршрут передавал `ModelPath` центральной прямо в `OpenAndActivateDocument`/`OpenDocumentFile`. Revit честно открывал то, что просили — центральный файл.

Последствия различаются по типу центральной:

- **файловая центральная** — открывается и редактируется напрямую, это классический путь к повреждению workshared-модели
- **Revit Server (RSN)** — открыть в таком режиме нельзя в принципе, запись некуда вернуть

## Почему не заметили раньше

Поведение было **задокументировано как задуманное**. Docstring инструмента гласила:

> `"none"` opens the central file itself without detaching

То есть код делал ровно то, что обещал текст. Ошибка была в самом решении, а не в расхождении кода с документацией, поэтому ни тесты, ни ревью докстрингов её не ловили.

Плюс режим по умолчанию — `detach="preserve"`, и большинство сценариев (осмотр модели, выгрузка данных) идут через него. Ветка `"none"` нужна только когда работу собираются синхронизировать обратно, то есть в самом ответственном сценарии.

## Решение

При `detach="none"` на центральной модели сначала создаётся локальная копия, открывается она. Имя по конвенции Revit: `Documents/<Модель>_<пользователь>.rvt`.

Две ловушки в самом `CreateNewLocal`:

1. **Отказывается писать поверх существующего файла.** Перезапись требует сначала удалить старую копию — то есть молча уничтожить возможную несинхронизированную работу. Поэтому параметр `overwrite_local` (по умолчанию `true`), а `false` превращает существующую копию в явную ошибку. Если копия открыта в Revit, `os.remove` не пройдёт, и лучше вернуть внятное «скорее всего открыта в Revit», чем сырой отказ API.

2. **`BasicFileInfo.IsCentral` возвращает `None` на части версий Revit.** Поэтому копия создаётся и при неизвестном флаге: лишняя локальная копия безвредна, открытая напрямую центральная — нет.

## Проверка

Ветка требует живого Revit и юнит-тестами не покрывается. Признак успеха: после `detach="none"` в `Documents` появился `<Модель>_<пользователь>.rvt`, и в модели доступен Synchronize with Central.
