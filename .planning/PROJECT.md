# revit-mcp-server

## What This Is

Мост между ИИ-ассистентом и Autodesk Revit. MCP-сервер на CPython говорит по HTTP
с расширением pyRevit, работающим внутри процесса Revit, и даёт ассистенту 54
типизированных инструмента для чтения и изменения модели. Пользователи —
BIM-инженеры Genpro на Windows с Revit 2024–2027 и pyRevit.

Форк линии Genpro поверх апстрима Demolinator; прародитель дерева —
`revit-mcp-python`. Лицензия MIT, монетизации нет.

## Core Value

Ассистент может достоверно читать и изменять модель Revit — и инженер может
доверять тому, что ответ сервера описывает то, что действительно произошло.

## Requirements

### Validated

<!-- Реализовано и подтверждено в работе. -->

- ✓ 54 MCP-инструмента над 51 маршрутом в 23 доменных модулях — ядро прогнано на живом Revit 2027, семь пользовательских сценариев на живом Revit 2024
- ✓ Два рантайма разделены и не смешиваются: CPython ≥3.11 (`main.py`, `tools/`) ⇄ IronPython 3 внутри pyRevit (`startup.py`, `revit_mcp/`)
- ✓ Регистрация по соглашению — автообнаружение `register_*_routes` / `register_*_tools`, без рукописных списков; отказ изолирован по домену, `/status/` сообщает `degraded` и называет упавшие
- ✓ Тестовый уровень без Revit — `tests/unit/`, 322+ теста, не требует Revit, pyRevit или сети
- ✓ Контракт `text/plain` + `parse_request_data()` в обход сломанного JSON-парсинга pyRevit под IronPython 3
- ✓ Транзакционная дисциплина: `suppress_warnings(t)` сразу после `t.Start()`, иначе модальный диалог вешает headless-сервер навсегда
- ✓ Совместимость Revit 2024–2027 через `get_element_id_value()` / `make_element_id()`
- ✓ Не-ASCII текст (кириллица) проходит сквозь мост неповреждённым
- ✓ Видимость отката транзакции — `commit_and_report()` возвращает 409 `rolled_back` вместо ложного success (частичное внедрение: `code_execution`, `parameters`, `editing.modify_element`)
- ✓ Открытие моделей, включая Revit Server (`RSN://`) и создание локальной копии при `detach="none"`
- ✓ Раздача в контур компании — payload вне git-репозитория, `contrib-kit/` для разработчиков без доступа к репозиторию

## Context

**Что вскрыто обследованием кода (2026-09-21), а не предположением:**

- `/execute_code/` не закрыт ничем — ни флагом, ни токеном. Полный `__builtins__` плюс `clr`/`System`: это неограниченный RCE под токеном процесса Revit, а не только доступ к Revit API
- На пилотной станции Routes слушает `0.0.0.0:48884` — подтверждено рантайм-логом pyRevit. `pyrevit configs routes` не умеет ставить `host`
- `/status/` возвращает только `document_title`. Ни PID, ни версии, ни порта, ни пути. Два инстанса с `Project1` неразличимы
- Мутирующие маршруты (`delete_elements`, `set_parameter`, `transform_elements`) не возвращают идентичность документа вообще
- Пул httpx: 20 одновременных соединений, ни замка, ни очереди, ни семафора. Параллельные вызовы инструментов открывают до 20 одновременных `DB.Transaction` в однопоточный Revit API
- `commit_and_report` внедрён не везде: `editing.py:75` (`delete_elements`) импортирует helper, но путь удаления зовёт голый `t.Commit()`; то же в `interop.py:96` (`export_ifc`)
- Журнала мутаций нет. Единственный след — `logging` в лог pyRevit, эфемерный и неструктурный
- Dry-run нет ни у одного разрушительного инструмента
- `save_document` (SaveAs) по умолчанию `overwrite=True`; три маршрута экспорта молча делают `makedirs`
- Порт 48884 захардкожен в `main.py:23` — единственное место в рантайме. Второй Revit, который pyRevit ставит на 48885, недостижим по построению

**Незакрытая связь с открытым багом:** расследование `param-write-rolls-back`
(`.planning/debug/`) закрыло видимость отката, но оставило непроверенной
параллельную гипотезу — «writes vanish» может объясняться тем, что отвечал
другой процесс Revit. Проверить это сейчас нечем: идентичности инстанса в
ответе нет. Фундамент этого milestone даёт инструмент для проверки.

**Среда:** IronPython 3 (`IPY342`) с 2026-09-07, парк стандартизирован.
`%APPDATA%\pyRevit\Extensions\revit-mcp-server.extension` — junction на репозиторий,
то есть правки здесь и есть развёрнутое расширение. На пилотных станциях —
копии файлов, не junction.

**Стенд для живой приёмки доступен полностью:** два Revit одновременно,
несколько моделей в одной сессии, рабочая модель Revit Server, пилотная станция
с 0.0.0.0-биндом.

## Constraints

- **Tech stack**: Revit-половина — IronPython 3 на языковом уровне Python 3.4 — f-strings это `SyntaxError` при загрузке расширения; только `"{}".format(x)`, только относительные импорты (`from .utils import ...`)
- **Tech stack**: Два рантайма никогда не делят интерпретатор; общий код только через `revit_mcp/textutils.py`, который не импортирует pyRevit
- **Testability**: `revit_mcp/` не импортируется под CPython — новая логика идёт на CPython-сторону, где её покрывают тесты; Revit-половина остаётся тонким поставщиком данных
- **Deployment**: После правки `revit_mcp/` pyRevit Reload небезопасен — наблюдался крах процесса Revit; нужен полный перезапуск
- **Safety**: Любая мутация документа — в транзакции, `suppress_warnings(t)` сразу после `t.Start()`; исключение — `Save`/`SaveAs` вне транзакции
- **Compatibility**: Revit 2024–2027 одной кодовой базой
- **Security**: Модель угрозы — ИИ портит модель, чужой из сети, отсутствие доказуемости. Не входит: целенаправленный локальный обход инженером

## Key Decisions

| Decision | Rationale | Outcome |
|----------|-----------|---------|
| Целевой рантайм Revit-половины — IronPython 3, не 2.7 | Парк перешёл на `IPY342`; без этого 22 из 23 доменов не регистрировались | ✓ Good |
| Регистрация автообнаружением вместо рукописных списков | Забытая строка в списке молча роняла возможность | ✓ Good |
| POST-тело объявляется `text/plain`, парсится `parse_request_data()` | Парсер JSON в pyRevit сломан под IronPython 3 и не патчится из `startup.py` | ✓ Good |
| 409 `rolled_back` вместо 200 — код несущий | При 200 `format_response` снова выдал бы ложный success | ✓ Good |
| Политика разрешений живёт на CPython-стороне | Там её покрывают тесты (правило «логика на CPython-стороне») | — Pending |
| Обход политики закрывается общим секретом, а не дублем правил в `revit_mcp/` | Дубль правил в IronPython нетестируем; секрет закрывает сеть одним барьером | — Pending |
| Секрет и политика вшиваются в payload при сборке | Не требует сети в рантайме; правка требует пересборки, то есть является порчей, а не настройкой | — Pending |
| Самовосстановление payload — только при старте | Замена файлов под работающим движком pyRevit — сценарий, который валит Revit | — Pending |

## Current Milestone: v0.1 Доверенный мост

**Goal:** Сделать так, чтобы каждый ответ сервера можно было отнести к конкретному
документу в конкретном процессе Revit, чтобы файлы сервера не могли молча разойтись
с эталоном, чтобы мутации не шли в Revit параллельно, и чтобы всё изменённое было записано.

**Target features:**
- Идентичность документа и инстанса в каждом ответе; детект двух слушателей на 48884; мультидокумент и настраиваемый порт
- Общий секрет на мутациях, форсирование бинда на 127.0.0.1, проверка и восстановление целостности payload
- Сериализация мутирующих вызовов; `commit_and_report` во всех мутирующих маршрутах
- Локальный структурный журнал аудита с честным результатом, включая откаты и пропуски
