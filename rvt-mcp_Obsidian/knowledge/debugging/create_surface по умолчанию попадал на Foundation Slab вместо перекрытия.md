# create_surface по умолчанию попадал на Foundation Slab вместо перекрытия

**Статус:** исправлено · коммит `67644ee`

## Симптом

`create_surface_based_element` без указания типа создавал элемент типа «Foundation
Slab». Он выглядит как перекрытие, но Revit относит его к **Structural Foundation**, а
не к Floors. Соответственно элемент не попадал в спецификации перекрытий, вёл себя
иначе в расчётах и путал координацию.

## Причина

Тип по умолчанию выбирался первым найденным `FloorType` из коллектора. В типичном
шаблоне Revit «Foundation Slab» оказывается в этом списке раньше обычных перекрытий —
то есть дефолт определялся **порядком перебора**, а не смыслом.

## Исправление

Выбор дефолта теперь предпочитает **не-фундаментный** `FloorType`. Порядок коллектора
больше не решает.

## Урок

> «Первый элемент из коллектора» — это не дефолт, это случайность, зависящая от
> шаблона проекта. Дефолт должен выбираться по признаку, а не по позиции.

Класс проблем: дефолты, работающие на машине разработчика и ломающиеся на чужом
шаблоне. Проверочный вопрос: **если пользователь откроет проект из другого шаблона,
дефолт останется тем же?** Если ответ зависит от порядка перебора — дефолта нет.
