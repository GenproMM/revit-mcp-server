# Коды статусов 400, 404, 500, 503 несут фиксированный смысл

## Соглашение

| Код | Смысл | Типичный текст |
|---|---|---|
| **400** | Плохие или отсутствующие данные запроса | `"No element_ids provided"`, `"No code provided"` |
| **404** | Элемент не найден | `"Element <id> not found"` |
| **500** | Неожиданное исключение | `str(e)` плюс `traceback` |
| **503** | Нет активного документа | `"No active Revit document"` |

Другие коды в проекте не используются.

## 503 — самая частая проверка

Первые три строки почти любого обработчика:

```python
if not doc:
    return routes.make_response(data={"error": "No active Revit document"}, status=503)
```

Это не формальность: инструменты требуют открытого документа, и 503 («сервис временно
недоступен») точно описывает ситуацию — Revit запущен, Routes отвечает, но работать
не с чем. Клиент по этому коду понимает, что нужно попросить пользователя открыть
проект, а не менять параметры вызова.

## 400 — с подсказкой, а не только с фактом

Практика проекта — вместе с 400 отдавать то, что поможет исправиться:

```python
return routes.make_response(data={
    "error": "No valid categories to check",
    "unknown_categories": a_unknown + b_unknown,
    "hint": "Use BuiltInCategory ids like OST_Walls or aliases like 'ducts', 'beams'.",
}, status=400)
```

Потребитель ответа — языковая модель. «Bad request» без объяснения приводит к
повторению той же ошибки; список нераспознанных значений плюс формат приводит к
исправленному вызову с первой попытки.

## 500 — и проблема с ним

```python
except Exception as e:
    logger.error("...: {}".format(str(e)))
    return routes.make_response(
        data={"error": str(e), "traceback": traceback.format_exc()}, status=500)
```

> [!warning] Traceback не должен уходить наружу
> Он раскрывает абсолютные пути файловой системы, внутренности расширения и версии
> библиотек. Правильно: логировать traceback, отдавать короткое сообщение плюс
> корреляционный идентификатор. Сейчас так делают, среди прочих,
> `revit_mcp/clash.py` и `revit_mcp/code_execution.py`.

## Что происходит с кодом дальше

HTTP-код **до клиента не доходит**. `_revit_call` превращает любой не-200 в строку:

```python
f"Error: {response.status_code} - {response.text}"
```

Дальше `format_response` видит уже строку и отдаёт её как есть. То есть код статуса
становится **частью текста сообщения** — и именно поэтому важно, чтобы тело ответа
содержало осмысленный `error`, а не только код.
