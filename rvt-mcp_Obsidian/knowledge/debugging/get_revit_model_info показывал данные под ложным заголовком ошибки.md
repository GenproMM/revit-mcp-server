# get_revit_model_info показывал данные под ложным заголовком ошибки

**Статус:** исправлено · коммит `c1231f6` · охраняется тестом

## Симптом

`get_revit_model_info` возвращал **реальные данные модели**, но под заголовком
`=== ERROR DETAILS ===`. То есть всё работало, а выглядело как поломка — и ИИ-клиент,
читая ответ, обоснованно решал, что вызов провалился.

## Причина

`format_response` считала ошибкой **любой словарь без ключа `status`**. Но многие
маршруты возвращают чистые данные и поля статуса не содержат вовсе — `/model_info/`
среди них.

Вторая половина проблемы: даже определив ответ как успех, функция не имела ветки для
структурированных данных без стандартной обёртки (`output` / `message` / `result` /
`data`) и падала в общую фразу «Operation completed successfully», **скрывая данные**.

## Исправление

Правило провала стало явным и узким:

```python
# Routes signal failure with an "error" key or an explicit failure status.
# Any other dict (including data-bearing responses that omit "status",
# e.g. get_revit_model_info) is a success — otherwise good data is
# mislabeled as an error.
has_error = (bool(response.get("error")) or
             status in ("error", "failed", "failure", "exception"))
```

Плюс добавлена ветка для структурированного успеха: все поля кроме
`status` / `health` / `success` выводятся как `Ключ: значение`, отсортированные — данные
**показываются**, а не прячутся.

Подробно — [[Провал ответа определяется только ключом error или явным статусом]].

## Регрессионный тест

`tests/test_model_info_format.py` — ассерт **на отсутствие** заголовка:

```python
assert "ERROR DETAILS" not in txt, "false error header present:\n" + txt[:300]
assert "total_elements" in txt, "expected model data missing"
```

Первый ассерт ловит ложную ошибку, второй — что данные вообще дошли. Тест требует
живой Revit.

## Урок

> Эвристика «отсутствие признака успеха = ошибка» инвертирована. Провал должен
> сигнализироваться **явно**; всё остальное — данные. Обратная логика превращает любой
> новый формат ответа в ложную ошибку.

Не добавляйте новых неявных сигналов ошибки в `format_response` — это была ровно
эта бага.

Дополнительно: функция чистая, без зависимостей, стострочная, полностью без тестов и
уже один раз выстрелила. Это лучший кандидат на юнит-тест во всём репозитории — см.
[[Текущие приоритеты]].
