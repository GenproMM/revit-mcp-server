# Фаза 2 адресует процесс на вызов и разделяет чтение с мутацией документа

Интерактивное обсуждение заменило противоречащие решения старого `--auto` контекста. Канонический контракт — `.planning/phases/02-live-identity-ambiguity-refusal-and-multi-document-addressin/02-CONTEXT.md` (2026-10-14), варианты — соседний `02-DISCUSSION-LOG.md`.

- У всех одна запись `revit`: доступные процессы показываются со своими портами и идентичностью, точный процесс выбирается **в каждом вызове**. Если процесс один, селектор можно опустить; при нескольких — отказ со списком. После рестарта выбор нужно повторить. Замок очереди — на целевой процесс; только GET `/status/` не ждёт очередь. Это продолжение [[Под замок все маршруты кроме status, одна общая запись сервера без копий]].
- Несколько документов без селектора в мутирующем вызове → отказ со списком. Явно выбранный неактивный документ → HTTP 412, без автоматической активации; переключение — отдельное действие.
- Читать неактивный документ без смены активного UI можно лишь маршрутом, безопасность которого доказана. Минимальный сценарий сравнения — сводка и список уровней для двух документов. Недоказанные адресные чтения явно отказывают; если минимальные два чтения не удаётся безопасно реализовать, исследование должно остановиться на решении пользователя, не менять условие приёмки молча.
- Два слушателя одного порта → отказ до отправки с PID обоих. Ответы должны содержать идентичность процесса и фактически затронутого документа, а не только адрес выбранного клиента.
- Подключение секрета и контроля целостности остаётся в фазе 5; исправление межсессионной подмены ответов pyRevit — backlog 999.1. Не считать замок одного процесса MCP глобальной гарантией.

Исследования и планов фазы 2 на момент записи нет. Детали селектора, безопасной активации и механизма pyRevit требуют исследования и живой проверки после полного перезапуска Revit, не Reload.
