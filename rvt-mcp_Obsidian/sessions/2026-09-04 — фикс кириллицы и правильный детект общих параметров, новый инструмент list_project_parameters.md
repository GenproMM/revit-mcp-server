# 2026-09-04 — фикс кириллицы и правильный детект общих параметров, новый инструмент list_project_parameters

Продолжение той же ветки (`feature/local-revit-mcp-tools`) и того же дня, но новый
Claude Code разговор — без памяти о предыдущих трёх сессиях этого vault. Отправная
точка: пользователь спросил, какой вид сейчас открыт в Revit.

## Что сделано

**1. Обнаружил кириллицу-в-`?` заново, независимо.** Живой ответ `/current_view_info/`
вернул `"???? 1-?? ?????"`. Не зная о предыдущей сессии и её решении «не трогать код»,
дошёл до той же причины тем же путём — `sanitize_string()`/`normalize_string()` в
`revit_mcp/utils.py` рубят всё не-ASCII через `.encode('ascii', 'replace')`. Подтвердил
независимо: pyRevit (`routes/server/handler.py`, локальная установка
`%APPDATA%\pyRevit-Master`) уже умеет безопасно эскейпить юникод в `\uXXXX` —
ASCII-фильтрация была лишней и вредной.

**2. На этот раз пользователь явно попросил исправить.** Правка внесена:
`sanitize_string()` сохраняет unicode как есть (гвардирует только `None`/тип),
`normalize_string()` переиспользует её вместо дублирования логики. Статус старой
заметки [[sanitize_string превращает кириллицу в вопросительные знаки]] обновлён —
раньше «причина найдена, не исправлено по прямому запрету», теперь исправлено и
проверено на живой модели.

**3. Повторно спровоцировал крах Revit нажатием pyRevit → Reload** после правки —
без знания о находке issue #3473 из прошлой сессии, просто по интуиции «примени
через Reload». Процесс исчез, порт перестал отвечать. Пользователь подтвердил:
«этот баг уже находили, он не решается» — попросил зафиксировать инструкцию для
пользователей. Это уже задокументировано в
[[pyRevit Reload при включённых Routes валит Revit на первом же запросе]] и теперь
дополнительно закреплено прямо в `CLAUDE.md` репозитория (раздел Known sharp edges) —
не только в vault, чтобы будущие сессии Claude Code видели предупреждение без доступа
к Obsidian.

**4. После полного перезапуска Revit — кириллица подтверждена рабочей.**
`view_name` = «План 1-го этажа», `view_family_type` = «ПЭ_Маркировочный» —
оба поля декодировались из `\uXXXX` корректно.

**5. Спросил про префиксы общих параметров — дал неверный ответ.** Через
`/execute_code/` проверил `isinstance(definition, DB.ExternalDefinition)` на
`doc.ParameterBindings` и получил `shared_count = 0` из 315 параметров, включая все
`ADSK_*`. Доложил пользователю, что «общих параметров в проекте нет вообще».

**6. Пользователь поправил: `ADSK_` — точно общие параметры.** Объяснение от
пользователя: при загрузке в проект общий параметр получает `InternalDefinition`,
поэтому тест на `ExternalDefinition` в `BindingMap` в принципе не может сработать —
это не свойство модели, а системная особенность API. Попросил найти правильный
способ через Perplexity MCP.

**7. Нашёл и проверил правильный метод.** `Perplexity search` указал на
`InternalDefinition.GetTypeId()` — строка `ForgeTypeId` кодирует происхождение:
`revit.local.shared:<guid>-<версия>` против `revit.local.project:<guid>-<версия>`.
Перепроверил на живой модели два независимых способа (ForgeTypeId-префикс и
перекрёстная сверка через `FilteredElementCollector(doc).OfClass(SharedParameterElement)`
по имени) — оба совпали на всех 315/315 биндингов. Реальный результат:
**309 общих, 6 обычных**; доминирующие префиксы общих — `CPI_` (193) и `ADSK_` (84).
Подробности и код: [[Общие параметры определяются по префиксу ForgeTypeId, а не по типу Definition]].

**8. Построил инструмент из этого разбора.** Раньше в репозитории вообще не было
маршрута/инструмента для параметров проекта — только `execute_code`. Добавил
`GET /project_parameters/` в `revit_mcp/parameters.py` и `list_project_parameters` в
`tools/parameter_tools.py` (фильтры `shared_only`, `prefix`, `search`,
`summary_only`). Заодно нашёл и исправил **второй, независимый** ASCII-фильтр —
собственную посимвольную копию в том же `parameters.py` (`_safe_str`), которую
прошлый grep по `encode('ascii')` не поймал, потому что она написана иначе. Это
означает, что `get_element_properties` тоже был сломан на кириллице до этой правки —
шире, чем показала первая находка.

## Как проверял без перезапуска Revit

Роут ещё не зарегистрирован в работающем процессе (нужен полный рестарт — junction
подхватывается им же, не раньше). Вместо `execute_code` со скопированной вручную
логикой — прочитал **реальный текст файла** `revit_mcp/parameters.py`, убрал `\r\n`
(IronPython 2.7 `exec` падает на CRLF в исходнике), выполнил в изолированном
пространстве имён с фейковым объектом `api`, перехватившим зарегистрированный
хендлер, и вызвал его напрямую на `doc`. Это подтверждает код маршрута, а не
копию его логики — риск «протестировал одно, закоммитил другое» исключён. Приём
записан в `CLAUDE.md` как повторно используемый.

## Обновлено в самом репозитории (не только в vault)

- `revit_mcp/utils.py` — `sanitize_string`/`normalize_string` не режут не-ASCII.
- `revit_mcp/parameters.py` — тот же фикс во второй, независимой копии (`_safe_str`);
  новый маршрут `/project_parameters/` и хелперы классификации.
- `tools/parameter_tools.py` — новый инструмент `list_project_parameters`.
- `CLAUDE.md` — снята устаревшая формулировка «pipeline is ASCII-only»; добавлено
  правило про `ForgeTypeId` вместо `ExternalDefinition`; добавлено предупреждение
  про Reload-крах и приём отладки маршрутов через `/execute_code/` без рестарта.
- `README.md` — новый инструмент в каталоге; попутно исправлены два расхождения
  счётчиков секций (Modify 8→9, Document 3→2), которые были там ещё до этой сессии.
- Изменения **не закоммичены** — только рабочее дерево.

## Открытые вопросы / следующие шаги

- Живой HTTP-вызов `GET /project_parameters/` ещё не выполнялся — логика роута
  проверена через прямой вызов хендлера, но полный перезапуск Revit для реальной
  регистрации маршрута ещё предстоит. Стоит подтвердить одним curl-запросом при
  следующей возможности.
- Вопрос из инбокса «отдавать ли фикс кодировки в апстрим» отчасти устарел — фикс
  уже применён локально в этой сессии, вопрос сузился до «выносить ли это отдельным
  PR апстриму Demolinator».
- `revit_mcp/parameters.py` вырос с 319 до 533 строк за одну правку — второй по
  скорости роста файл после `colors.py` в этом проекте; переоценить, не пора ли
  выносить классификацию параметров в отдельный модуль, если туда добавится ещё
  функциональность (например, редактирование биндингов).
