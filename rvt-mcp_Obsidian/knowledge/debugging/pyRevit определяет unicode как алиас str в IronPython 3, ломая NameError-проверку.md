# pyRevit определяет unicode как алиас str в IronPython 3, ломая NameError-проверку

**Статус:** исправлено · найдено при первом реальном тестовом прогоне семи
пользовательских сценариев (открытие/детач, чтение и запись параметров,
создание видов и элементов, перемещение, редактирование семейств) на живом
Revit 2024 с реальной 98 МБ моделью — не пилотной станцией, а локальной
машиной без доступа к серверам компании

## Симптом

**Каждый** POST-маршрут отвечал `500 Server error (TypeError): the JSON
object must be str, not 'bytes'` — включая уже существующий `/execute_code/`.
Ошибка возникала даже там, где main.py уже объявляет `Content-Type: text/plain`
именно для обхода известного бага pyRevit-парсинга (см. «Связанное» ниже) — то
есть один обходной путь уже стоял, но за ним обнаружился второй, независимый
баг того же корня. После text/plain ошибка сменилась на
`'bytes' object has no attribute 'get'` — то есть
`parse_request_data()` возвращал `bytes` нетронутым вместо `dict`.

## Причина

`revit_mcp/textutils.py` определял рантайм так:

```python
try:
    _TEXT_TYPE = unicode  # noqa: F821 - defined only on Python 2
    _BYTES_TYPE = str
except NameError:
    _TEXT_TYPE = str
    _BYTES_TYPE = bytes
```

Логика опирается на то, что `unicode` не существует на Python 3 и `try`
провалится в `except NameError`. **Это не так внутри движка pyRevit**:
диагностический пробник, запущенный прямо в работающем Revit через
`/execute_code/`, показал —

```
has_unicode=False bytes_is_str=False sample_type=bytes
isinstance(bytes,str)=False ver=3.4.2
```

— то есть у самого движка IronPython 3.4.2 `unicode` действительно
отсутствует. Но диагностический маршрут `/echo_request/` (временный, только
для отладки, удалён из финального кода) внутри реального pyRevit-контекста
показал другое:

```
module_BYTES_TYPE=str   module_TEXT_TYPE=str   is_bytes=True   bytes_is_str=False
```

pyRevit **сам инжектирует `unicode` в builtins своего IronPython 3 движка**
как алиас `str` (вероятно ради совместимости расширений, писавшихся под
IronPython 2.7 — тех же расширений, которые сам проект переносит на движок 3,
см. [[Целевой рантайм Revit-половины — IronPython 3, не 2.7]]). Поэтому
`try: unicode` внутри `textutils.py` **не бросает NameError** — переменная
существует, просто это не настоящий Python-2-`unicode`, а `str`. Оба алиаса
схлопывались на `str`, ни один настоящий `bytes` не подходил под
`_BYTES_TYPE`, и тело каждого POST-запроса проходило сквозь
`parse_request_data()` непреобразованным.

Тесты не поймали это по той же причине, что и предыдущий баг с `unicode`
внутри широкого `except` (см. [[unicode внутри широкого except молча
обнулял значения параметров]]): CPython, на котором крутится
`tests/unit/`, действительно не знает `unicode`, зонд идёт по правильной
ветке, и весь набор из 293 тестов оставался зелёным, пока реальный движок
отвечал 500 на каждый POST.

## Диагностика

Ключевой шаг — не гадать, а спросить рантайм напрямую. Временный маршрут
`/echo_request/` вернул тип, repr и результат `isinstance` прямо из тела
живого запроса, включая содержимое `textutils._BYTES_TYPE`/`_TEXT_TYPE` —
этого хватило, чтобы за один вызов увидеть, что предположение «unicode
отсутствует ⇒ Python 3» неверно именно в этом хосте. Отдельный
PowerShell-хостинг сборок `IronPython.dll`/`Microsoft.Scripting.dll` напрямую
(`[IronPython.Hosting.Python]::CreateEngine()`) показал версию без
pyRevit-инъекций — своё, «чистое» поведение движка, отличное от того, что
видит расширение внутри Revit. Расхождение между двумя пробами и есть находка.

## Исправление

```python
if bytes is str:  # IronPython 2.7 / Python 2 — истинно только там
    _TEXT_TYPE = unicode  # noqa: F821
    _BYTES_TYPE = str
else:  # IronPython 3 / CPython 3
    _TEXT_TYPE = str
    _BYTES_TYPE = bytes
```

`bytes is str` — единственная проверка типовой идентичности, которая не
зависит от того, что ещё инжектировал хост в builtins. `scripts/conventions.py`
теперь принимает обе формы охраны (`except NameError` и `if bytes is str:`),
предпочитая вторую — добавлена функция
`_guarded_by_python2_runtime_test()`, симметричная существующей
`_guarded_by()`. Регрессия закреплена тестом, который переоткрывает модуль
после временной инъекции `builtins.unicode = str` — воспроизводя ровно то,
что делает pyRevit, без необходимости живого Revit
(`test_parses_a_bytes_body_when_unicode_is_defined`).

## Урок

> Проверка рантайма по отсутствию имени хрупка вдвойне: она ломается не
> только если хост добавляет то, чего раньше не было (как здесь), но и
> предполагает, что единственный вменяемый источник имени — это сам язык.
> `bytes is str` спрашивает про **тождество типов**, а не про то, что лежит
> в `builtins` — поэтому его не может обмануть ничей инжект.

Второй урок практический: если баг подозрительно похож на то, что «уже
чинили» ([[unicode внутри широкого except молча обнулял значения
параметров]]), не значит, что это тот же баг — здесь механизм другой
(ложноположительный NameError-пробник, а не широкий `except`), хотя оба
коренятся в одном и том же имени `unicode` и одном и том же движке.
