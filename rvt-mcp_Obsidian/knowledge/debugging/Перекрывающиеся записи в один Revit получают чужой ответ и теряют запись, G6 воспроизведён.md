# Перекрывающиеся записи в один Revit получают чужой ответ и теряют запись, G6 воспроизведён

**Симптом.** В живом G6 две записи параметра и одно чтение шли одновременно через три процесса сервера к одному Revit (PID 8308). Все три вызова получили один и тот же текст: «Set Комментарии from '' to 'g6-ovb' on element 286693». Запись `a` (элемент 286692) ответила «успехом» чужим текстом и **потерялась**: readback показал `old=''`. Чтение вернуло этот текст вместо списка документов.

**Причина.** Не «ответил другой процесс»: PID, порт и токен сессии одинаковы во всех ответах. Это известная подмена ответов при пересечении запросов внутри pyRevit ([[Пересекающиеся запросы pyRevit получают чужой ответ, а их код не выполняется]]); замок моста действует только внутри одного процесса сервера, а здесь их было три. Фикс — на стороне Revit, backlog 999.1.

**Что это значит.** Последовательные записи корректны (`old` равен предыдущему `new`). Классификатор ставит G6 в `stop` (`g6-listing-unusable`), потому что перекрывающееся чтение не вернуло список. AMBIG-04 остаётся открытым: [[Фаза 2 принята как есть с открытым риском AMBIG-04, override оформлен]].
