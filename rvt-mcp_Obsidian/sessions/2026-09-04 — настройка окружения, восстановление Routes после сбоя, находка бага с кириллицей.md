# 2026-09-04 — настройка окружения, восстановление Routes после сбоя, находка бага с кириллицей

Ветка `feature/local-revit-mcp-tools`, HEAD `77be6c4`. Задача пользователя: настроить
работающее соединение MCP-сервера с Revit («Demolinator» — по имени владельца форка
на GitHub, `github.com/Demolinator/revit-mcp-server`) на этой рабочей станции.

## Что сделано

**1. Диагностика исходного состояния.** Расширение pyRevit было установлено как
**полная копия** репозитория в `%APPDATA%\pyRevit\Extensions\revit-mcp-server.extension`,
а не как ссылка — правки в `revit_mcp/` не доходили до Revit без ручного
копирования. Routes был включён в конфиге, но не отвечал: TCP-порт слушался,
HTTP зависал без ответа.

**2. Заменил копию на junction.** Сверил содержимое копии с репозиторием (тот же
HEAD, файлы идентичны — терять было нечего), переименовал в `.bak`, создал
`New-Item -ItemType Junction` на сам репозиторий, проверил сквозную запись,
удалил бэкап. Теперь `revit_mcp/` и `startup.py` — те же файлы, что в git, без
дублирования.

**3. Починил невалидный JSON в конфиге Claude Desktop.** В блоке `"revit"` не была
закрыта фигурная скобка `"env": { "REVIT_HOST": "127.0.0.1"` — весь файл не
парсился. Исправил, добавил `REVIT_HOST=127.0.0.1` явно (localhost на этой машине
резолвится сначала в `::1`, а Routes слушает только IPv4).

**4. Спровоцировал и разобрал крах Revit.** Дважды: один раз посоветовав
пользователю pyRevit → Reload (стандартный шаг из README), второй раз тестовым
запросом к ещё не зарегистрированному маршруту сразу после reload. Оба раза Revit
падал молча, системный лог показал `InvalidOperationException` в
`ScriptConsole`/`MetroWindow` на фоновом потоке IronPython. Поиском (Perplexity)
нашёл точное совпадение — [issue #3473 в pyRevitLabs/pyRevit](https://github.com/pyrevitlabs/pyRevit/issues/3473):
Routes-сервер, пересозданный при Reload, падает на первом же запросе,
воспроизводимость 100%. Фикс — только полный перезапуск Revit, никогда не Reload
при включённых Routes. Подробности: [[pyRevit Reload при включённых Routes валит Revit на первом же запросе]].

**5. После чистого перезапуска — рабочая цепочка.** Проверил снизу вверх: процесс
жив → порт слушается → файловый runtime-лог pyRevit показывает
`Executing startup script for extension: revit-mcp-server` и
`Routes server is listening on http://127.0.0.1:48884` → `/revit_mcp/status/`
отвечает `200` → сквозной вызов `get_revit_status` через реальный слой
`tools/`/`main.py` тоже `200`. Соединение подтверждено на всех уровнях.

**6. Нашёл и объяснил баг с кириллицей.** Пользователь запросил площадь выделенного
элемента; `get_element_properties` вернул параметры, но все русские имена —
`?????`, невозможно опознать «Площадь». Обошёл через `execute_code` и
`BuiltInParameter.HOST_AREA_COMPUTED` — стена 22×8×0.2 м, площадь 176 м² без
вычета проёмов (в проекте `Проверка_ОТверстий` это стоит перепроверить отдельно).
Пользователь сообщил, что с оригинальным апстримным расширением такой проблемы
не было — сравнил историю git, нашёл регрессию в коммите `bb7cda2`
(`sanitize_string` кодирует всё в ASCII, апстрим отдаёт `.Name` как есть),
подтвердил экспериментом на живой модели через `execute_code` (сырое имя vs
«санитизированное» рядом). Правку не делал по прямому запрету пользователя —
«должно работать из коробки, без правок в репозитории». Подробности:
[[sanitize_string превращает кириллицу в вопросительные знаки]].

**7. Разобрал безобидное расхождение в `uv.lock`.** Пользователь увидел дифф 242
строки, спросил что это. Проверил построчно: только `revision 1→3`, добавление
поля `upload-time` у всех пакетов (формат-апгрейд от более новой версии uv) и
переименование самого проекта `simple-revit-mcp → mcp-server-for-revit` вслед за
`pyproject.toml` — реальных изменений зависимостей, версий или хешей нет.

## Текущее состояние окружения

- Junction активен: `revit-mcp-server.extension → C:\Users\Admin\source\repos\revit-mcp-server`.
- pyRevit видит расширение под именем `revit-mcp-python`, секция
  `[revit-mcp-python.extension] disabled = false`.
- Routes: `enabled = true`, `core_api = true`, `127.0.0.1:48884`.
- `[core]`: `debug = false`, `verbose = false`, `filelogging = true` — сознательно
  оставлено так, поднятие уровня логирования увеличивает риск повтора краха из
  п.4 (см. заметку о крахе).
- Claude Desktop: конфиг валиден, 6 MCP-серверов, `revit.env.REVIT_HOST = 127.0.0.1`.
  **Не проверено**, что пользователь перезапустил Claude Desktop после правки —
  до перезапуска старый (битый) конфиг ещё в памяти приложения.
- Repo untouched: `git status` на конец сессии — только `M uv.lock` (было так и до
  начала работы).

## Открытые вопросы / следующие шаги

- Кириллица в именах остаётся сломанной для всех штатных инструментов до правки
  `sanitize_string` — теперь это осознанный, а не случайный дефект. См.
  [[sanitize_string превращает кириллицу в вопросительные знаки]] и обновлённые
  [[Текущие приоритеты]].
- Стоит перепроверить пользователю, действительно ли отверстия в стене
  `id=279315` (проект `Проверка_ОТверстий`) должны были вычитаться из площади —
  `HOST_AREA_COMPUTED` = 176 м² в точности равна габаритам без вычетов.
- Правило «после Reload — не доверять» стоит вынести в README/CLAUDE.md проекта
  как явное предупреждение для будущих сессий — сейчас это знание только в vault.
