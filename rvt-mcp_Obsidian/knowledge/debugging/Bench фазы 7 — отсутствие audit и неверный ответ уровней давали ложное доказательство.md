# Bench фазы 7 — отсутствие audit и неверный ответ уровней давали ложное доказательство

## Симптом

Первоначальный bench проходил 23 unit-теста, но классификатор возвращал `ok` для синтетической записи без audit JSONL и для записи с правильным call_id, но посторонним инструментом/маршрутом. Отдельно fake transport закреплял неверное поле `count`, тогда как production `/list_levels/` возвращает `total_levels`.

## Причина

Проверки доверяли вставленным наблюдениям вместо корреляции с журналом; fake повторял предположение реализации, а не реальный контракт маршрута. Успешный unit suite не доказывал достоверность самого доказательства.

## Исправление

Коммит `c90464c`, файлы `tests/test_phase7_live_bench.py` и `tests/unit/test_phase7_live_bench.py`:

- Audit обязателен; каждый сценарий сопоставляется ровно одной записи по call_id, tool и route. Повторное использование ID между сценариями запрещено.
- Решение, approval и outcome читаются из audit, не из вставленного ответа. H4 требует одинаковых непустых args у разных вызовов; H5 — move и X=12.5 в args.
- Отсутствие уровня доказывается только HTTP 200 с валидными `levels` и `total_levels`, имена сравниваются точно.
- POST-attempt счётчик сохраняется через flush/fsync до передачи запроса transport; сбой чтения после POST оставляет STOP и ненулевой счётчик.
- Локальный policy store не меняет глобальное состояние policy; сетевые пути и Windows reparse points отвергаются до чтения. Системный proxy для loopback выключен.

## Проверка и пределы

46 focused tests; полный offline suite — 6923 passed, 3 skipped. Реальные Revit, Routes, Hermes, share и секрет не использовались. Это не подтверждает клиентский UI, эффекты в модели или IronPython-совместимость вживую; SAFE-20 остаётся открытым.
