# Целевой рантайм Revit-половины — IronPython 3, не 2.7

**Обновляет:** [[Revit-часть написана на IronPython 2.7 и не может делить код с MCP-частью]]
— то решение зафиксировано 2026-09-04 и было верным на тот момент. Парк
пользователя сменил движок pyRevit; этот файл фиксирует новый факт, а не
отменяет старую логику ограничений.

## Решение

`revit_mcp/` и `startup.py` пишутся на пересечении диалектов IronPython 2.7 и
IronPython 3 (языковой уровень Python 3.4), а не только на 2.7. Подтверждено
скриншотом настроек pyRevit пользователя: «Активный движок: IronPython 3
(342)». Явно проговорено пользователем в диалоге: «важно что PyRevit должен
работать на IronPython3».

## Обоснование

Первый пилот раскатки на реальной станции (`e.ermolenko`) обнаружил это не
через документацию, а через отказ: `pyrevit env` показал `Engine: IPY342`, и
22 из 23 доменов маршрутов отказались регистрироваться с `ImportError` —
расширение при этом рапортовало чистую загрузку, и `/status/` отвечал
`Route does not exist` от собственного сервера pyRevit, а не от нашего кода.

## Как это применяется

Писать под **пересечение** рантаймов, не мигрировать на чистый Python 3:

- f-строки и `async` остаются запрещены — IronPython 3.4 это язык уровня
  Python 3.4, f-строки появились в 3.6. `scripts/conventions.py` эту часть
  правила не менял.
- Импорт хелперов внутри пакета — **относительный**:
  `from .utils import ...`, не `from utils import ...`. Направление
  изменилось на противоположное тому, что требовало решение от 2026-09-04, —
  голый импорт соседа внутри пакета является неявным относительным импортом,
  который Python 3 убрал.
- Модули, которых нет в Python 3 (`StringIO`, `urllib2`, …) и члены, которые
  переехали (`urllib.unquote` → `urllib.parse.unquote`), оборачиваются
  `try: <py3-форма> / except ImportError: <py2-форма>`.
- Встроенные имена Python 2 (`unicode`, `basestring`, `xrange`, `long`) —
  только через уже существующий алиас в `revit_mcp/textutils.py`
  (`_TEXT_TYPE`), никогда не бare-ссылкой. См.
  [[unicode внутри широкого except молча обнулял значения параметров]].

`scripts/conventions.py` теперь проверяет обе стороны конвенции на AST:
`check_ironpython_dialect` ловит голый импорт локального модуля, py2-only
модуль/имя без охраны, и разрешает охрану только когда обработчик исключения
называет его явно (`except ImportError` / `except NameError`), а не любой
`except Exception`. Проверено тестами в обе стороны — четыре реальных
поломки ловятся, четыре правильные формы остаются чистыми
(`tests/unit/test_conventions.py`).

## Цена решения

Написание на пересечении двух диалектов сложнее, чем писать под один. Плюс:
любая новая станция парка с ещё не мигрированным движком (IPY 2.7) тоже
должна продолжать работать — это и есть смысл «пересечения», а не просто
«теперь целимся в IPY3». Не проверено эмпирически, что весь код одинаково
работает на обоих движках одновременно — проверка шла на живой IPY3-станции;
за IPY2.7-станцию отвечает исходное решение от 2026-09-04.
