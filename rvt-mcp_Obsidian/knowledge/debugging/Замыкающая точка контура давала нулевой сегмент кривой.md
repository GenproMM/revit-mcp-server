# Замыкающая точка контура давала нулевой сегмент кривой

**Статус:** исправлено · коммит `67644ee`

## Симптом

`create_surface_based_element` падал с ошибкой Revit «Curve length is too small», если
в массиве точек контура была явно указана замыкающая точка.

## Причина

Обработчик строил замкнутый контур, соединяя точки по кругу — последнюю с первой. Если
вызывающий уже указал замыкающую точку (то есть последняя точка равна первой), то
итоговое соединение получалось «из точки в саму себя» — сегмент нулевой длины, который
Revit отвергает.

То есть два разумных соглашения о формате входа столкнулись:

- «контур задаётся уникальными вершинами, замыкание неявное»
- «контур задаётся полным списком точек, включая замыкающую»

Обработчик молча предполагал первое.

## Исправление

Массивы точек с явной замыкающей точкой больше не порождают нулевой сегмент — он
детектируется и пропускается. Оба формата входа теперь допустимы.

## Урок

> Если формат входа допускает два разумных прочтения, поддержите оба, а не то, которое
> кажется правильным. Особенно когда вызывающий — языковая модель: она выберет то,
> которое естественнее для человека, а не то, которое подразумевал автор.

Практическое следствие: для любого маршрута, принимающего массив точек/контур, стоит
явно решить и задокументировать поведение при дубликате первой и последней точки. То же
касается коллинеарных точек и точек, совпадающих внутри массива.
