# Исполнители фазы 2 идут последовательно в основном дереве, коммиты по путям

## Решение

Планы фазы 2 исполняются субагентами `gsd-executor` **по одному в основном рабочем дереве**, без worktree. Для этого в `.planning/config.json` (не отслеживается git) стоит `workflow.use_worktrees=false`. Каждый коммит — по явным путям (`git commit -m ... -- <пути>`), никогда `git add -A`. `STATE.md` и `ROADMAP.md` обновляются командами gsd-tools и остаются незакоммиченными.

## Почему

Дерево постоянно грязное работой других сессий (staged `ROADMAP.md`, файлы фазы 7, заметки хранилища, `graphify-out/`, `README.md`, `deploy/*`). Worktree форкается от HEAD и не видел бы незакоммиченный код 02-01, а обычный `git commit` захватил бы чужие staged-файлы. Хук диспетчеризации иначе требует `isolation="worktree"`.

## Следствия

- Волна с несколькими планами выполняется последовательно, хотя файлы планов не пересекаются.
- Исполнители обязаны перед стартом проверить `git status` на чужие правки и остановиться при их обнаружении; двойной вызов `state.advance-plan` недопустим.
- Вернуть worktree: `node ~/.claude/gsd-core/bin/gsd-tools.cjs query config-set workflow.use_worktrees true`, когда дерево станет чистым.
- Живые стенды (02-02, 02-07, 02-18) — blocking-human: инженер сам перезапускает Revit и вводит команды наблюдения; классификатор никогда не даёт разрешения.
