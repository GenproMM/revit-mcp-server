## Interface from 04-01 (import from `.utils`; do not edit utils.py or textutils.py here)

`commit_and_report(t, swallower)`, `finalize_outcome(commit_result, data, requested, succeeded,
failed)` returning `(payload, http)`, `exception_outcome(t, requested, succeeded, failed)`. Item
convention: colour routes use the element id in both lists; requested = number of elements the
override loop attempts.

## Execution rules for every task in this plan

- IronPython 3.4-level syntax; relative sibling imports; no cross-domain imports. Keep the `with
  DB.Transaction(...) as t:` form; call `commit_and_report(t, swallower)` inside the block.
- `color_elements_by_parameter` and `clear_element_colors` change their return value from a dict to
  a `(payload, http_status)` pair on every path (validation and exception paths return their existing
  dict with 200); the two route wrappers unpack it and pass `status=http_status` to
  `routes.make_response`. Nothing else in the repository calls these functions (verify with a grep of
  `revit_mcp/` and `tools/` before changing the signature).
- Tests: never weaken an existing assertion; the colour 200-error and refusal tests stay as they are.
- Commit protocol: `uv run pytest tests/unit -q` green before every commit; explicit pathspec commits
  only (`git commit -m "<message>" -- <paths>`), never `git add -A`/`.`; the user's staged files stay
  staged. Prefix `feat(04-07):` / `test(04-07):`; end with your session's attribution line.
