# Разработка инструментов Revit MCP

## 1. Назначение

Добавить новый инструмент в MCP-сервер Revit или изменить существующий так,
чтобы он попал на рабочие станции через штатную раскатку. Скилл закрывает
регламент: что генерировать, что проверять, чем подтверждать готовность.
Алгоритм самого инструмента остаётся решением разработчика.

Репозиторий — `GenproMM/revit-mcp-server`. Полные правила лежат в нём:
`AGENTS.md` (коротко, для ИИ), `CONTRIBUTING.md` (подробно).

## 2. Когда применять и когда нет

**Применять**, когда нужно: новый инструмент, новый маршрут, правка поведения
существующего инструмента, или разбор «почему инструмент не появился у клиента».

**Не применять**, когда: нужно просто *вызвать* существующий инструмент Revit
(это обычная работа с моделью); нужно изменить правило аудита моделей (правила
живут в конфигурации скилла аудита, релиз сервера не нужен); нужна раскатка на
парк станций (это `deploy/`, отдельная ответственность).

**Не применять `execute_revit_code` как способ решить задачу.** Это аварийный
люк для разведки. Рабочее решение — типизированный маршрут.

## 3. Входные данные и грабли

Нужно до начала работы:

- **Читает или изменяет модель.** Определяет всё: читающий маршрут не
  открывает транзакцию.
- Категории Revit и параметры, с которыми работаем.
- Что возвращается и в каких единицах.

Грабли, каждая из которых уже стоила рабочего дня:

- **Два рантайма.** `revit_mcp/` — IronPython 2.7: только `"{}".format(x)`,
  никаких f-строк. f-строка = `SyntaxError` при загрузке: домен не
  зарегистрируется, инструмент не появится, в логах ничего внятного.
  `tools/` — CPython 3.11+, там можно всё.
- **Кнопки Reload в pyRevit недостаточно.** Она валит процесс Revit на первом
  же запросе. Только полное закрытие и открытие Revit.
- **`suppress_warnings(t)` строкой после `t.Start()`.** Без него штатное
  предупреждение Revit открывает модальное окно и вешает сервер навсегда.
- **`DB.ElementId(<int>)` падает на Revit 2027.** Только
  `make_element_id()` / `get_element_id_value()`.
- **Размеры наружу — миллиметры.** Внутри Revit футы, конвертация в маршруте.
- **Кириллица.** Имена из Revit — через `get_element_name()`.

## 4. Эталон

Докстринг `check_clashes` в `tools/clash_tools.py`. Он задаёт структуру:
назначение с примером из предметной области → правила области для каждой
комбинации входа → форматы значений с конкретными примерами → форма возврата с
единицами → ограничения прямым текстом → блок `Args:` со всеми параметрами,
включая `ctx`.

Докстринг — это **контракт для модели**, единственное, что она видит перед
вызовом. Не «что делает функция», а «когда вызывать, с чем, и что придёт».

## 5. Процедура

1. **Проверить, что этого ещё нет.** Прочитать `tests/unit/tool_manifest.txt`.
   Часто нужное — параметр существующего инструмента, а не новый инструмент:
   лишний инструмент ухудшает выбор моделью для всех остальных.
2. **Сгенерировать каркас.** Вручную файлы не создавать.
   ```
   uv run python scripts/new_tool.py <domain> <tool_name>        # с записью
   uv run python scripts/new_tool.py <domain> <tool_name> --get  # чтение
   ```
   Регистрировать ничего не нужно — обход пакета находит модули сам.
3. **Заполнить TODO.** Алгоритм маршрута и докстринг инструмента.
4. **Прогнать тесты.** `uv run pytest tests/unit`. Упало — нарушено правило,
   править код, а не тест.
5. **Проверить на живой модели.** Полностью перезапустить Revit →
   `http://localhost:48884/revit_mcp/status/?verbose=true` (домен в списке,
   `health: healthy`) → `mcp dev main.py` и вызвать инструмент.
6. **Коммит.** Ветка `feature/<тема>`, тело в форме симптом → причина →
   исправление.

## 6. Выходные данные

- `revit_mcp/<domain>.py` — маршрут.
- `tools/<domain>_tools.py` — инструмент с докстрингом-контрактом.
- Строка в `tests/unit/tool_manifest.txt`.
- Зелёный `pytest tests/unit`.
- Подтверждение с живого Revit: домен в `/status/`, вызов через `mcp dev`.

Раскатку выполняет владелец `deploy/`: `publish-extension.cmd` для
Revit-половины, `build-payload.cmd` для CPython-половины.

## 7. Запреты

- Не создавать файлы в `revit_mcp/` и `tools/` вручную.
- Не править `format_response` в `tools/utils.py`. Дикт без `status` — это
  данные, а не ошибка.
- Не отключать и не ослаблять тесты, чтобы «прошло».
- Не трогать `deploy/`, отключение `GenproMCP`, имя `routes.API("revit_mcp")`
  и имя папки расширения — это контракты раскатки.
- Не возвращать `"status": "success"`, пропустив элементы: считать пропуски и
  отдавать их в ответе.
- Не сообщать о готовности по зелёным юнит-тестам. Они ничего не говорят о
  поведении внутри Revit.

## 8. Приёмка

Готово, если выполнено всё:

- `uv run pytest tests/unit` — зелёный.
- Revit полностью перезапущен, домен виден в `/status/?verbose=true`,
  `health: healthy`.
- Инструмент вызван через `mcp dev main.py` и вернул ожидаемое.
- Имя инструмента есть в `tests/unit/tool_manifest.txt`.
- Докстринг содержит ограничения и блок `Args:` со всеми параметрами.
- Если инструмент пишет в модель — проверено, что документ не остался с
  незакрытой транзакцией и Revit не показал модальное окно.
