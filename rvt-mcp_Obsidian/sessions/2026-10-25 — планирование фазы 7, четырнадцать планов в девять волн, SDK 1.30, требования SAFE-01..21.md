# Планирование фазы 7: четырнадцать планов в девять волн, SDK 1.30, требования SAFE-01..21

## Результаты

- `/gsd-plan-phase 7`. Контекст D-01…D-23 из обсуждения, формального исследования раньше не было (только `07-RESEARCH-NOTES.md`). Пользователь выбрал «Исследовать сначала».
- **Исследование** (`07-RESEARCH.md`, 1016 строк; HIGH для SDK, клиента Hermes, схемы разрешения и выкладки; MEDIUM для поведения Revit API и отрисовки окна в Hermes Desktop). Всё прототипировано в scratchpad, репозиторий и HermesFork не менялись, Revit не запускался, share не трогался.
  - Целевой SDK — `mcp` 1.30.0: elicitation есть с 1.10. Полный unit-suite на 1.30.0 зелёный при `structured_output=False`, иначе у всех 59 инструментов появляется `outputSchema` и 33 теста падают. Три транспорта, `user_request` в схемах, холодный старт в раскладке payload 1.03–1.08 с.
  - **Новый блокер:** с 1.11.0 `mcp` безусловно импортирует `pywin32`, а embeddable CPython payload игнорирует `.pth` — `import mcp` падает. См. [[mcp 1.11+ импортирует pywin32, а embeddable CPython payload его не находит]].
  - Hermes не рисует поля формы и отвечает `accept` с `content={}`; одинаковый текст окон в gateway склеивается, `/approve all` разрешает все ожидающие. Отсюда уникальный код в каждом окне и окна по одному на процесс.
  - Под `stateless_http=True` у HTTP-транспортов нет capability elicitation — confirm-операции там блокируются; путь Hermes — stdio.
  - Разрешение — HMAC по точному тексту тела, а не по пересериализованным аргументам: IronPython 3.4 печатает `repr(0.1)` как `0.10000000000000001`.
  - Реестр одноразовых разрешений — в памяти расширения, потребление внутри `gate_or_response`.
  - Единственный путь, добавляющий общие параметры, — `edit_family`; проверку по ФОП делать на CPython. Typed-инструментов переопределения параметров (D-23) нет.
  - Попутно: `edit_family` использует перегрузку `AddParameter` с `BuiltInParameterGroup`, удалённую в Revit 2025+ (вне фазы).
- **Решения пользователя после исследования** → D-24…D-27 в `07-CONTEXT.md`: SDK 1.30.0; `load_family` — confirm с предупреждением; памяти повторов нет; файл оператора рядом с секретом. См. [[Фаза 7 — SDK 1.30 вместо 2.x, load_family с предупреждением, без памяти повторов, файл оператора рядом с секретом]].
- **Требования** SAFE-01…SAFE-21 формализованы в `REQUIREMENTS.md` и ROADMAP (раньше было «TBD»); POLICY-01…04 помечены как заменённые.
- **Стратегия валидации** `07-VALIDATION.md` заполнена из раздела Validation Architecture.
- **Карта паттернов** `07-PATTERNS.md`: 27 файлов, аналог найден для всех; без аналога пять концепций (server-side elicitation, реестр nonce, hot reload TOML, shim pywin32, стенд elicitation).
- **Проба граничных случаев** (spec-less): 23 пункта, все `unresolved` — классификатор не понял русский текст требований; переданы планировщику как помеченные допущения.
- **Планы:** 14 планов в 9 волн. Планировщик упёрся в лимит сессии после 10 планов и был продолжен; дописал 07-11…07-14, иначе SAFE-08/17/18/20/21 и живой стенд остались бы без плана.
  - 07-01 — обновление SDK за чекпоинтом просмотра lock-файла (неавтономный).
  - 07-02 — трассер: `delete_elements` через окно и одноразовое разрешение, полная базовая политика.
  - 07-03 — shim `pywin32`, проверка payload, три транспорта.
  - 07-04 политика и hot reload; 07-05 протокол разрешений (TDD, 32 потока); 07-07 тестовая инфраструктура до включения проверки.
  - 07-06 тест-сторож классификации; 07-08 — чекпоинт решения D-18 и проверка разрешения в `gate_or_response` (неавтономный).
  - 07-09 канал подтверждения; 07-10 общий `revit_mcp/lookup.py` и один маршрут `/mutation_preflight/` (вместо трёх из исследования); 07-11 ФОП и окно на русском.
