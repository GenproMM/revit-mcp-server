# pyRevit Routes — единственная внешняя интеграция проекта

У проекта ровно **одна** внешняя граница: локальная неаутентифицированная HTTP-связь
с сервером pyRevit Routes. Ни облачных сервисов, ни СУБД, ни провайдеров
аутентификации, ни исходящего трафика в интернет.

## Что такое Routes

Микрофреймворк внутри pyRevit, поднимающий HTTP-API прямо в процессе Revit. Он даёт
то, чего нельзя получить снаружи, — **бэкенд с доступом к контексту Revit**. Каждый
обработчик получает живой документ аргументом.

## Параметры связи

| Что | Значение |
|---|---|
| Базовый URL | `http://{REVIT_HOST}:48884/revit_mcp` |
| Клиент | `httpx.AsyncClient`, один пуловый экземпляр |
| Лимиты пула | 10 keep-alive / 20 всего соединений |
| Хелперы вызова | `revit_get`, `revit_post`, `revit_image` в `main.py` |
| Аутентификация | **нет** — ни ключа, ни токена, ни TLS |
| Таймауты | 30 с обычные, 60 с для картинок |
| Форма трафика | 12 GET, 35 POST, 1 картинка |

Хелперы внедряются в каждый модуль инструментов через
`tools/__init__.py:register_tools` — см.
[[Транспорт внедряется в модули инструментов, а не импортируется]].

## Серверная сторона

Маршруты регистрируются на `routes.API("revit_mcp")` в `startup.py` — 22 вызова
`register_*_routes(api)`, покрывающих домены: status, model_info, views, placement,
colors, code_execution, building, editing, structure, annotation, analysis,
documentation, rooms, view_management, tags, transforms, mep, parameters, interop,
detail, clash, document.

Итого 48 эндпоинтов — см. [[48 MCP-инструментов зеркалят 48 маршрутов pyRevit]].

## Проверка живости

```
GET http://localhost:48884/revit_mcp/status/
```

```json
{"status": "active", "health": "healthy", "revit_available": true,
 "document_title": "...", "api_name": "revit_mcp"}
```

Это единственный маршрут, который вызывается с переопределённым таймаутом
(`tools/status_tools.py`) — остальные 47 живут на дефолтных 30 секундах.

## Риски интеграции

**Произвольное исполнение кода.** `POST /revit_mcp/execute_code/` — см. отдельную
заметку [[execute_code даёт неаутентифицированное исполнение кода внутри Revit]].

**Дедлок на модальном диалоге** — главная угроза живости. Необработанное
предупреждение Revit блокирует сервер Routes навсегда. Смягчается
`suppress_warnings` / `_FailureSwallower`, которые обязаны вызываться сразу после
`transaction.Start()`. См. [[Модальный диалог Revit вешал headless-сервер навсегда]] и
[[Каждая транзакция глушит модальные диалоги Revit]].

**Ни ретраев, ни circuit breaker** на клиенте httpx. Зависание на стороне Revit
проявляется как таймаут в 30 с (или 60 с для картинок), возвращённый строкой ошибки —
см. [[Ошибки не выбрасываются, а возвращаются строками]].

**Единый таймаут на все операции.** Clash-детект, полная сводка модели и экспорты
делят бюджет со статус-пингом. Нужны таймауты на уровне обёртки для известно медленных
эндпоинтов.

## Наблюдаемость

- **Revit-сторона:** stdlib `logging`, `logger = logging.getLogger(__name__)` в каждом
  модуле маршрутов, пишет в лог pyRevit.
- **MCP-сторона:** uvicorn-логирование при HTTP-транспортах; stdio-режим не пишет
  ничего. Ошибки инструментов уходят клиенту строками и **не логируются**.
- Ничего не связывает вызов MCP-инструмента с породившим его запросом Routes — нет
  корреляционного идентификатора. Диагностика зависшей операции через границу
  процессов сейчас невозможна.
