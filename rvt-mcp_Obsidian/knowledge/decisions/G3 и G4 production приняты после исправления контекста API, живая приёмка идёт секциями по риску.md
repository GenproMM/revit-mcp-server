# G3 и G4 production приняты после исправления контекста API, живая приёмка идёт секциями по риску

## Решение

Пользователь выбрал **observed** по записи `g34-production-3.json` (2026-10-22, после полного перезапуска Revit на исправленном коде):

- G3: чтение сводки и уровней неактивного документа в обе стороны, окно не переключалось, данные принадлежали запрошенному документу.
- G4: активация сохранённого документа (200 `activated`, подтверждена повторным чтением), отказы для несохранённого и отсоединённого (422, активный документ не изменился), диалогов не было.
- **MDOC-04 принят только в узком классе** «сохранён, не workshared, путь существует». Активация workshared остаётся отказом и не измерена; чтения неактивных документов шире сводки и уровней не поддерживаются.
- Более ранние записи с STOP (первый прогон с 500, второй с исключением) сохранены как улики и не заменяются.

## Живая приёмка 02-18 — секциями по риску

S0 (G1/G5, G3, G4 заново), S1 (G2: два документа с одинаковым названием, закрытие, замена), S2 (два процесса Revit под одной записью) — без разрешений, только чтение. Мутации, G5 (коллизия портов на вспомогательном порту 48991) и G6 (откат записи параметра) выполняются только по явному разрешению пользователя с его словами, на одноразовых копиях, без сохранения и синхронизации. Неразрешённая секция — not-run, итог фазы `stop`, при невыполненном G6 открыт AMBIG-04. Фаза принимается, только если наблюдаются все девять критериев ROADMAP; итоговый выбор accept/stop остаётся за пользователем, маркер `PHASE2_ACCEPTANCE_OBSERVED` не является одобрением.
