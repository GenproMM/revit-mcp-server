# Архитектура — это мост между двумя рантаймами Python

Весь проект — это одна идея: Revit API живёт только внутри процесса Revit на .NET,
а MCP-протокол хочется реализовать на современном Python. Поэтому репозиторий
содержит **два независимых кодовых дерева**, которые никогда не делят интерпретатор
и общаются исключительно по локальному HTTP.

```
ИИ-клиент (Claude Desktop / Code / Cursor)
    │  MCP: stdio | SSE (/sse) | streamable-http (/mcp)
    ▼
MCP-сервер, CPython 3.11+          ← main.py + tools/
    │  HTTP JSON, keep-alive AsyncClient
    │  http://localhost:48884/revit_mcp/...
    ▼
pyRevit Routes, IronPython 2.7     ← startup.py + revit_mcp/
    │  Revit API (DB, revit.doc, Transaction)
    ▼
Документ Autodesk Revit (.rvt)
```

## Кто за что отвечает

| Компонент | Ответственность | Файл |
|---|---|---|
| Бутстрап MCP | Создаёт `FastMCP`, читает конфиг, выбирает транспорт | `main.py` |
| HTTP-мост | `revit_get` / `revit_post` / `revit_image` на общем `httpx.AsyncClient` | `main.py` |
| Реестр инструментов | Импортирует и вызывает каждый `register_*_tools` | `tools/__init__.py` |
| Модули инструментов | Объявляют `@mcp.tool()`, собирают payload, зовут мост | `tools/*_tools.py` |
| Форматтер ответа | Нормализует словари и ошибки Routes в текст для MCP | `tools/utils.py` |
| Реестр маршрутов | Импортирует и вызывает каждый `register_*_routes` | `startup.py` |
| Модули маршрутов | `@api.route()`-обработчики, делающие реальную работу в Revit | `revit_mcp/*.py` |
| Хелперы Revit | ElementId, имена, глушение диалогов | `revit_mcp/utils.py` |

## Ключевые свойства

**Строгое зеркалирование.** На каждый `revit_mcp/X.py` есть `tools/X_tools.py`.
Имена домена совпадают почти всегда — исключения: `revit_mcp/rooms.py` ↔
`tools/room_tools.py`, а `tools/family_tools.py` ложится на `revit_mcp/placement.py`.

**Соглашение о регистрации.** С обеих сторон единственный публичный контракт модуля —
функция `register_*_routes` / `register_*_tools`. См. [[Паттерн регистратора маршрутов]] и
[[Паттерн регистратора инструментов с инъекцией транспорта]].

**Инъекция зависимостей.** HTTP-вызовы передаются в регистраторы инструментов
аргументами, а не импортируются. См.
[[Транспорт внедряется в модули инструментов, а не импортируется]].

**Все мутации — за транзакцией.** Изменять документ можно только внутри
`DB.Transaction` внутри обработчика маршрута. См.
[[Каждая транзакция глушит модальные диалоги Revit]].

**Полное отсутствие состояния.** Между вызовами ничего не кэшируется; единственный
изменяемый глобал на всём MCP-сервере — `_http_client` в `main.py`
([[Один keep-alive HTTP-клиент обслуживает все вызовы]]).

## Путь одного запроса

1. Клиент вызывает инструмент, FastMCP диспатчит в зарегистрированную корутину.
2. Инструмент собирает плоский `dict` и ждёт `revit_post("/clash_check/", data, ctx)`.
3. `_revit_call` отправляет запрос на пуловом клиенте.
4. pyRevit Routes находит подходящий обработчик в `revit_mcp/clash.py`.
5. Обработчик читает `doc`, гоняет коллекторы и транзакции, возвращает `routes.make_response(...)`.
6. `_revit_call` возвращает разобранный JSON либо строку `Error: <код> - <тело>`.
7. `format_response` рендерит данные или блок `=== ERROR DETAILS ===`.

## Ограничения, которые нельзя обойти

- **Два рантайма.** В `revit_mcp/` запрещены f-строки, `list[str]`, `async`, `pathlib`.
  См. [[Revit-часть написана на IronPython 2.7 и не может делить код с MCP-частью]].
- **Однопоточность.** MCP-сторона — один asyncio-цикл; Revit-сторона однопоточна на
  контексте Revit API. Параллелизм на уровне инструментов не даёт параллелизма в Revit.
- **Импорты.** Модули `revit_mcp/*.py` пишут `from utils import ...` (верхний уровень,
  не относительно), потому что pyRevit кладёт каталог модуля в `sys.path`. `tools/utils.py` —
  совершенно другой, не связанный файл.
- **Порт.** 48884 захардкожен, настраивается только хост.
- **Холодный старт.** ~0.9 с на `initialize` по stdio — это пол фреймворка.
