# Голый import соседа внутри revit_mcp сломал 22 из 23 доменов

**Статус:** исправлено, коммиты `0e07076`, `d75c24c` · найдено на первой
пилотной станции (`e.ermolenko`)

## Симптом

`/status/` отвечал не нашим кодом, а встроенным сервером pyRevit:
`RouteHandlerNotDefinedException: Route does not exist`. При этом расширение
формально загрузилось — `pyrevit env` показывало его в списке, `disabled` был
снят. Рантайм-лог pyRevit (`%APPDATA%\pyRevit\<год>\..._runtime.log`) внутри
`Found pyRevit assembly:` не содержал сборки `revit-mcp-server` вовсе, а чуть
ниже — прямая трассировка:

```
Failed to register route domain 'view_management'
  File "...\revit_mcp\utils.py", line 9, in <module>
Failed to register route domain 'views'
  File "...\revit_mcp\views.py", line 7, in <module>
Registered 1 route domains, 22 FAILED: analysis, annotation, ..., views
```

## Причина

Все 23 файла `revit_mcp/*.py` (кроме `textutils.py`) писали
`from utils import get_element_name, ...` — голым импортом соседа внутри
пакета. Под IronPython 2.7 это неявный относительный импорт: интерпретатор
ищет `utils.py` рядом. **Python 3 эту семантику убрал** — под ним такой
импорт ищет `utils` как отдельный установленный пакет, не находит и роняет
`ImportError`. Станция была подключена движком `IPY342` (IronPython 3), а не
2.7, на который был рассчитан весь код (см.
[[Целевой рантайм Revit-половины — IronPython 3, не 2.7]]).

Каскад: падает `revit_mcp/utils.py` при первом же импорте → падает всё, что
его импортирует, то есть 21 домен из 22 плюс сам `utils` как «домен» (он
таковым не является, но попытка импортировать его тоже проваливается) — итог
«1 зарегистрирован, 22 FAILED» ровно совпал с числом файлов, содержащих такой
импорт.

Отдельно всплыли ещё два py2-специфичных импорта той же природы, найденные
только после того, как первый слой был снят и следующий домен упал:
`code_execution.py` — `from StringIO import StringIO` (модуль убран в py3,
класс переехал в `io`), `views.py` — `from urllib import unquote`
(функция переехала в `urllib.parse`). Первые два узких grep-а на конкретные
запрещённые модули оба эти случая пропустили — они искали `urllib2`, а не
голый `urllib`.

## Обход / исправление

Все 23 строки переведены на явный относительный импорт:
`from .utils import ...`, `from .textutils import ...`. `StringIO` и
`unquote` обёрнуты `try: <py3-форма> / except ImportError: <py2-форма>`.

`scripts/conventions.py` — `check_ironpython_dialect` теперь проверяет
направление на AST (запрещает голый импорт локального модуля пакета) и
отдельно ловит py2-only модули/переехавшие имена без охраны. Оба правила
протестированы в обе стороны: четыре реальные поломки ловятся, четыре
исправленные формы остаются чистыми (`tests/unit/test_conventions.py`).

## Урок

> Три отдельных узких grep-а нашли три отдельных бага за один день, каждый —
> руками, после того как пилотная станция уже на нём споткнулась. Правило
> должно жить в чекере на AST, с исчерпывающим списком (py2-only модули +
> переехавшие имена), а не быть списком точечных находок, растущим по одной
> станции за раз.
