# Валидация продукта — сборка Empire State Building в живом Revit 2027

## Что было сделано

Полный стек прогнан end-to-end против живой установки **Revit 2027 + pyRevit 6.4.0** —
все ~45 маршрутов на реальной модели. В качестве задачи выбрана сборка массинга
**Empire State Building** высотой 443 м.

Формулировка из коммита `0081712`:

> «Validated live on Revit 2027 by building a full Empire State Building.»

## Почему это лучшая проверка, чем тесты

Половина багов, найденных так, **невозможно** обнаружить юнит-тестом или проверкой на
модели из двух стен:

| Баг | Почему нашёлся только на реальной задаче |
|---|---|
| [[place_family трактовал миллиметры как футы и уносил семейство на 2.4 км]] | При `x=0` бага не видна; нужны координаты порядка тысяч мм |
| [[Балки садились на Z=0 вместо отметки уровня]] | На первом этаже незаметно; на 80-м очевидно |
| [[Окна и двери без хоста прилипали к началу координат]] | Нужны реальные окна в реальных стенах |
| [[Модальный диалог Revit вешал headless-сервер навсегда]] | Нужно рутинное предупреждение Revit, а оно возникает от реальной геометрии |
| [[get_view возвращал 404 на именах видов с пробелами]] | Нужны виды с дефолтными именами вроде «Level 1» |
| [[create_surface по умолчанию попадал на Foundation Slab вместо перекрытия]] | Нужен обычный шаблон проекта, а не пустой документ |

То есть эта сессия дала больше, чем весь существующий тестовый набор
([[Тесты — это самостоятельные скрипты, а не pytest-сьют]]).

## Что она же выявила как отсутствующее

Задача упиралась в дыры в возможностях, и они были закрыты новыми инструментами:

- **Нечего сохранять.** Модель терялась при перезапуске Revit → появился
  `save_document` ([[Save и SaveAs выполняются вне транзакции]]). Проверен сохранением
  443-метровой модели на диск.
- **Нечего ставить.** Библиотека семейств была почти пустой — ни мебели, ни дверей →
  появился `load_family`.
- **Нечего импортировать.** Для достоверной геометрии не хватало 3D-телесных форматов →
  `link_file` расширен до SAT / SKP / 3DM
  ([[link_file передавал None вместо out-параметра и терял импортированный элемент]]).
- **Нечем координировать.** → появился флагманский `check_clashes`, проверенный на
  реальном случае «балка против воздуховода»
  ([[Медленный фильтр Revit всегда идёт в паре с быстрым]]).

## Метод, который стоит повторять

Паттерн полезен как таковой:

1. Выбрать **осмысленную, узнаваемую задачу целиком**, а не набор изолированных
   проверок.
2. Довести её до конца, фиксируя каждое препятствие.
3. Каждое препятствие превратить либо в исправление бага, либо в новый инструмент.
4. Записать в тело коммита **симптом → причину → исправление** — именно поэтому вся
   папка отладочных заметок восстановима из истории git.

Заодно это честная проверка ценностного предложения: если ассистент не может собрать
узнаваемое здание, заявление «автоматизирует Revit» не подтверждено.

## Ограничение метода

Ручной, невоспроизводимый, зависит от наличия Revit и человека. Он **не заменяет**
автоматических тестов — он находит другой класс проблем. Прогоняемый тестовый уровень
без Revit остаётся приоритетом номер один
([[Текущие приоритеты]]).
