# execute_code даёт неаутентифицированное исполнение кода внутри Revit

Самый мощный и самый опасный маршрут проекта. Это стоит понимать явно, а не
обнаруживать случайно.

## Что именно происходит

`POST /revit_mcp/execute_code/` принимает строку с IronPython и делает `exec` в
пространстве имён, куда предзаложены:

```python
namespace = {
    "doc": doc,                    # живой документ Revit
    "DB": DB,                      # весь Revit API
    "revit": revit,                # хелперы pyRevit
    "clr": _clr,                   # CLR-интероп
    "System": _System,             # вся .NET-библиотека
    "__builtins__": __builtins__,  # нетронутые builtins
    "print": lambda *args: ...,    # перехват вывода в StringIO
}
```

Всё это оборачивается в `DB.Transaction` с `suppress_warnings`, и вывод `print`
перехватывается в `StringIO` для возврата клиенту.

С нетронутыми `__builtins__` доступны `open`, `__import__`, `os`, `subprocess` — то
есть это исполнение произвольного кода на машине **с правами пользователя Revit**, а
не только манипуляция моделью.

## Что защищает

Ничего, кроме сетевой достижимости.

- Ни аутентификации, ни токена, ни allowlist.
- MCP-клиент по умолчанию ходит на `localhost` (`main.py`), но это **дефолт клиента**,
  а не ограничение бинда на сервере.
- `REVIT_HOST` переопределяется переменной окружения на любой хост. Указав его на
  чужую машину, вы отправите изменяющие модель запросы и произвольный код по сети в
  открытом виде.
- Любой локальный процесс на машине может обратиться к `:48884` напрямую, минуя
  MCP-сервер целиком.

## Почему он вообще существует

Это аварийный люк: когда типизированного инструмента для задачи нет, ИИ-ассистент
может дописать нужное на IronPython прямо в рантайме. Практически это очень удобно и
именно поэтому опасно — см.
[[execute_code остаётся аварийным люком для отсутствующих инструментов]].

## Рекомендации

1. Убедиться, что сервер Routes действительно биндится на петлю, и при возможности —
   форсировать это.
2. Ввести env-флаг `REVIT_MCP_ALLOW_EXEC`, по умолчанию выключенный: маршрут должен
   быть opt-in на этапе загрузки расширения.
3. Требовать заголовок с общим секретом на `/execute_code/`.
4. Постепенно поднимать часто исполняемые сниппеты в типизированные маршруты, снижая
   давление на этот путь.

## Смежная проблема — traceback наружу

Несколько маршрутов (в том числе этот и `clash_check`) возвращают
`traceback.format_exc()` прямо в ответе, раскрывая абсолютные пути файловой системы и
версии библиотек. Traceback нужно логировать, а клиенту отдавать короткое сообщение и
корреляционный идентификатор.

## Ещё одна проблема того же файла

Восстановление `sys.stdout` не защищено `finally` — см.
[[sys.stdout может остаться закрытым StringIO до конца сессии Revit]].
