# pyRevit хранит disabled=true по имени папки расширения

**Статус:** исправлено, коммит `5fcd8fe` · найдено на первой пилотной станции
после того, как загадка «Route does not exist» свелась к «расширение вообще
не собиралось»

## Симптом

`install.cmd` отработал все шесть шагов без ошибок, `payload` встал, версия
корректная. Но рантайм-лог pyRevit при старте Revit собирал сборки для
`pyRevitCore`, `pyRevitTools`, `MM_LAB` — и ни разу не упоминал
`revit-mcp-server`. В `pyRevit_config.ini`:

```ini
[revit-mcp-server.extension]
disabled = true
private_repo = true
```

## Причина

pyRevit читает `default_enabled` из `extension.json` **только при первом
знакомстве** с расширением, а секцию в конфиге ключует **именем папки**
(`revit-mcp-server.extension`), которое не менялось никогда. Станция раньше
видела более старую сборку этого же расширения с
`default_enabled: "False"` / `builtin: "True"` (или GenproMCP-эпоху) — pyRevit
один раз записал `disabled = true`, и текущий `extension.json` (уже
`"True"`/`"False"`, как положено) на это никак не влияет: секция для pyRevit
уже существует, второй раз `default_enabled` не читается.

`publish-extension.cmd` защищает только свою половину — то, что публикуется
на шару. Снять уже записанный на станции флаг было некому: `install.cmd`
регистрировал путь поиска расширения, но не трогал состояние
enabled/disabled.

## Обход / исправление

`install.cmd`, шаг `[2/6]`, сразу после `extensions paths add`:

```bat
"!PYREVIT!" extensions enable revit-mcp-server >nul 2>&1
```

Дёшево и идемпотентно — на чистой станции просто ничего не делает, на
станции с этим наследием снимает флаг. `private_repo = true` не трогали:
он появился от прежнего `builtin: "True"`, на загрузку не влияет, и решать
его отдельно, если pyRevit начнёт лезть за обновлениями по приватному пути.

## Урок

> «Установка прошла успешно» и «расширение сейчас грузится» — разные
> утверждения, и между ними стоит однажды записанный флаг, переживающий любое
> число новых версий `extension.json`. Диагностировать это по конфигу нельзя
> без знания правила про first-seen; диагностировать по рантайм-логу
> (`Found pyRevit assembly:`) можно всегда — там факт, а не намерение.
> Раздел 10 `SETUP-RUNBOOK.md` теперь ссылается именно на лог, а не на
> «обычно причина в X».
