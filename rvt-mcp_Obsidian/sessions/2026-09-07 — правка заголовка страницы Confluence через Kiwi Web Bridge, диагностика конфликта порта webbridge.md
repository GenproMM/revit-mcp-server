# 2026-09-07 — правка заголовка страницы Confluence через Kiwi Web Bridge, диагностика конфликта порта webbridge

## Контекст задачи

Отдельная короткая сессия в тот же день, не связанная с кодовой базой
revit-mcp-server: пользователь попросил открыть страницу Confluence
(`https://wikign.com/pages/viewpage.action?pageId=229441856`, «Создание нового
инструмента для RevitMCP» — методичка про добавление инструментов в этот же
проект, но задача была про саму вики-страницу, не про код) и переименовать её
в «Создание нового инструмента для RevitMCP (ТЕСТ)» через MCP-сервер
Kiwi Web Bridge.

## Что пошло не так и как обошли

MCP-сервер `webbridge` не подключился — harness показал только
`CONNECTION_CLOSED`. Диагностировано: `kimi-webbridge mcp` слушает
захардкоженный порт 10086, и его уже держал другой запущенный экземпляр
(`node.exe`, PID 60076) — новый процесс падал на `EADDRINUSE`, а harness
сворачивал это до неинформативного `CONNECTION_CLOSED`. Полный разбор —
[[webbridge MCP падает CONNECTION_CLOSED из-за занятого порта 10086]].

Обходной путь: тот же пакет работает и как обычный CLI
(`npx kimi-webbridge <tool> '<json>'`) и достучался до уже поднятого моста
напрямую, без MCP-транспорта. Через него и сделана вся правка:
`navigate` на страницу → `navigate` на `editpage.action` (редактор) →
`fill('#content-title', …)` → `click('#rte-button-publish')` → проверка
`evaluate` после публикации (URL вернулся на `viewpage.action`, `document.title`
и `h1` содержат новый заголовок).

Отдельная сложность самого вызова: PowerShell рвёт кавычки JSON-аргумента
CLI, пришлось звать `npx kimi-webbridge …` из Bash с JSON, собранным через
heredoc в файл.

## Результат

Заголовок страницы 229441856 изменён и опубликован:
«Создание нового инструмента для RevitMCP» →
«Создание нового инструмента для RevitMCP (ТЕСТ)».

## Не закрыто

Само по себе ничто не блокирует — но конфликт порта повторится в любой
следующей сессии, если старый `kimi-webbridge mcp` не будет остановлен
(`Stop-Process -Id <pid>`) перед стартом новой. Настоящее исправление — на
стороне пакета `kimi-webbridge` (сделать порт настраиваемым или не падать на
уже работающем инстансе), вне этого репозитория.

Пункт не заведён в [[Текущие приоритеты]] — задача не относится к дорожной
карте revit-mcp-server.
