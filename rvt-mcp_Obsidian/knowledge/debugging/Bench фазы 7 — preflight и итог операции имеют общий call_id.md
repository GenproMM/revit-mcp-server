# Bench фазы 7 — preflight и итог операции имеют общий call_id

## Измерение на рабочем ПК

Пользователь выполнил одноразовую live-приёмку пилота `2026.10.26-1209.92fbaf5`, Revit 2024, Hermes Desktop. Direct: `DIRECT_CHECK_OK`, `POSTS_SENT=5`, `SECRET_OCCURRENCES=0`. Итоговый классификатор выдал **PHASE7_BENCH_STOP**, поскольку для H1–H5 найдено несколько строк с одним call_id.

Диагностика сохранённого final.json: один audit-файл, 25 строк. Для каждого сценария есть ровно одна строка целевого маршрута, а дополнительные строки — `/mutation_preflight/` с тем же call_id. Для принятой мутации видны preflight до окна, preflight после согласия и целевой маршрут. Для отказа/таймаута — preflight и итоговая запись отказа на целевом маршруте. Это не доказательство повторной мутации.

## Причина в коде

`tests/test_phase7_live_bench.py::_audit_entries` индексирует все записи по call_id. `_scenario_entry` требует `len(found) == 1` ДО фильтрации по ожидаемым tool/route из SCENARIOS. Законные preflight-строки делают любой такой сценарий неоднозначным для классификатора.

## Требуемое исправление (ещё не сделано)

Выбирать единственную запись по call_id + ожидаемый tool + ожидаемый route; учитывать законные preflight-строки отдельно. Не выбирать произвольную первую/последнюю строку, не удалять строки из исходных доказательств. Сохранить отказы на дубликатах итогового маршрута, неверных tool/route, отсутствующем аудите, переиспользовании call_id, неверных decision/approval/outcome и разных args у H4. Добавить регрессии с реалистичной последовательностью preflight → recheck → mutation и preflight → refusal/expiry.

Исходный STOP остаётся фактом. Исправленный классификатор должен прочитать тот же final.json и записать новый отдельный результат с версией классификатора, без HTTP/новых POST и без перезаписи доказательств. Повтор direct запрещён после POSTS_SENT>=1. SAFE-20/21 и фазу 7 не закрывать автоматически.

## Другие замечания той же приёмки

- `get_selected_elements` скрывает ID/категорию: `revit_mcp/editing.py` возвращает `elements`, `count`, `message`, а `tools/utils.py::_project_response` выбирает только `message`. Исправить узко и с тестом реального ответа; не менять глобальную семантику ошибок. Пользователь получил ID через Revit UI.
- H1 удалил 1 элемент и 13 зависимых. Пользователь подтвердил карточку и затем исчезновение элемента. Не установлено, что карточка предсказала точный каскад: проверить факты/формулировку, не выдавать неизвестный каскад за известный.
- H4: новая карточка показана, разные call_id, элемент остался; сами коды карточек не записаны, их различие НЕ подтверждено. Аудит ещё должен подтвердить идентичность args.
- Windows PowerShell исказил кавычки Python при `& $Py -c $Code`; `NameError: PHASE7_APP`. Запуск через `$Code | & $Py -` сработал. Для кириллицы учитывать кодировку stdin Windows PowerShell, не передавать секреты в исходном коде/выводе.
- deploy-скрипты при CP65001 неверно прочитали LF config.cmd; запуск при CP866 сработал. Упаковку .cmd и кодовую страницу инструкций проверить, не исправлять это слепой сменой production-скриптов.
