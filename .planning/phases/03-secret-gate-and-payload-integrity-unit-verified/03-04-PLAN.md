## Notes the executor needs

- **Shape for Phase 5 (RESEARCH Pitfall 9):** `check_integrity(root)` is a plain function the Phase 5
  caller runs once at extension load and caches; do not add caching or module state here.
- **startup.py imports both helpers at the next Revit start:** discovery imports every
  non-underscore `revit_mcp/*.py` and reports a module without a registrar as a helper. `integrity.py`
  must therefore import cleanly under IronPython 3 and register nothing. Plan 03-06 simulates that
  runtime; plan 03-08 checks `hashlib` live.
- **D-17 note:** CONTEXT names `revit_mcp/integrity.py` as a "thin pyRevit-dependent wrapper". This
  plan builds it with no pyRevit import at all (a plain file reader), which keeps it unit-testable;
  `revit_mcp/security.py` (the Phase 5 wrapper installer) is not created in this phase.

- `revit_mcp/integrity.py` and the additions to `revit_mcp/trust.py` follow the IronPython 3.4
  dialect (CLAUDE.md): encoding cookie line 1, `"{}".format`, no f-strings, no `{**d}`/`[*a]`, no

  annotations, no 3.9+ APIs, standard library only.

  `git hash-object startup.py` stays as recorded before the plan.
