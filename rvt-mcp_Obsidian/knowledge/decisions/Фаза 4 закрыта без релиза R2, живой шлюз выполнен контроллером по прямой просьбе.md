# Фаза 4 закрыта без релиза R2, живой шлюз выполнен контроллером по прямой просьбе

**Контекст.** План 04-11 помечен `autonomous: false`, `gate="blocking-human"`: по правилам проекта живые шаги идут руками инженера, один раз. Контроллер сначала остановился и отдал пользователю нумерованные шаги. На чекпоинте релиза R2 (`.planning/RELEASES.md`) форма ответа мутаций уже изменилась.

**Решения пользователя.**
1. Пользователь прямо попросил контроллера выполнить шлюз самому и подставил значения (стена, вид, элемент для маркировки, папка вне репозитория). Контроллер выполнил один запуск `tests/test_phase4_live_outcomes.py run` после проверки условий: один слушатель на 48884, один процесс Revit, запущенный после последней правки `revit_mcp/`, один документ, пустая папка вне репозитория. Результат `PHASE4_OUTCOMES_OK`, `POSTS_SENT=5`, шлюз израсходован.
2. Релиз **R2 пропущен** (`skipped` в Ledger, коммит `cfca0aa`). R2 не делается отдельно; открытые советы ревью переносятся к ближайшему релизу.

**Почему так.** Живые условия проверяются дёшево до первой записи (скрипт сам делает только чтения в предпроверке и отказывается при нарушении), а явная просьба пользователя заменяет «человек за машиной» в рамках его же правила; без неё контроллер сам живые шаги не запускает. Пропуск R2: у фазы 4 нет раскатываемого эффекта сверх следующих фаз, пилотный релиз выгоднее собрать после фазы 5.

**Как применять.** Живые одноразовые шлюзы по-прежнему не запускаются без явного указания пользователя. Перед любым живым запуском контроллер проверяет порт, процесс и время старта Revit против последней правки `revit_mcp/`. Требования в `REQUIREMENTS.md` отмечает только `phase.complete`: исполнителям запрещено править этот файл.
