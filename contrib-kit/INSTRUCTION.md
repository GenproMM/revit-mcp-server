# Инструкция: как сделать свой инструмент для RevitMCP

Пошагово, с нуля. Читать сверху вниз, ничего не пропуская.

Вам **не нужен** доступ к репозиторию сервера и не нужно знать Git. Вы соберёте
один файл-архив и положите его в папку на сервере. Дальше его добавит
сопровождающий.

---

## Часть 1. Что вы вообще делаете

RevitMCP состоит из двух половин, которые разговаривают между собой:

- **половина внутри Revit** — принимает команды и работает с моделью;
- **половина снаружи** — та, с которой разговаривает ИИ-помощник.

Ваш инструмент — это **по одному файлу в каждую половину**. Ровно два файла.
Больше ничего. Именно поэтому его можно передать архивом, не трогая репозиторий.

Пример: инструмент «сводка стен по типам».

- Файл внутри Revit собирает стены и считает площади.
- Файл снаружи описывает модели, **когда** этот инструмент вызывать и что он
  вернёт.

Второй файл важнее, чем кажется. Языковая модель видит только его описание —
больше у неё ничего нет. Плохое описание = инструмент вызывают неправильно.

## Часть 2. Настройка среды. Один раз

### Шаг 2.1. Проверьте, что Revit и RevitMCP работают

Откройте Revit и **откройте любую модель** (не пустое окно — именно модель).

Затем откройте в браузере:

```
http://localhost:48884/revit_mcp/status/
```

**Что должно быть:** страница с текстом, где встречается `"health": "healthy"`.

**Если страница пустая или ошибка соединения:**

| Что видите | Что делать |
|---|---|
| Не удаётся подключиться | Revit закрыт, или в нём не открыта модель. Откройте модель. |
| Пусто, но соединение есть | Расширение RevitMCP не загрузилось. Перезапустите Revit **полностью** (закрыть и открыть, не кнопкой Reload). |
| Не помогло | Напишите сопровождающему: без работающего моста делать инструмент нельзя. |

Без этого шага дальше идти нет смысла — вы не сможете проверить свою работу.

### Шаг 2.2. Найдите Python

Отдельно ставить ничего не нужно: Python уже приехал вместе с pyRevit.

Откройте **Проводник** и вставьте в адресную строку:

```
%APPDATA%\pyRevit\bin
```

Зайдите в папку `cengines`, там будет папка вида `CPY3123` (цифры могут
отличаться). Внутри — `python.exe`. **Запомните полный путь к нему**, он
понадобится. Выглядит примерно так:

```
C:\Users\ВашеИмя\AppData\Roaming\pyRevit\bin\cengines\CPY3123\python.exe
```

Проверьте: откройте **PowerShell** (Win+X → Терминал) и выполните, подставив
свой путь:

```powershell
& "C:\Users\ВашеИмя\AppData\Roaming\pyRevit\bin\cengines\CPY3123\python.exe" --version
```

Должно напечатать `Python 3.12.3` или похожее.

> Если у вас уже установлен свой Python 3 и команда `python --version` работает —
> используйте его, разницы нет. Набор работает на любом Python 3.

### Шаг 2.3. Распакуйте набор

Возьмите `revitmcp-contrib-kit.zip` из папки:

```
\\srv-dfs\BIM\06_RevitMCP\contrib-kit\
```

Распакуйте **целиком** в удобное место, например `C:\work\revitmcp-kit`.
Не переименовывайте файлы внутри и не удаляйте `conventions.py` — без него
ничего не заработает.

Должно получиться:

```
C:\work\revitmcp-kit\
  revitmcp_kit.py        программа, которой вы будете пользоваться
  conventions.py         правила проверки (не трогать)
  INSTRUCTION.md         этот файл
  README.md              краткая версия
  AGENTS.md              правила для ИИ-помощника
  .kilo\agents\          настройка агента
```

Проверьте, что набор запускается. В PowerShell:

```powershell
cd C:\work\revitmcp-kit
python revitmcp_kit.py
```

Должен напечататься список команд. Если пишет «python не найден» — используйте
полный путь к `python.exe` из шага 2.2 вместо слова `python`.

> **Совет, чтобы не мучиться с длинным путём.** Выполните один раз в PowerShell:
> ```powershell
> Set-Alias python "C:\Users\ВашеИмя\AppData\Roaming\pyRevit\bin\cengines\CPY3123\python.exe"
> ```
> Это действует до закрытия окна. Дальше в инструкции пишется просто `python`.

### Шаг 2.4. Установите VS Code и Kilo Code

1. Установите **VS Code**, если его нет.
2. В VS Code нажмите значок расширений слева (или `Ctrl+Shift+X`).
3. Найдите **Kilo Code** и установите.
4. Откройте настройки Kilo Code и подключите вашу модель (ключ и адрес вам даёт
   сопровождающий или ИТ).

### Шаг 2.5. Откройте папку набора в VS Code

**Это важный шаг, его часто делают неправильно.**

В VS Code: `Файл` → `Открыть папку` → выберите `C:\work\revitmcp-kit`.

Именно **папку набора**, а не отдельный файл. Только тогда Kilo Code
автоматически прочитает `AGENTS.md` и будет знать правила: какой Python нужен,
чего нельзя делать, как проверять.

**Как убедиться, что помощник видит правила.** Напишите ему в чат:

```
Прочитай AGENTS.md и скажи одной фразой: чем отличается файл в revit_mcp
от файла в tools?
```

Правильный ответ по смыслу: *в `revit_mcp` — IronPython 3 внутри Revit, на
уровне языка Python 3.4, там нельзя f-строки; в `tools` — обычный
современный Python 3, там можно всё.*

Если помощник этого не знает — он не прочитал правила. Проверьте, что открыта
папка, а не файл, и что `AGENTS.md` лежит в её корне.

**Настройка среды закончена.** Дальше — работа.

## Часть 3. Делаем инструмент

### Шаг 3.1. Сначала решите, читает он или пишет

Это самый важный вопрос, и ответить на него надо **до** написания кода.

- **Читает** — только смотрит модель и возвращает данные (сводка, проверка,
  поиск). Ничего не меняет.
- **Пишет** — создаёт, удаляет или изменяет элементы, ставит значения
  параметров.

От этого зависит устройство файла: читающий инструмент **не открывает
транзакцию**, пишущий обязан её открыть и правильно защитить.

Если сомневаетесь — почти всегда нужен читающий. Начните с него.

### Шаг 3.2. Создайте каркас

```powershell
python revitmcp_kit.py new wall_report list_wall_report --get --author "Иван Иванов"
```

Разберём команду:

| Часть | Что это |
|---|---|
| `new` | создать каркас |
| `wall_report` | тема инструмента, папка и файлы получат это имя |
| `list_wall_report` | имя, которым инструмент будет вызывать модель |
| `--get` | **читающий** инструмент. Пишущий — просто не указывайте этот флаг |
| `--author "Иван Иванов"` | вы, для истории изменений |

Имена — только строчные латинские буквы, цифры и подчёркивание. Никаких
пробелов, дефисов и русских букв.

Хорошие имена инструментов начинаются с глагола: `list_...`, `get_...`,
`check_...`, `create_...`, `set_...`.

### Шаг 3.3. Что получилось

Появилась папка `wall_report-tool`:

```
wall_report-tool\
  manifest.json                    кто автор, какие инструменты в пакете
  revit_mcp\wall_report.py         РАБОТА С МОДЕЛЬЮ (внутри Revit)
  tools\wall_report_tools.py       ОПИСАНИЕ ДЛЯ МОДЕЛИ (снаружи)
  NOTES.md                         что сделали и как проверяли
```

Ровно эти файлы и должны получиться в итоге. Ни больше, ни меньше.

**Куда что складывать в пакете.** Раскладка по папкам жёсткая, приёмка смотрит
именно на неё:

| Папка в пакете | Что туда кладётся |
|---|---|
| `revit_mcp\` | файл, работающий с моделью внутри Revit (IronPython 3) |
| `tools\` | **новые инструменты для revit-mcp-server** — файлы с `@mcp.tool()`, которые видит модель |
| `skills\` | **skills и дополнительные инструкции** — `SKILL.md`, вспомогательные `*.md`, справочные материалы для ИИ-помощника |

Если ваш набор добавляет на revit-mcp-server новые инструменты — их файлы
складываются в `tools\`. Если вы передаёте skills или дополнительные
инструкции (описания сценариев, памятки, правила для помощника) — они
складываются в `skills\`.

Папку `skills\` каркас не создаёт, потому что она нужна не всегда. Если она вам
нужна — создайте её сами в корне пакета, рядом с `tools\`, и перечислите её
содержимое в `NOTES.md`.

Внутри файлов расставлены пометки `TODO` — это места, где нужны вы. Всё
остальное уже написано правильно: имена функций, структура, служебные строки.
**Не переименовывайте функции и не меняйте их аргументы** — по ним сервер
находит ваш инструмент.

### Шаг 3.4. Работайте с помощником

Перейдите в папку пакета и откройте её в VS Code:

```powershell
cd wall_report-tool
```

Теперь попросите помощника. Хороший запрос выглядит так:

```
Заполни TODO в этом пакете.

Инструмент читающий: он собирает все стены модели, группирует их по типу
и считает суммарную площадь.

Возвращать: имя типа, количество стен, суммарную площадь в квадратных
миллиметрах. Плюс счётчик стен, площадь которых прочитать не удалось.

Параметр example — часть имени типа стены для фильтра, необязательный.
```

Чем точнее вы скажете, что должно вернуться и в каких единицах, тем меньше
придётся переделывать.

**Что помощник сделает сам:** структуру кода, правильные служебные вызовы,
обработку ошибок, формат описания.

**Что решаете только вы:**

- какие элементы брать и по какому признаку;
- какие параметры читать, у экземпляра или у типа;
- что вернуть и в каких единицах;
- что считать ошибкой, а что — законным пустым ответом.

### Шаг 3.5. Заполните описание для модели

Помощник напишет описание сам, но **прочитайте его сами** и проверьте, что там
есть все четыре вещи:

1. Когда этот инструмент вызывать.
2. Конкретные примеры значений: `"Generic - 200mm"`, а не «имя типа».
3. Единицы измерения: «площадь в квадратных миллиметрах».
4. **Ограничения прямым текстом.** Например: «стены в связанных моделях не
   учитываются», «витражные стены считаются как одна стена».

Четвёртый пункт — самый важный и его чаще всего забывают. Без него модель
примет пустой ответ за доказательство, что таких стен в проекте нет, и сообщит
пользователю неверный вывод о модели.

### Шаг 3.6. Заполните manifest.json и NOTES.md

В `manifest.json` замените `TODO` в поле `description` на одну строку о
назначении. Проверьте, что в `author` стоит ваше имя.

`NOTES.md` заполните честно: на какой модели проверяли, какая версия Revit, что
осталось непроверенным. Это читает сопровождающий, и это единственное место,
где можно предупредить его о слабом месте.

## Часть 4. Проверка

Проверок две, и они разные. Обе обязательны.

### Шаг 4.1. Проверка формы

```powershell
python ..\revitmcp_kit.py check
```

**Если всё хорошо**, напечатает `Замечаний нет.`

**Если есть замечания**, вы увидите список. Читайте формулировки буквально —
они точные. Частые:

| Замечание | Что это значит |
|---|---|
| `f-strings are Python 3 only` | В файле внутри Revit использована f-строка. Там нужен `"{}".format(x)`. Покажите замечание помощнику — он исправит. |
| `остались TODO в докстринге` | Не заполнено описание для модели. Без него инструмент непригоден. |
| `не заполнено description` | В `manifest.json` осталось `TODO`. |
| `Args: block` | В описании не перечислены все параметры. |
| `use make_element_id()` | Использован запрещённый способ работы с номерами элементов — он падает на Revit 2027. |

Самый простой способ исправить: скопируйте текст замечания и отдайте помощнику
целиком.

Повторяйте, пока не будет `Замечаний нет.`

### Шаг 4.2. Проверка поведения на живой модели

**Это главная проверка.** Предыдущая смотрит только на форму кода — она не
знает, правильные ли данные возвращает ваш инструмент.

Убедитесь, что Revit открыт и модель открыта. Затем:

```powershell
python ..\revitmcp_kit.py probe
```

Для пишущего инструмента или если нужны параметры:

```powershell
python ..\revitmcp_kit.py probe --payload '{"example": "Generic"}'
```

Что происходит: ваш код отправляется в **ваш собственный** Revit и выполняется
на **реально открытой модели**. Repозиторий для этого не нужен, Revit
перезапускать не надо.

**Что должно быть:** строка `PROBE_OK:` и за ней данные. Посмотрите на данные
глазами: похожи ли числа на правду? Столько ли стен, сколько вы ожидаете?

**Если ошибка:**

| Что видите | Что делать |
|---|---|
| `мост не отвечает` | Revit закрыт или модель не открыта. Проверьте шаг 2.1. |
| `Маршрут упал внутри Revit` + текст ошибки | Отдайте помощнику весь текст, включая трассировку. |
| `PROBE_OK` но данные пустые | Логика не находит элементы. Проверьте категорию и фильтр. |
| `PROBE_OK` но числа неправдоподобные | Скорее всего перепутаны единицы: внутри Revit футы, наружу миллиметры. |

> **Важно.** Зелёная проверка формы — это **не** «работает». Работает — это
> `PROBE_OK` с данными, которые вы посмотрели и признали правильными.

## Часть 5. Сдача

### Шаг 5.1. Соберите пакет

```powershell
python ..\revitmcp_kit.py pack
```

Команда сначала сама перепроверит форму и откажется собирать пакет с
замечаниями. Получится файл `wall_report.zip` — ваши два файла, манифест,
заметки и, если она есть, папка `skills\` целиком.

### Шаг 5.2. Положите пакет на Google Drive и отправьте ссылку

Папку приёма вы делаете сами, на своём Google Drive.

1. Создайте на своём Google Drive **произвольную папку** — имя любое, лишь бы
   вам самим было понятно: `RevitMCP-инструменты`, `revitmcp-inbox-Иванов`.
2. Положите в неё собранный `.zip`.
3. Откройте доступ к папке: `Открыть доступ` → добавьте
   **e.ermolenko@genpro.ru** с правами **Читатель**.
4. Скопируйте ссылку на папку (`Копировать ссылку`) и **отправьте её в
   Google-чате BIM-менеджеру e.ermolenko@genpro.ru**. В сообщении укажите имя
   инструмента и одну фразу о назначении — этого достаточно.

Ссылку достаточно отправить **один раз**. Дальше складывайте в эту же папку
все свои следующие пакеты и просто пишите в чат, что появился новый — новую
папку и новую ссылку каждый раз создавать не нужно.

> Отправляйте ссылку **на папку**, а не на отдельный файл: по ссылке на файл
> сопровождающий не увидит ваши следующие пакеты.

### Шаг 5.3. Что происходит дальше

1. Сопровождающий запускает приёмку: она проверяет пакет теми же правилами,
   что и ваш `check`, и отдельно ищет опасные конструкции.
2. Сопровождающий **читает ваш код**. Это обязательный шаг: ваш код будет
   исполняться внутри Revit на всех станциях отдела, и автоматика не может
   оценить замысел.
3. Если всё в порядке — код попадает в репозиторий, ваше имя сохраняется в
   истории изменений.
4. Инструмент приезжает людям при следующем перезапуске Revit и входе в
   систему. Ничего никому делать не нужно.

Если что-то не так, сопровождающий вернёт пакет с замечаниями. Исправьте и
соберите заново.

## Частые ошибки

**Открыли в VS Code отдельный файл, а не папку.** Помощник не читает правила и
пишет код, который не пройдёт проверку. Открывайте папку.

**Начали писать код, не решив, читает инструмент или пишет.** Переделывать
придётся почти всё. Решите сначала.

**Правили `conventions.py`, чтобы проверка прошла.** Это копия файла, по
которому проверяет сопровождающий. Проверка у вас пройдёт, приёмка откажет.

**Сдали по зелёной проверке формы, не запустив `probe`.** Самая частая причина
возврата пакета.

**Добавили в пакет что-то ещё:** правку общего файла, второй модуль, файл с
данными. Приёмка отклонит архив целиком. Пакет — это два модуля инструмента
плюс, если нужно, папка `skills\`. Если задача требует большего, напишите
сопровождающему **до** того, как писать код.

**Разложили файлы не по тем папкам.** Инструменты для revit-mcp-server — в
`tools\`, skills и дополнительные инструкции — в `skills\`. Файл с `@mcp.tool()`,
лежащий в корне пакета или в `skills\`, приёмка не найдёт.

**Отправили ссылку на файл вместо ссылки на папку.** Тогда следующий ваш пакет
сопровождающий не увидит, и придётся писать в чат заново.

**Перепутали единицы.** Внутри Revit всё в футах, наружу всё в миллиметрах.
Если числа отличаются примерно в 305 раз — дело в этом.

**Использовали кнопку Reload в pyRevit.** Для этого расширения она не годится и
роняет Revit. Только полный перезапуск. Для проверки своего кода перезапуск не
нужен вообще — используйте `probe`.

## Куда смотреть ещё

- `README.md` — то же самое коротко, для повторного использования.
- `AGENTS.md` — полный список правил. Его читает ваш ИИ-помощник; полезно
  прочитать и вам, чтобы понимать его отказы.

Если застряли — напишите сопровождающему и приложите: текст команды, полный
вывод с ошибкой и содержимое `NOTES.md`. Этого обычно достаточно.
