# 2026-09-07 — пилот раскатки на удалённой станции, миграция на IronPython 3, шесть найденных багов

## Контекст задачи

Продолжение сессии [[2026-09-07 — автообнаружение регистрации, тестовый уровень, приёмка инструментов без доступа к репозиторию]]
и работы над [[Деплой в контур — сервер раздаёт файлы, оба процесса живут на станции]]
— тот же день, но новый разговор. Пользователь начал первый реальный пилот
раскатки: сначала на своей машине (`Admin`), затем на удалённой пилотной
станции (`e.ermolenko`) под удалённым управлением через диалог — все команды
пользователь выполнял сам и присылал вывод, ни одного прямого доступа к
станции не было.

Каждый следующий шаг раскатки — публикация, сборка, установка, проверка —
вскрывал новую поломку. Итог: шесть независимых багов, пять из них исправлены
и закоммичены, один (сеть) остался открытым решением, не кодовым фиксом.

## Хронология находок

### 1. Публикация ушла в дерево-двойник (кодовая страница cmd.exe)

Первый же запуск `deploy\publish-extension.cmd` отрапортовал успех, но
`ext\` не появилась там, где искал Проводник. Причина —
[[cmd.exe читает config.cmd в консольной кодовой странице, не в UTF-8 файла]]:
кириллический литерал `MCP_SHARE_ROOT` из `config.cmd` (UTF-8 без BOM)
`cmd.exe` разобрал в активной кодовой странице консоли (866), и `mkdir`
построил дерево с нечитаемым именем рядом с настоящей папкой.

Ошибся дважды в диагностике этого случая: сначала счёл искажение
косметикой вывода — оказалось, оно било по реальному пути записи; затем
попытался воспроизвести на другой машине и не смог, из чего сделал
предварительный (не подтверждённый до конца технически) вывод. Подтверждение
пришло не от анализа, а от пользователя: `chcp 65001` перед вызовом решил
проблему на реальной станции.

### 2. Гейт холодного старта мерил не то

Следующий шаг, сборка payload, упал на приёмочном тесте:
`initialize too slow: 2.295 s` при лимите 2.0 с. Разобрано в
[[Гейт холодного старта мерил SMB-задержку шары, а не старт сервера]] —
сборка стажировалась прямо на сетевую шару, и гейт запускал сервер оттуда
же, меряя SMB, а не старт процесса. Перенесено в `%TEMP%`, коммит `31ea748`.

### 3. Hermes-блок писался не в тот файл

`configure_hermes.py` жёстко резолвил `~/.hermes/config.yaml` — того, что
Windows-ветка резолвинга самого Hermes Agent никогда не выбирает
(платформенное умолчание там — `%LOCALAPPDATA%\hermes`, а на пилотной
станции ещё и `HERMES_HOME` был переопределён форком в `%LOCALAPPDATA%\gena`).
См. [[configure_hermes.py писал в файл, которого Hermes на Windows не читает]],
коммит `8825f6d`. Найдено чтением исходников работающего форка Hermes,
установленного локально из git (`NousResearch/hermes-agent` @ `56526bc0d`) —
попытка достать код форка пользователя с GitHub (`GenproMM/MastermindServices`)
не удалась, репозиторий приватный, анонимный `WebFetch` вернул 404, `gh` на
машине не установлен. Логика резолвинга (`HERMES_HOME` → платформенное
умолчание) устойчива к этому пробелу, но сверка с форком буквально не
проводилась.

### 4. Расширение не грузилось: устаревший disabled=true

После правки config.cmd публикация и сборка прошли, `install.cmd` отработал
все шесть шагов чисто — но `/status/` отвечал `Route does not exist` от
самого pyRevit. Несколько итераций проверки (лог, путь поиска расширений,
диалоги Revit, таймаут загрузки по UNC) свелись к рантайм-логу: расширение
вообще не собиралось pyRevit. Причина —
[[pyRevit хранит disabled=true по имени папки расширения]]: наследие более
старой версии `extension.json`, конфиг ключуется именем папки, которое не
менялось. `install.cmd` теперь сам снимает флаг, коммит `5fcd8fe`.

### 5. Миграция на IronPython 3 — самая крупная находка сессии

Следующий перезапуск дал первый частичный успех: `/status/` ожил, но
`"health": "degraded"`, 22 из 23 доменов в `failed_domains`. `pyrevit env`
показал движок `IPY342` — станция подключена к IronPython 3, не 2.7, на
который был рассчитан весь `revit_mcp/`. Пользователь подтвердил явно:
парк переходит на IronPython 3 насовсем, это не временная аномалия одной
станции.

Разобрано в [[Целевой рантайм Revit-половины — IronPython 3, не 2.7]]
(решение) и [[Голый import соседа внутри revit_mcp сломал 22 из 23 доменов]]
(баг): 23 голых `from utils import ...` — неявный относительный импорт,
убранный в Python 3. Плюс два точечных py2-импорта
(`StringIO`, `urllib.unquote`), найденных по одному, каждый после того, как
предыдущий фикс открывал следующий слой отказа. Три отдельных узких grep-а
не поймали то, что в итоге поймал полный обход всех импортов файл за файлом.

Заодно найдена независимо от пилотного лога, чтением кода при аудите:
[[unicode внутри широкого except молча обнулял значения параметров]] — вторая
копия бага [[sanitize_string превращает кириллицу в вопросительные знаки]] в
`parameters.py`, которая под IronPython 3 не падает, а тихо возвращает пустую
строку для каждого значения параметра. Самая опасная находка дня именно
потому, что её не нашла бы пилотная станция — она не проявляется как ошибка.

Оба фикса, `0e07076` и `d75c24c`, сопровождены расширением
`scripts/conventions.py` на AST-проверку обоих классов ошибки, с тестами в
обе стороны (ловит четыре реальные поломки, не ловит четыре исправленные
формы) — решение зафиксировано текстом: три узких grep-а за один день не
масштабируются, следующая станция с иным движком не должна повторять то же
расследование.

### 6. Ручная вставка Hermes-конфига с универсальными путями

Пока payload с фиксом №3 не пересобран на станции, конфиг Hermes правили
руками — YAML-блок с маркерами `# >>> RevitMCP managed block >>>` (чтобы
будущий `configure_hermes.py` опознал его как свой), затем JSON-вариант с
`${APPDATA}`/`${LOCALAPPDATA}` вместо абсолютного пути пользователя — форк
поддерживает интерполяцию в духе Cursor (`_interpolate_env_vars`,
подтверждено чтением `tools/mcp_tool.py`). Осталось фактом станции: версия
движка `CPY3123` и вариант размещения `pyRevit-Master` — их подстановкой не
снять, они должны совпадать с `payload\ENGINE`.

## Не закрыто

**Routes слушает `0.0.0.0`, не `127.0.0.1`** — подтверждено рантайм-логом, не
починено, требует решения человека (правка `pyRevit_config.ini` при закрытом
Revit, файрвол, или `routes disable` между тестами), а не кода. Записано в
[[Открытые вопросы по проекту]], раздел «Безопасность пилота».

Не пересобран payload с фиксом Hermes-пути (`8825f6d`) на пилотной станции —
ручная вставка конфига остаётся временной, до пересборки `configure_hermes.py`
откажется трогать запись без маркеров managed-блока (штатное поведение).
