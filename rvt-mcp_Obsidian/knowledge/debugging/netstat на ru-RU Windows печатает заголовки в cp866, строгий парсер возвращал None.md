# netstat на ru-RU Windows печатает заголовки в cp866, строгий парсер возвращал None

**Статус:** исправлено, коммит `d7337eb` · найдено первым запуском живой перепроверки 02-02

## Симптом

`PHASE2_IDENTITY_RECHECK_STOP: listener inventory None does not show the reported PID ...`, хотя `Get-NetTCPConnection` и `netstat` показывали один слушатель на 48884. `bridge.listener_snapshot([48884])` возвращал `None`; значит, и каждый выбранный вызов `get_revit_status(target=...)` отказывал бы с «Listener inventory unavailable» на каждой русской машине.

## Причина

`netstat.exe` печатает заголовок («Активные подключения», «Имя Локальный адрес …») в OEM-кодировке cp866, а `subprocess` с `text=True` декодирует локалью cp1251, поэтому строки превращаются в мусор. Парсер допускал перед данными только четыре известных варианта заголовка и по любой другой нечитаемой строке возвращал `None` (отказ по закрытому правилу G5). Тесты были зелёными, потому что фикстуры содержали английский и один русский вариант, но не настоящие байты cp866.

## Исправление

- Строки до первой `TCP`-строки пропускаются **по форме, а не по тексту**: подходит строка, в которой ни одно поле не разбирается как `host:port`. Любая не-`TCP` строка после первой строки данных, повреждённая строка данных или вывод без строк данных по-прежнему дают `None`.
- `netstat` запускается с `encoding="ascii", errors="replace"`, так что декодирование не зависит от локали и не падает.
- Копия парсера в `tests/test_phase2_preflight.py` изменена идентично (тест проверяет AST-равенство), регрессионные тесты используют реальные байты cp866.
