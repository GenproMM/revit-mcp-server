# Окна и двери без хоста прилипали к началу координат

**Статус:** исправлено · коммит `2469821` · найдено на живой модели

## Симптом

Окно или дверь, запрошенные в конкретной точке, создавались в начале координат
проекта. Не рядом, а именно в `(0, 0, 0)`. При этом элемент существовал и выглядел
нормально — просто не там и не в стене.

Обнаружено при добавлении окон в QA-модель Empire State Building.

## Причина

`place_family` использовал неhosted-перегрузку `NewFamilyInstance` для **всех**
семейств без разбора. Но семейства, требующие хост (окна, двери и прочие
стено-размещаемые), в этой перегрузке создаются без хоста, и Revit молча снапит их к
началу координат вместо запрошенной точки.

Ошибки нет — Revit считает такой вызов допустимым. Просто результат бессмысленный.

## Исправление

Три шага:

1. **Определить**, требует ли семейство хост-стену (по категории и по признакам
   семейства).
2. **Найти ближайшую стену** к запрошенной точке — коллектор по
   `DB.BuiltInCategory.OST_Walls` с выбором минимального расстояния.
3. **Использовать hosted-перегрузку** `NewFamilyInstance(point, symbol, host_wall, ...)`.

Отдельно и важно: если для hosted-семейства стены рядом **не нашлось**, маршрут теперь
**внятно падает** вместо создания сломанного экземпляра:

> «Family '...' must be hosted by a wall, but no wall was found near the requested
> location. Create the host wall first.»

## Урок

> Успешный вызов Revit API не означает осмысленного результата. Тихая деградация до
> «элемент создан, но в неправильном месте» хуже исключения — она проходит все
> проверки и обнаруживается глазами через десятки операций.

Правильная реакция на невозможность корректно выполнить операцию — явная ошибка с
инструкцией, что сделать сначала. Сообщение адресовано ИИ-клиенту, который может
создать стену и повторить вызов.
