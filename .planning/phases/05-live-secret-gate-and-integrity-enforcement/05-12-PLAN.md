## Execution rules for every task in this plan

- The script imports the repository's `bridge` and `tools` lazily inside the run path (sys.path gets
  REPO_ROOT), never at import, so the unit test can load it without side effects.
- Seams for the offline tests, used by the real code path too: `_bridge()` returns the bridge module,
  `_direct_client(port)` returns the httpx client for direct steps, `_git(args, repo)` runs git. Tests
  replace them with fakes; there is no test-only branch in the logic.
- The wrong-secret bridge step sets `bridge._secret_cache` to WRONG_SECRET for that single call and calls
  `bridge.reset_secret_cache()` right after it (in a finally), before any later step.
- Never read the secret file in the script except through `bridge.load_secret()` inside `scan-secret`;
  never print it; records never contain it.
- `uv run pytest tests/unit -q` green before every commit; explicit pathspec commits
  (`git commit -m "<message>" -- tests/test_phase5_live_gate.py tests/unit/test_phase5_live_gate.py`;
  never `git add -A` or `.`); prefix `test(05-12):`; end with your session's attribution line.
