# Добавление возможности требует правок в четырёх местах (историческая: было 4, стало 2)

Было стандартное изменение в этом проекте — два новых файла (или два новых блока) и две
строки регистрации. Пропустить любую из четырёх точек означало тихо потерять
возможность. Теперь строк регистрации нет — см. врезку выше.

## Чек-лист

### 1. Обработчик маршрута — `revit_mcp/<домен>.py`

Добавить `@api.route("/<имя>/", methods=["POST"])` внутрь существующего модуля домена,
либо создать модуль с функцией `register_<домен>_routes(api)`.

Требования: `# -*- coding: UTF-8 -*-`, IronPython-совместимый синтаксис, докстринг,
`logger`, паттерн «валидация → транзакция → сериализация».

См. [[Паттерн регистратора маршрутов]] и
[[Паттерн обработчика маршрута — валидация, транзакция, сериализация]].

### 2. Регистрация маршрута — `startup.py`

Дописать импорт и вызов в `register_routes()`, **в конец**, в том же стиле:

```python
from revit_mcp.newdomain import register_newdomain_routes

register_newdomain_routes(api)
```

### 3. Обёртка инструмента — `tools/<домен>_tools.py`

Добавить корутину под `@mcp.tool()`, возвращающую
`format_response(await revit_post(...))`.

Требования: `# -*- coding: utf-8 -*-`, тайп-хинты, `ctx: Context = None` последним,
докстринг как контракт для модели.

См. [[Паттерн регистратора инструментов с инъекцией транспорта]] и
[[Докстринг инструмента — это контракт для модели, а не для разработчика]].

### 4. Регистрация инструмента — `tools/__init__.py`

Дописать импорт **и** вызов в `register_tools()`. Внимание: число аргументов зависит от
того, что модуль использует.

### 5. (плюс) README

Обновить количество инструментов и каталог. Сейчас там 48.

## Почему четыре, а не одно

Регистрация ведётся двумя рукописными списками — см.
[[Регистрация ведётся двумя рукописными списками]]. Автообнаружение через
`pkgutil.iter_modules` возможно (соглашение об именах строгое), но не сделано.

> [!warning] Забытая строка не даёт ошибки
> Модуль просто не регистрируется. Инструмент не появится у клиента, маршрут ответит
> 404, и ничто в логах на это не укажет. Проверка после добавления — вызвать инструмент
> через `mcp dev main.py`.

## Проверочные вопросы перед коммитом

- Все координаты и размеры конвертированы мм → футы? ([[Все инструменты принимают миллиметры, Revit внутри считает в футах]])
- `suppress_warnings(t)` стоит сразу после `t.Start()`? ([[Каждая транзакция глушит модальные диалоги Revit]])
- ElementId только через хелперы, без `.IntegerValue`? ([[ElementId читается и создаётся только через хелперы]])
- Текстовый path-параметр прогнан через `unquote`? ([[get_view возвращал 404 на именах видов с пробелами]])
- Пакетная операция возвращает список пропущенных? ([[Пакетные операции возвращают success, скрывая пропущенные элементы]])
- Дефолт выбран по признаку, а не «первый из коллектора»? ([[create_surface по умолчанию попадал на Foundation Slab вместо перекрытия]])
- Поведение соседних инструментов с тем же параметром такое же? ([[Балки садились на Z=0 вместо отметки уровня]])

## Куда что кладётся

| Что | Куда |
|---|---|
| Общие хелперы Revit | `revit_mcp/utils.py`, импорт `from utils import ...` |
| Общие хелперы MCP | `tools/utils.py`, импорт `from .utils import ...` |
| Новый домен, Revit | `revit_mcp/<домен>.py` |
| Новый домен, MCP | `tools/<домен>_tools.py` |
| Тест | `tests/unit/test_<тема>.py`, pytest (устарело: было `tests/test_<тема>.py`, stdio-скрипт) |
| Проверки конвенций | `scripts/conventions.py` — единственный источник для теста, приёмки и набора разработчика |
