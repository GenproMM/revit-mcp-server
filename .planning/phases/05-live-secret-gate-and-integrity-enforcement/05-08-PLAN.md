## Share layout after this plan

    <MCP_SHARE_ROOT>\ext\<MCP_EXT_NAME>\           live; pyRevit loads this over UNC (the only folder in its search path)
    <MCP_SHARE_ROOT>\ext-staging\<MCP_EXT_NAME>\   build in progress; never registered with pyRevit
    <MCP_SHARE_ROOT>\ext-previous\<MCP_EXT_NAME>\  the build before the live one (one version kept)
    <MCP_SHARE_ROOT>\ext-rejected\<MCP_EXT_NAME>\  the build a rollback took out of service

`ext`, `ext-staging`, `ext-previous` and `ext-rejected` are siblings under one share root, so `move` is a
rename on one volume (RESEARCH A7: a DFS namespace spanning folder targets is not verified; the pilot
probe covers it).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build server -> share `ext\` | every workstation loads this folder at its next Revit start |
| developer working tree -> junction-loaded extension | a manifest in the repo root decides whether the developer's own mutations are blocked |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-32 | Denial of service | Revit starting mid-publish loads a half-built extension (WR-02) | high | mitigate | build and gate in ext-staging, swap by rename (Task 1) |
| T-05-33 | Denial of service | swap failure destroying the live extension | high | mitigate | move live aside first (failure changes nothing), restore previous if the second move fails; in-use row (Task 2) |
| T-05-34 | Tampering | a staged tree whose manifest or secret is wrong reaching ext | high | mitigate | --check verified_match and secret_tool verify gate the swap (Task 1) |
| T-05-35 | Tampering | developer manifest committed or written in a subfolder | medium | mitigate | --allow-repo-dest only at the repo root and only when git-ignored (Task 3) |
| T-05-36 | Information disclosure | stale secret copy in ext-previous / ext-rejected after a rotation | medium | mitigate | documented in the rotation procedure (plan 05-10); folders sit under the same access-controlled share root |
| T-05-37 | Tampering | a test publishing to the real share | high | mitigate | _assert_scratch extended to every new target before any spawn (Tasks 1-2) |
</threat_model>
