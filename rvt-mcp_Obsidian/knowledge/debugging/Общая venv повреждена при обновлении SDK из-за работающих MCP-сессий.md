# Общая venv повреждена при обновлении SDK из-за работающих MCP-сессий

## Симптом и причина

Во время 07-01 после одобрения обновления MCP 1.9 → 1.30 команда `uv sync --group dev` столкнулась с `Access denied (os error 5)` при удалении файлов. Около 15 процессов MCP других сессий использовали общую `.venv`. Обновление остановилось посередине; обычное окружение нельзя считать исправным.

`uv pip check` подтвердил четыре неполных пакета (METADATA/RECORD): `mcp-1.9.0`, `typer-0.15.4`, `typing_inspection-0.4.0`, `ruamel_yaml-0.19.1`.

## Проверенный обход

Здоровое окружение создано из frozen lock с dev-группой вне репозитория через `UV_PROJECT_ENVIRONMENT`. Все последующие офлайн проверки прошли там; последнее независимое подтверждение после волны 3: **6624 passed, 3 skipped**, exit 0.

Путь и точка продолжения: [[2026-10-25 — исполнение фазы 7, шесть планов завершены, продолжить с 07-06]]. Временный путь не является постоянной инфраструктурой: перед использованием проверить наличие окружения и версию MCP.

## Ограничения восстановления

- Не повторять sync в общей `.venv`, пока работающие с ней сессии не закрыты по согласованию с пользователем.
- Не завершать чужие процессы и не удалять заблокированные файлы автоматически.
- Временное окружение не исправляет общую `.venv`; не объявлять обновление обычного окружения успешным.
- После согласованного закрытия потребителей восстановление общей `.venv` — отдельная операция с проверкой зависимостей и unit-suite.
