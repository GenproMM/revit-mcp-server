# Под замок все маршруты кроме status, одна общая запись сервера без копий

Решения пользователя на чекпоинте плана 01-04 после живого стенда. Записаны в
`.planning/phases/01-serialization-and-configurable-addressing/01-04-SUMMARY.md`.

## D-27 → d27-b, позже d27-c

Стенд показал подмену ответов в общем обработчике pyRevit (см.
[[Пересекающиеся запросы pyRevit получают чужой ответ, а их код не выполняется]]).

- **Сейчас (d27-b):** все маршруты, идущие через обработчик Revit, берут замок `bridge.py`.
  Исключение только `/status/`: его измерили, он мимо очереди. `/model_info/` план тоже
  освобождал, но его не измеряли, поэтому он остаётся под замком. Allowlist D-08 убирается или
  пересматривается, смысл SER-02 меняется: чтения ждут изменений.
- **Позже (d27-c):** исправление на стороне Revit. Только оно закрывает пересечение между
  разными процессами сервера.
- По плану d27-b означает **остановку фазы 1 на перепланирование** (`/gsd-plan-phase 1 --gaps`).

## A5 → a5-a, одна общая запись сервера

У всех пользователей одна запись `revit` MCP-сервера, копии (`revit-a` / `revit-b`) делать
нельзя, и так должно остаться. Поэтому D-03 («два Revit = две записи») пользователям
недоступно.

- SC5 засчитывается по `tests/test_two_instance_targets.py` (`TWO_INSTANCE_OK` на стенде),
  отклонение от формулировки «один сеанс ассистента» записано.
- Схему «две записи» в пользовательской документации не описывать. План 01-05 переписать.
- `REVIT_PORT` остаётся настройкой «к какому Revit идёт этот сервер».
- Выбор Revit в каждом вызове внутри одного сервера переносится в Phase 2 (IDENT-01), с
  отдельным замком на каждый Revit.
