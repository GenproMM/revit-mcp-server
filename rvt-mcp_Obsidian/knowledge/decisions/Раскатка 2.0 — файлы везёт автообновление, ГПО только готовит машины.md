# Раскатка 2.0 — файлы везёт автообновление, ГПО только готовит машины

## Контекст

У пользователей сборка 09.17 с `\\srv-dfs\BIM\06_RevitMCP`. Payload у них обновляет задача «RevitMCP Update»/ярлык (`update.cmd` при входе), расширение Revit грузит с share при каждом полном перезапуске, запись Гены не меняется. Значит, публикация 2.0 в основную раздачу доставит файлы сама.

## Решение

Групповая политика — только скрипт входа `deploy/gpo-prep.ps1` (инструкция администратора — `deploy/GPO-ROLLOUT.md`). Он, лишь при установленном RevitMCP и закрытом Revit:
1. IPY2712 → `pyrevit attach <clone> 342 --attached` (решение пользователя: переключать, а не останавливаться — IPY342 стандарт парка);
2. добавляет `host = "127.0.0.1"` в `[routes]`, если строки нет (с копией конфига);
3. запускает `update.cmd` раздачи, **только если** наше расширение зарегистрировано с неё же — иначе тестировщик пилота получил бы основной payload с другим секретом (401).

Журнал `%LOCALAPPDATA%\RevitMCP\gpo-prep.log`, режим `-DryRun`. Включать за неделю до публикации 2.0: для 09.17 изменения безвредны. Задержка скриптов входа по умолчанию 5 минут — открыт Revit → скрипт ждёт следующего входа.

## Порядок выпуска

Пилот принят → тег `release/2.0.0` на коммит rc → сборка под `chcp 866` с основным секретом (у 09.17 его нет — создастся, сохранить на share) → публикация вне рабочего времени обеих половин (адреса `/revit_mcp/` и `/genpro_revit_mcp/` различаются, смешанное состояние временно даёт «Route does not exist») → сообщение: Update RevitMCP → перезапуск Гены → полный перезапуск Revit → проверка `get_revit_status`.
