<objective>
Move the transport out of `main.py` into a new root module `bridge.py` and serialize every
mutating POST issued through this MCP server process behind one module-global
`asyncio.Lock`, then make the pyRevit Routes port a deployment setting (`REVIT_PORT`) that is
parsed strictly and refuses to start on a bad value.

Purpose: SER-01 (mutations from this server never reach Revit's single-threaded API in
parallel) and IDENT-05 (the target port is configurable) are the two foundations every other
plan in this phase builds on. Scope stays CPython-side per D-01 — no file under `revit_mcp/`
changes and no Revit restart is needed for this plan.

Output: `bridge.py`, a slimmed `main.py`, `tests/unit/test_bridge_serialization.py`, and the
two source-text tests retargeted at `bridge.py`.
</objective>

<assumption_delta_decision>
Detector signals: pluralization ("second" Revit instance, second waiting call) and chosen
(the port goes from a constant to a parameter).

- **Primary noun:** the Revit *target* = `REVIT_HOST:REVIT_PORT`, exactly one per MCP server
  process (D-02), exposed as `bridge.REVIT_TARGET` and `revit_get.revit_target`.
- **Decision:** `promote`. The configured target replaces the hardcoded `48884` as the
  identity that the transport (`BASE_URL`), the lock (D-07: one lock per target, and one target
  per process means one module-global lock) and `get_revit_status` (D-06, plan 01-03) are keyed
  on. `48884` is demoted to `DEFAULT_REVIT_PORT`, the default of one variant. Nothing is added
  alongside: no code path keeps a literal port.
- **Second waiting call:** the lock *is* the queue; `asyncio.Lock` waiters are FIFO. No
  `RevitTarget` registry and no discovery (D-04, D-07; registry/discovery are Deferred Ideas in
  CONTEXT.md). This reflects the identity model CONTEXT.md already decided — one MCP entry =
  one Revit instance — and does not relitigate it.
- **Known limit, recorded not reopened:** `host:port` names a launch slot, not a Revit process
  or a document (RESEARCH Pitfall 10). Phase 2 promotes the identity again to process identity
  (PID + session token, IDENT-01..04).
- **Invariant test (accepted, Task 2):** `test_port_literal_only_in_default` fails the moment
  a second literal `48884` reappears in `bridge.py`; `test_port_reaches_base_url` proves the
  configured value is what the client actually dials.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client config env → MCP server process | `REVIT_HOST` / `REVIT_PORT` come from the MCP client's config block (operator-controlled, typo-prone) |
| MCP server process → pyRevit Routes (loopback HTTP) | every mutation crosses here; pyRevit shares one request handler across HTTP threads |
| MCP server stdout → MCP client | the stdio protocol stream; any stray byte corrupts it |
