<objective>
Give the confirmation window exact, cheap, read-only facts from Revit (D-09): one shared lookup helper so the
check and the mutation resolve the same element, parameter, definition and family, and one open POST read,
`/mutation_preflight/`, that answers for the six confirm/check routes what the mutation would touch, saying
"unknown" where an exact answer is not available.

Purpose: SAFE-05 (facts for the window) and SAFE-07 (the D-10 conditions need real facts). The preflight is a
bridge-internal read (no MCP tool, the manifest stays at 59). One route rather than three keeps the pinned
inventory change to one entry (Claude's discretion on how many preflight routes; parity comes from the shared
helper module, not from colocation).

Output: `revit_mcp/lookup.py`, refactored lookups in three domain modules, `revit_mcp/preflight.py`, the pins,
tests.
</objective>

## Execution rules for every task in this plan

- Every `revit_mcp/` file is IronPython 3.4 dialect: encoding cookie, `"{}".format`, no f-strings, relative
  sibling imports (`from .lookup import ...`, `from .utils import ...`), never import one domain module from
  another (lookup.py is a helper: no register_*_routes), ElementId only through `make_element_id` /
  `get_element_id_value`, names through `sanitize_string` / `get_element_name`, POST bodies only through
  `parse_request_data`, route handlers never raise and answer with `routes.make_response`.
- The preflight is a read: no `DB.Transaction`, `Delete`, `Save`, `EditFamily`, `LoadFamily`, `Open*`,
  activation or UI switch.
- Never start or reload Revit and never call a live route; live verification is the user-run bench (07-14)
  after a full Revit restart.
- Commit protocol as in 07-01 (pathspec commits; full suite green before each commit). Prefix
  `refactor(07-10):` / `feat(07-10):` / `test(07-10):`.
