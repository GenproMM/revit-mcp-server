# Requirements: revit-mcp-server — milestone v0.1 «Доверенный мост»

**Defined:** 2026-09-21
**Core Value:** Ассистент может достоверно читать и изменять модель Revit — и инженер может доверять тому, что ответ сервера описывает то, что действительно произошло.

## v1 Requirements

Требования этого milestone. Каждое отображается в фазу дорожной карты.

### Идентичность (IDENT)

- [ ] **IDENT-01**: `/status/` возвращает идентичность процесса Revit — PID, версию Revit, порт и токен сессии, выданный один раз при запуске процесса
- [ ] **IDENT-02**: Каждый ответ мутирующего маршрута называет документ, который он изменил (заголовок и путь), а не только результат операции
- [ ] **IDENT-03**: Идентичность документа разрешается на момент запроса, а не берётся из кэша — остаётся корректной после `OpenAndActivateDocument` и при смене активного документа пользователем в UI
- [ ] **IDENT-04**: Два документа с одинаковым заголовком (два `Project1`) различимы по полям ответа
- [ ] **IDENT-05**: Порт pyRevit Routes настраивается переменной окружения `REVIT_PORT`, как сейчас настраивается только хост

### Разрешение неоднозначности (AMBIG)

- [ ] **AMBIG-01**: Наличие двух слушателей на одном порту обнаруживается до отправки запроса
- [ ] **AMBIG-02**: При обнаружении двух слушателей сервер отказывает явной ошибкой вместо обращения к недетерминированно выбранному процессу
- [ ] **AMBIG-03**: Инженер видит в сообщении об отказе, какие именно процессы конфликтуют (PID), чтобы закрыть лишний
- [ ] **AMBIG-04**: Репродукция `param-write-rolls-back` повторно проверяема при видимой идентичности — гипотеза «отвечал другой процесс» становится подтверждаемой или опровергаемой

### Мультидокумент (MDOC)

- [ ] **MDOC-01**: Инженер может получить список открытых в сессии Revit документов с идентичностью каждого
- [ ] **MDOC-02**: Мутирующий инструмент принимает явный идентификатор документа в вызове
- [ ] **MDOC-03**: Мутирующий вызов без явного документа не угадывает молча — поведение по умолчанию явно определено и описано в докстринге инструмента
- [ ] **MDOC-04**: Инженер может переключить активный документ отдельным инструментом
- [ ] **MDOC-05**: Обращение к документу, закрытому после получения списка, даёт понятную ошибку, а не работу не с тем документом

### Секрет и сеть (SEC)

- [ ] **SEC-01**: Мутирующие маршруты требуют общий секрет; запрос без верного секрета отклоняется до открытия транзакции
- [ ] **SEC-02**: Секрет едет в теле запроса по уже доказанному пути `text/plain` + `parse_request_data()`, без нового непроверенного кода разбора
- [ ] **SEC-03**: Отказ по секрету возвращает не-200 и доходит до модели как видимая ошибка, а не как ложный успех
- [ ] **SEC-04**: Сравнение секрета выполняется за постоянное время на обеих половинах моста
- [ ] **SEC-05**: Читающие маршруты и `/status/` остаются доступны без секрета — диагностика не блокируется рассогласованием секрета
- [ ] **SEC-06**: Секрет не попадает ни в журнал аудита, ни в лог, ни в текст ошибки
- [ ] **SEC-07**: Расширение обнаруживает бинд Routes не на loopback и сообщает об этом как о небезопасной конфигурации
- [ ] **SEC-08**: Секрет генерируется и внедряется в payload на этапе сборки; обе половины моста получают согласованную пару

### Целостность (INTG)

- [ ] **INTG-01**: Манифест файлов расширения с хешами формируется при сборке payload
- [ ] **INTG-02**: Расхождение файлов `revit_mcp/` с манифестом обнаруживается при загрузке расширения
- [ ] **INTG-03**: Проверка целостности не пишет файлы — только обнаруживает и сообщает
- [ ] **INTG-04**: При обнаружении расхождения мутации отклоняются, чтение и диагностика продолжают работать
- [ ] **INTG-05**: `/status/` называет конкретные разошедшиеся файлы, чтобы инженер знал, что переустанавливать
- [ ] **INTG-06**: Проверка не даёт ложных срабатываний на `__pycache__`, `.pyc`, переводах строк и артефактах редактора
- [ ] **INTG-07**: Недоступность источника эталона не приравнивается к повреждению — состояние сообщается отдельно и не блокирует запуск
- [ ] **INTG-08**: На машине разработчика, где расширение это junction на репозиторий, проверка не мешает работе

### Сериализация (SER)

- [ ] **SER-01**: Мутирующие вызовы этого MCP-сервера не уходят в Revit параллельно
- [ ] **SER-02**: Удержание очереди мутацией не блокирует `/status/` и читающие вызовы
- [x] **SER-03**: Исключение, таймаут или отмена внутри сериализованного участка освобождают очередь
- [x] **SER-04**: Ожидание в очереди не приводит к тому, что вызов получает меньше своего бюджета времени
- [ ] **SER-05**: Область действия сериализации документирована честно — она покрывает вызовы этого процесса и не является гарантией против второго клиента

### Честный результат (TRUTH)

- [ ] **TRUTH-01**: Все мутирующие маршруты сообщают реальный `TransactionStatus`, а не предполагаемый успех
- [ ] **TRUTH-02**: `delete_elements` и `export_ifc` переведены на `commit_and_report` — закрытие двух известных оставшихся пропусков
- [ ] **TRUTH-03**: Пакетные операции возвращают пропущенные и сбойные элементы рядом с успешными, а не только счётчик
- [ ] **TRUTH-04**: Частичный отказ пакетной операции имеет собственный явный статус, отличимый и от успеха, и от полного отказа

### Аудит (AUDIT)

- [ ] **AUDIT-01**: Каждая мутация записывается в локальный структурный журнал JSONL
- [ ] **AUDIT-02**: Запись содержит время, инструмент, маршрут, идентичность документа, затронутые элементы и исход
- [ ] **AUDIT-03**: Записывается фактический исход, а не намерение — откат пишется как откат, частичный пропуск как частичный пропуск
- [ ] **AUDIT-04**: Один вызов инструмента связывается со своими записями общим идентификатором
- [ ] **AUDIT-05**: Журнал не ломает stdio-транспорт — ничего не пишется в stdout
- [ ] **AUDIT-06**: Журнал не повреждается при двух одновременно работающих экземплярах Revit
- [ ] **AUDIT-07**: Рост журнала ограничен
- [ ] **AUDIT-08**: Журнал не содержит секрета и не содержит лишних персональных данных

## Future Requirements

Признано, но отложено. Не входит в дорожную карту этого milestone.

### Политика и подтверждение (POLICY)

- **POLICY-01**: Конфигурируемая политика разрешений, вшитая в payload при сборке
- **POLICY-02**: Разрушительная операция возвращает preview — точный список того, что изменится — и одноразовый токен
- **POLICY-03**: Применение требует второго вызова с полученным токеном
- **POLICY-04**: Права администратора контролируются автором проекта через конфиг в репозитории на сервере

### Идемпотентность (IDEM)

- **IDEM-01**: Мутирующий вызов принимает ключ идемпотентности
- **IDEM-02**: Повтор вызова с тем же ключом не выполняет операцию дважды
- **IDEM-03**: Клиент может отличить «не дошло» от «дошло, применено, ответ потерян»

### Восстановление целостности (RESTORE)

- **RESTORE-01**: Отдельный скрипт восстанавливает разошедшиеся файлы при закрытом Revit
- **RESTORE-02**: Восстановление атомарно — частично скопированный файл не подменяет рабочий

### Гигиена ответов (HYG)

- **HYG-01**: Traceback не возвращается клиенту (36 мест в 17 модулях); логируется, наружу идёт корреляционный идентификатор
- **HYG-02**: Потолки на размер партии в мутирующих маршрутах
- **HYG-03**: Защита от перезаписи файлов при экспорте и SaveAs
- **HYG-04**: Валидация путей на границе маршрутов

## Out of Scope

Явно исключено. Записано, чтобы не возвращаться без решения.

| Feature | Reason |
|---------|--------|
| Самовосстановление файлов в рантайме | Запись файлов под работающим движком pyRevit — документированный путь к краху Revit; изнутри `startup.py` перезапуск процесса и Reload неразличимы, а на dev-машине с junction восстановление затрёт незакоммиченную работу. Перенесено в RESTORE-01 как отдельный офлайн-скрипт |
| Защита от целенаправленного локального обхода | Модель угрозы — случайная перезапись файлов инженером, не злоумышленник за консолью станции |
| Уникальный секрет на станцию | Секрет вшивается в payload при сборке, один payload на парк. Рубеж сетевой, не локальный |
| Позиция в очереди и ETA при ожидании | Ни одна сопоставимая система (Selenium, Jupyter) этого не делает для одного бэкенда; блокирующее ожидание с таймаутом — норма экосистемы |
| Полная интеграция OpenTelemetry SDK | Одно-процессный настольный инструмент; заимствуется только форма корреляционного идентификатора, не коллекторы и экспортёры |
| Поэлементная история изменений уровня worksharing Revit | Погоня за гранулярностью, которой не даёт сам Revit; маршрутный уровень с ElementId уже не грубее родной истории |
| Подпись кода (Authenticode) вместо манифеста хешей | Проверка подписи в .NET по умолчанию не блокирующая — сама по себе не даёт отказа при подмене; манифест с хешами решает задачу без инфраструктуры подписи |
| Расщепление `revit_mcp/colors.py` | Фоновый долг, не блокирует фундамент |
