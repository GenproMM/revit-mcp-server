## The status contract (defined here; the live runner 05-11/05-12 reads these names)

- `trust.secret_fingerprint(secret)`: for a value `check_secret` would accept as configured (text or
  bytes of at least MIN_SECRET_LENGTH once stripped), `hashlib.sha256(<UTF-8 bytes>).hexdigest()[:8]`;
  otherwise None. Never raises.
- `security.status_block(port, listeners=None)` returns
  `{"secret": {"configured": <bool>, "fingerprint": <8 hex or None>}, "integrity": <the load-time result
  dict, or unverifiable/read_error when the state is not initialized>, "bind": <classify_listeners
  verdict>}`. `listeners` is a zero-argument callable returning `(host text, port)` pairs; the default
  `_dotnet_listeners()` imports `System.Net.NetworkInformation.IPGlobalProperties` inside the function
  and builds `(str(ep.Address), int(ep.Port))` from `GetIPGlobalProperties().GetActiveTcpListeners()`;
  any exception yields None, which classify_listeners reports as unknown. Never raises.
- `trust.security_alerts(block)` returns a list of plain sentences, empty unless integrity is
  verified_mismatch (naming the files and saying mutations are refused with 423 until the extension is
  reinstalled and Revit fully restarted), bind is exposed (Routes listens beyond loopback; the secret is
  the only network barrier; mutations are not blocked), or the secret is not configured (every mutation
  is refused with 401 server_not_configured). Pure, never raises.
- `/status/` 200 and 503 replies gain the three block keys plus `security_alerts` (only when non-empty);
  `health` is "degraded" when registry.is_degraded(), an identity error, or a non-empty
  security_alerts; the 503 branch gains `health` too. No top-level `error` key is added for a
  degraded state; the 503 body keeps its existing `error: "No active Revit document"`.
- Bridge: `secret_fingerprint(secret)` duplicates the trust rule on purpose (the payload ships no
  revit_mcp package; a test pins the parity, like `_secret_from_bytes`); `loaded_secret_fingerprint()`
  returns `secret_fingerprint(_secret())`; `revit_get.secret_fingerprint = loaded_secret_fingerprint`
  beside the existing `revit_target` and `discover_targets` seams.
- Comparison line in get_revit_status, inserted right after the formatted status text and before the
  "MCP target:" line, built from `tools.utils._body_of(response)` (dict reply or the JSON of an
  "Error: 503 - ..." text) and `getattr(revit_get, "secret_fingerprint", None)`. No line at all when the
  reply has no `secret` block and the transport exposes no fingerprint (keeps every existing exact-text
  test unchanged). Wording (Claude's discretion): "Shared secret: both halves hold the same secret
  (fingerprint {fp})." / "Shared secret: the halves DIFFER (Revit {a}, this MCP server {b}); every
  mutation is refused with 401 mismatch until both come from the same build: run Update RevitMCP,
  restart the assistant session, then fully restart Revit." / "Shared secret: the Revit extension has
  none; every mutation is refused (401 server_not_configured)." / "Shared secret: this MCP server loaded
  none; every mutation is refused (401 missing): run Update RevitMCP (or sign out of Windows and back
  in) and restart the assistant session." / "Shared secret: the Revit extension does not report its
  secret state (an extension older than R3)."
