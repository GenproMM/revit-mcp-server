# 2026-09-08 — семь пользовательских сценариев на живой модели, детач-open, edit_family, фикс section-view и unicode-пробника

## Контекст задачи

Сессия началась вечером 2026-09-07 и продолжилась за полночь на 2026-09-08
(Revit-перезапуски в логе — от 23:00 до 00:20). Пользователь поставил задачу
без доступа к серверам компании: MCP указывает на этот же локальный
репозиторий (не оригинальный форк), и нужно прогнать семь реальных
пользовательских сценариев на живом Revit:

1. открыть модель с детачем и сохранить рабочие наборы
2. прочитать параметры выбранного элемента
3. записать параметры элементу
4. создать виды (план, секция, спецификация)
5. создать новые элементы
6. переместить существующий элемент
7. отредактировать загруженное семейство и загрузить его обратно в проект

Изначально пришёл как `/gsd-add-tests` (тестовый уровень для завершённой
фазы) — но `.planning/STATE.md`/`ROADMAP.md` в проекте нет, GSD-воркфлоу
неприменим. Пользователь прислал реальную задачу сразу вслед за этим, она и
стала содержанием сессии.

## Что сделано

### Диагностика окружения перед тестами

Revit не был запущен (`REVIT_HOST`), pyRevit подключен только к 2024.3.3 и
2027 — не к 2025; тестовые модели на диске все R24, значит цель — Revit
2024. `.claude.json` держал `revit` MCP-сервер только под записью с
заглавной `C:/…`, сессия матчилась на строчную `c:/…` — сервер не
подхватился. Файл пропатчен (с бэкапом), нужен перезапуск сессии Claude Code,
чтобы `mcp__revit__*` появились в следующий раз.

### Найдены и исправлены три реальных бага

Все три подробно разобраны отдельными заметками:

- [[pyRevit определяет unicode как алиас str в IronPython 3, ломая NameError-проверку]] —
  **блокировал весь POST-трафик**, включая уже существовавший `/execute_code/`.
  Самая важная находка сессии.
- [[create_view section — direction cross up давал левосторонний базис и пустое исключение]] —
  секции не создавались вообще никогда, при любом входе.
- [[SaveAs детач-модели требует WorksharingSaveAsOptions.SaveAsCentral]] —
  половина сценария 1 («сохранить рабочие наборы») была недостижима без
  этого фикса.

Плюс окружное наблюдение, не баг кода:
[[Два процесса Revit.exe могут слушать 48884 одновременно без ошибки]].

### Добавлены три новых инструмента (51 → 54)

- `open_model` / `list_model_worksets` (`revit_mcp/worksharing.py`,
  `tools/worksharing_tools.py`) — см. [[open_model закрывает воркседы по
  паттерну имени, переиспользуя конфигурацию из скилла
  revit-open-links-closed]]. Паттерн конфигурации воркседов переиспользован
  из приватного скилла `revit-open-links-closed`
  (`GenproMM/MastermindServices`, ветка `master`), написанного для другого
  MCP-сервера компании (`genpro-revit-mcp`, модели `RSN://`) — сама
  конфигурация API не зависит от источника модели.
- `edit_family` (`revit_mcp/placement.py`) — открывает загруженное семейство,
  меняет/добавляет тип, грузит обратно через `IFamilyLoadOptions`, чтобы не
  упереться в диалог «семейство уже загружено». Значения параметров
  конвертируются в единицы Revit по `ForgeTypeId` самого параметра
  (`DB.UnitUtils.ConvertToInternalUnits`), а не слепым коэффициентом мм→футы
  — семейство держит рядом с длинами углы и голые числа.

Оба зарегистрированы в `tests/unit/tool_manifest.txt`; `scripts/conventions.py`
и полный юнит-набор (300 тестов) зелёные.

### Прогон всех семи сценариев на реальной модели

Копия `SRB_02_AR_PD_R24…отсоединено_maggenda.rvt` (98 МБ, уже отсоединённая,
13 рабочих наборов) скопирована в scratch-папку сессии. Каждый сценарий
проверен HTTP-вызовом маршрута и **независимой** проверкой результата
(повторное чтение параметра после записи, координаты стены до/после
перемещения через `execute_code`, состав типов семейства через
`GetFamilySymbolIds` вместо капнутого на 50 записей `list_families`):

| # | Сценарий | Результат |
|---|---|---|
| 1 | Детач + сохранение воркседов | ✅ 21 с, без диалога; сохранённый файл содержит все 13 наборов |
| 2 | Чтение параметров выбранного элемента | ✅ 81 параметр, кириллица и `GP_*` целы |
| 3 | Запись параметра | ✅ подтверждено повторным чтением |
| 4 | Виды: план / секция / спецификация | ✅ план и спецификация сразу; секция — после фикса |
| 5 | Создание элемента | ✅ стена создана |
| 6 | Перемещение элемента | ✅ Y 0→3000 мм точно |
| 7 | Редактирование семейства + перезагрузка | ✅ новый тип подтверждён в проекте напрямую через API |

Побочная находка при верификации сценария 7: `list_families` жёстко режет
список на 50 типов (уже задокументировано в докстринге инструмента) —
собственный первый прогон верификации ошибочно принял это за провал
(семейство было `Системная панель`, системное, `edit_family` корректно
отклонил его 400-м).

## Открытые вопросы / долг

- `.claude.json` пропатчен, но не проверен живым перезапуском сессии — в
  следующем разговоре стоит подтвердить, что `mcp__revit__*` появились.
- `edit_family` не проверен на реальном изменении *значения* параметра типа
  (только на создании нового типа) — стоит прогнать отдельно, когда
  понадобится реальный кейс правки размера семейства.
- Пункт 8 в [[Текущие приоритеты]] («портировать `open_revit_server_model` из
  `GenproMCP`») остаётся отдельной задачей — `open_model` решает похожую, но
  не идентичную потребность (локальные файлы, не `RSN://`).
