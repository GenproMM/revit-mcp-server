<objective>
Build the human-run live gate for the two criteria that cannot be proven offline: a real Revit
rollback and a real partial batch recorded truthfully (ROADMAP criterion 2), and two Revit instances
mutated simultaneously through one server process plus a second server process without corrupting or
mixing entries (criterion 5). The same record also gives a live look at criteria 1 and 7. The script
is one-shot like Phase 4's: a write is never repeated, everything is judged by a pure classifier from
the record and the audit files, and nothing is judged by eye.

Purpose: D-20 (live bench, human-run, write steps one-shot), D-19's live counterpart, research
Pitfall 18 and assumption A3 (the rollback trigger is rehearsed before the gate). This plan only
builds and unit-tests the runner; 06-07 is the human run.

Output: `tests/test_phase6_live_audit.py` and its unit twin `tests/unit/test_phase6_live_audit.py`.
</objective>

## Execution rules for every task in this plan

- The script is ordinary CPython (it never runs in Revit). It must define no `test_*` function and
  do nothing at import (no bridge import, no env change, no I/O), so the unit suite can import its pure
  functions. Imports of `bridge`, `main` and `audit` happen inside the command functions, after
  REVIT_MCP_AUDIT_DIR is set.
- The script names only these routes for reads: /status/, /documents/, /element_properties/; and only
  these tools for writes: execute_revit_code, tag_elements, set_parameter. A call outside the lists is
  refused before anything is sent (pattern `_require_allowed` of the Phase 4 script). It never saves
  a document, never opens a model, never reads, prints or records the secret.
- No live Revit is used while building this plan; every check here is offline.
- Commit protocol as in 06-01; prefixes `test(06-06):`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live runner -> real Revit instances | write steps change scratch models on the engineer's bench |
| live runner -> local disk | the record and the audit directory hold ports, ids, paths and user names of a workstation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-29 | Information disclosure | secret in the record or console | high | mitigate | the secret is read only through bridge._secret() for the occurrence count; only SECRET_OCCURRENCES=<n> is printed; classifier reasons never include it (Tasks 1-2) |
| T-06-30 | Tampering | a write step repeated on the model | medium | mitigate | posts_sent counted before each call, records never overwritten, the procedure forbids a rerun once POSTS_SENT >= 1 (Tasks 1-2) |
| T-06-31 | Information disclosure | record or audit dir inside the repository | medium | mitigate | refusals for --out and --audit-dir inside the repository, before any request (Task 1) |
| T-06-32 | Tampering | a write to the wrong Revit instance | medium | mitigate | preflight requires exactly one listener (single) or exactly two usable targets (dual); every write names its selector (Task 2) |
| T-06-33 | Denial of service | a rehearsal that commits real changes | low | mitigate | rehearse reports REHEARSAL_COMMITTED; the procedure requires rollback code that makes no model change of its own besides posting the failure, in a scratch model that is never saved (Task 2) |
</threat_model>
