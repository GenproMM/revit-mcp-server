# Паттерн обработчика маршрута — валидация, транзакция, сериализация

## Форма

Три фазы в одном теле, и всё целиком в `try/except`. Обработчик **никогда** не
выбрасывает наружу.

```python
@api.route("/delete_elements/", methods=["POST"])
def delete_elements_handler(doc, request):
    """Что делает + ожидаемый payload."""
    try:
        # ── 1. Валидация ──
        if not doc:
            return routes.make_response(
                data={"error": "No active Revit document"}, status=503)

        data = {}
        if request and request.data:
            data = json.loads(request.data) if isinstance(request.data, str) else request.data

        element_ids = data.get("element_ids")
        if not element_ids:
            return routes.make_response(
                data={"error": "No element_ids provided"}, status=400)

        # ── 2. Транзакция ──
        t = DB.Transaction(doc, "MCP: Delete Elements")
        t.Start()
        suppress_warnings(t)          # ← сразу после Start(), обязательно
        try:
            ...  # правки модели
            t.Commit()
        except Exception as tx_error:
            if t.HasStarted() and not t.HasEnded():
                t.RollBack()
            raise tx_error

        # ── 3. Сериализация ──
        return routes.make_response(data={
            "status": "success",
            "deleted_count": len(deleted),
            "message": "Deleted {} element(s)".format(len(deleted)),
        })

    except Exception as e:
        logger.error("delete_elements failed: {}".format(str(e)))
        return routes.make_response(
            data={"error": str(e), "traceback": traceback.format_exc()}, status=500)
```

## Почему обработчики длинные

50–150 строк — норма, потому что валидация, транзакция и сериализация живут вместе.
Извлекать в приватные `_helpers` стоит, когда разрастается **ветвление**: разрешение
категорий, геометрическая математика, описание элемента.

## Разбор payload

Каждый обработчик парсит вручную, никаких pydantic-моделей на Revit-стороне:

```python
data = json.loads(request.data) if isinstance(request.data, str) else request.data
```

Двойная форма нужна, потому что pyRevit отдаёт `request.data` то строкой, то уже
разобранным словарём.

Валидация — проверки наличия ключей и `isinstance`-гварды. Границы списков и корректность
ID **не проверяются** — это известная дыра.

## Правила транзакции

1. `suppress_warnings(t)` **сразу** после `t.Start()` — см.
   [[Каждая транзакция глушит модальные диалоги Revit]].
2. Внутренний `try/except` с `RollBack()` при `HasStarted() and not HasEnded()`.
3. Исключение перебрасывается наружу, где его подхватит внешний `except` и превратит
   в 500.

Исключения из правила: `Save`/`SaveAs` и `LoadFamily` работают **вне** транзакции —
см. [[Save и SaveAs выполняются вне транзакции]].

## Известные проблемы этого паттерна

- **`traceback.format_exc()` уходит клиенту** — раскрывает абсолютные пути и версии.
  Логировать надо, отдавать — нет.
- **Пакетные пропуски невидимы** — см.
  [[Пакетные операции возвращают success, скрывая пропущенные элементы]].
- **Нет пагинации** у читающих маршрутов: коллекторы материализуются целиком через
  `list(...)`.
