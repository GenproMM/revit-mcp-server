# Набор разработчика инструментов Revit MCP

Как добавить свой инструмент в RevitMCP, не имея доступа к репозиторию сервера.

## Что нужно

- **Revit с открытой моделью и установленный RevitMCP.** Тот самый, штатный —
  ничего дополнительно ставить не надо.
- **Python 3.** Подойдёт любой, включая тот, что приносит с собой pyRevit:
  `%APPDATA%\pyRevit\bin\cengines\CPY*\python.exe`. Набор работает только на
  стандартной библиотеке: ни `uv`, ни `pytest`, ни интернета.
- **Kilo Code в VS Code** (или Hermes). Правила для ассистента лежат в
  `AGENTS.md` рядом и подхватываются автоматически.

Проверить, что мост жив: откройте в браузере
`http://localhost:48884/revit_mcp/status/`. Пусто — Revit закрыт или расширение
не загрузилось.

## Четыре команды

```bash
python revitmcp_kit.py new <domain> <tool> [--get]   # создать каркас
python revitmcp_kit.py check                          # проверить конвенции
python revitmcp_kit.py probe                          # прогнать на своём Revit
python revitmcp_kit.py pack                           # собрать пакет для сдачи
```

`<domain>` — тема инструмента (`wall_report`, `audit`), `<tool>` — имя, которым
инструмент будет вызывать модель (`list_wall_report`). Строчные латинские
буквы, цифры, подчёркивание.

`--get` — если инструмент только **читает** модель. Это важнее, чем кажется:
читающий маршрут не открывает транзакцию.

## Как это выглядит целиком

```bash
python revitmcp_kit.py new wall_report list_wall_report --get --author "Иван Иванов"
```

Создаётся `wall_report-tool/`:

```
wall_report-tool/
  manifest.json                    кто автор, какие инструменты
  revit_mcp/wall_report.py         маршрут внутри Revit (IronPython 2.7)
  tools/wall_report_tools.py       инструмент для модели (Python 3)
  NOTES.md                         что сделали и как проверяли
```

Дальше вы заполняете `TODO`. **Ваше решение — только алгоритм и докстринг.**
Структура файлов, имена функций, сигнатуры и регистрация уже заданы и трогать
их не надо: ими проверяется совместимость с сервером.

```bash
cd wall_report-tool
python ../revitmcp_kit.py check
python ../revitmcp_kit.py probe
python ../revitmcp_kit.py pack
```

Готовый `wall_report.zip` положите в папку приёма:

```
\\srv-dfs\BIM\01_Ресурсы плагинов\827_RevitMCP\inbox\
```

Дальше пакет проверяет и добавляет в репозиторий сопровождающий. Авторство
сохраняется — оно берётся из `manifest.json`.

## Что делает `probe` и почему он важен

`check` проверяет **форму**: кодировку, диалект, сигнатуры, докстринг. Он не
знает, возвращает ли ваш маршрут правильные данные.

`probe` берёт текст вашего маршрута, отправляет его в `/execute_code/` вашего
собственного Revit, подставляет вместо сервера заглушку и вызывает ваш
обработчик **на реальной открытой модели**. Репозиторий для этого не нужен, и
Revit перезапускать не надо.

Для маршрута с телом запроса:

```bash
python ../revitmcp_kit.py probe --payload '{"example": "OST_Walls"}'
```

Зелёный `check` — это не «работает». Работает — это `PROBE_OK` с осмысленными
данными.

## Главное, что ломается

**f-строка в `revit_mcp/`.** Этот файл исполняется IronPython 2.7 внутри
Revit — там нет f-строк. Только `"{}".format(x)`. Иначе домен не загрузится, и
никакой внятной ошибки не будет. `check` это поймает.

**Транзакция без `suppress_warnings`.** Если ваш маршрут пишет в модель,
оставьте блок транзакции ровно как в шаблоне. Без `suppress_warnings(t)` сразу
после `t.Start()` штатное предупреждение Revit открывает модальное окно и вешает
сервер — у всех, навсегда, пока человек не нажмёт кнопку.

**`DB.ElementId(<int>)`.** На Revit 2027 падает. Только `make_element_id()`.

**Миллиметры.** Всё, что уходит наружу и приходит снаружи, — в миллиметрах.
Внутри Revit футы, конвертация в маршруте через `MM_TO_FEET`.

Полный список — в `AGENTS.md`. Его же читает ваш ИИ-ассистент.

## Докстринг — это не документация

Докстринг инструмента в `tools/*_tools.py` — единственное, что языковая модель
видит перед вызовом. Из него строится схема. Поэтому он пишется **для модели**:
не «что делает функция», а «когда это вызывать, с чем, и что придёт».

Обязательно: правила области, конкретные примеры значений, единицы измерения и
**ограничения прямым текстом**. Без ограничений модель примет пустой результат
за доказательство отсутствия — и сообщит пользователю неверный вывод о модели.

`check` не пропустит пакет с `TODO` в докстринге.

## Чего в пакет не входит

Пакет — это ровно два модуля, манифест и заметки. Приёмка **отклоняет** архив,
в котором есть что-либо ещё: правки общих файлов, дополнительные модули, данные.
Если задача этого требует — обсудите с сопровождающим до того, как писать код.

## Не редактируйте `conventions.py`

Это точная копия файла, по которому сдачу проверяет сопровождающий. Расхождение
означает, что `check` скажет «всё хорошо», а приёмка откажет.
