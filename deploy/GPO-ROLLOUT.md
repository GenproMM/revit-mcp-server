# RevitMCP 2.0 — подготовка машин через групповую политику

Для администратора домена. Как подключить скрипт `gpo-prep.ps1` при входе
пользователя, что он делает, как проверить результат и как всё вернуть.

## Зачем это нужно

Файлы RevitMCP доставляются пользователям без ГПО: при входе в Windows их
обновляет задача «RevitMCP Update» (или ярлык в автозагрузке), а часть внутри
Revit загружается с сетевой папки при каждом запуске Revit. Но у части машин
есть две проблемы, которые обновление само не исправит:

| Проблема | Что будет в 2.0 без исправления |
|---|---|
| pyRevit работает на движке IronPython 2.7 (IPY2712) | Расширение загружается, но все изменения модели отказывают с ошибкой 401 |
| В настройках pyRevit нет `host = "127.0.0.1"` для Routes | Работает, но служба Revit доступна из сети, а статус показывает `degraded` |

Плюс машины, где установщик не смог настроить автообновление: туда новая
версия сама не приедет.

## Что делает скрипт

При входе пользователя, **только если RevitMCP у него установлен и Revit закрыт**:

1. Если pyRevit на движке IPY2712 — переключает на IPY342
   (`pyrevit attach master 342 --attached`). Это стандартный движок парка; он
   меняется для всех расширений pyRevit на этой машине.
2. Если в разделе `[routes]` файла `%APPDATA%\pyRevit\pyRevit_config.ini` нет
   строки `host` — добавляет `host = "127.0.0.1"`, предварительно сохранив копию
   файла. Существующий `host` не меняет; если раздела `[routes]` нет, ничего не
   создаёт.
3. Запускает обновление `\\srv-dfs\BIM\06_RevitMCP\install\update.cmd`, но
   **только** если расширение пользователя зарегистрировано с этой же папки.
   Тестировщиков пилота (`06_RevitMCP_pilot`) скрипт не переводит на основную
   версию.

Всё записывается в журнал `%LOCALAPPDATA%\RevitMCP\gpo-prep.log`. Скрипт не
останавливает вход в систему и не показывает окон; ошибка одного шага
записывается в журнал, остальные шаги выполняются.

У пользователей без RevitMCP скрипт ничего не делает и журнал не пишет.

## 1. Положить скрипт на сервер

1. Создайте папку `\\srv-dfs\BIM\06_RevitMCP\gpo\`.
2. Скопируйте в неё `gpo-prep.ps1` (из репозитория, папка `deploy`).
3. Права на папку: **пользователям — только чтение**, запись — только
   администраторам. Скрипт выполняется от имени каждого пользователя, поэтому
   изменить его не должен никто, кроме вас.

## 2. Сначала проверить на нескольких машинах (пробный режим)

1. Создайте группу безопасности, например `RevitMCP-GPO-Test`, и добавьте в
   неё 2–3 пользователей.
2. Создайте GPO по шагам раздела 3, но в параметрах допишите в конец ` -DryRun`,
   а в «Фильтрации безопасности» GPO оставьте только эту группу.
3. После их входа в систему откройте у них `%LOCALAPPDATA%\RevitMCP\gpo-prep.log`.
   В пробном режиме скрипт ничего не меняет, а только пишет, что сделал бы:
   `DRY RUN would attach…`, `DRY RUN would add host…`, `DRY RUN would run…`.
4. Если записи разумные — уберите ` -DryRun` и повторите проверку уже по-настоящему
   на тех же машинах (раздел 4).

## 3. Настроить GPO

В консоли **Group Policy Management (gpmc.msc)**:

1. Создайте GPO, например `RevitMCP - prep`, и привяжите её к OU с
   пользователями Revit.
2. Откройте её на изменение: **User Configuration → Policies → Windows Settings →
   Scripts (Logon/Logoff) → Logon**.
3. На вкладке **Scripts** (не «PowerShell Scripts») нажмите **Add**:
   - **Script Name:** `powershell.exe`
   - **Script Parameters:**
     `-NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File "\\srv-dfs\BIM\06_RevitMCP\gpo\gpo-prep.ps1"`
4. **Задержка скриптов входа.** По умолчанию Windows запускает скрипты входа
   через 5 минут после входа. Если за это время пользователь откроет Revit,
   скрипт ничего не изменит (запишет `Revit is running`) и сработает при
   следующем входе. Чтобы срабатывал сразу: **Computer Configuration →
   Policies → Administrative Templates → System → Group Policy → Configure Logon
   Script Delay** = Enabled, 0 минут (политика компьютера, для машин этих
   пользователей).

## 4. Как проверить

На машине пользователя, после входа:

- `gpresult /r` — в разделе пользователя должна быть применённая GPO `RevitMCP - prep`;
- `%LOCALAPPDATA%\RevitMCP\gpo-prep.log` — последние строки за сегодня:

  ```
  start: user ivanov, share \\srv-dfs\BIM\06_RevitMCP
  engine: attach master 342 --attached, exit 0
  engine: now IPY342
  routes: added host = "127.0.0.1"; port = 48884; backup …
  update: ran \\srv-dfs\BIM\06_RevitMCP\install\update.cmd, exit 0
  done
  ```

  На уже настроенной машине — `engine: ok (…)` и `routes: host already set; kept`.
  `stop: Revit is running` — нормально, скрипт сработает при следующем входе.
  `engine: STILL IPY2712` или строки `ERROR` — сообщите сопровождающему RevitMCP.

## 5. Порядок раскатки 2.0

1. **За неделю до выпуска** включите GPO (сначала пробный режим, потом рабочий).
   Для текущей версии 09.17 изменения безвредны, поэтому машины готовятся заранее.
2. Сопровождающий публикует 2.0 в `\\srv-dfs\BIM\06_RevitMCP` вне рабочего времени.
3. При следующем входе скрипт и задача обновления привозят новую версию;
   пользователи полностью перезапускают Revit и перезапускают Гену.
4. После раскатки GPO можно оставить: на настроенной машине она ничего не меняет,
   а новым пользователям поможет. Или отвязать — на работу RevitMCP это не влияет.

## 6. Как вернуть

- **Отключить скрипт:** отвяжите GPO от OU. Уже сделанные изменения остаются.
- **Вернуть движок** (только если старый движок нужен другому расширению):
  при закрытом Revit выполнить
  `"%APPDATA%\pyRevit-Master\bin\pyrevit.exe" attach master 2712 --attached`.
  RevitMCP 2.0 на нём работать не будет.
- **Вернуть настройки pyRevit:** при закрытом Revit заменить
  `%APPDATA%\pyRevit\pyRevit_config.ini` копией
  `%LOCALAPPDATA%\RevitMCP\pyRevit_config.before-gpo-<дата>.ini`.
