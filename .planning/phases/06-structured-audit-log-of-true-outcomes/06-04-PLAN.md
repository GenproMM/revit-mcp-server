<threat_model>
ASVS level 1; block on high. Every high threat below is mitigated in this plan.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client -> published tool schema | every client learns the new user_request parameter from the schema |
| MCP server -> pyRevit Routes (POST envelope) | call_id joins the secret in the reserved _mcp envelope |
| concurrent MCP requests inside one server process | each request runs in its own task with its own contextvar state |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-18 | Denial of service | Revit gate rejecting an envelope with an extra key | high | mitigate | row runs the real gate_or_response on an envelope carrying call_id and proves acceptance and stripping before the bridge sends it (Task 2) |
| T-06-19 | Spoofing | model pre-seeding _mcp.call_id in tool data | medium | mitigate | with_envelope keeps refusing any data that already holds _mcp (existing pin); call_id is set only by the bridge from the contextvar (Task 2) |
| T-06-20 | Repudiation | call_id cross-wired between concurrent calls | medium | mitigate | contextvar set per tool call in its own task; concurrency row asserts distinct ids and no cross entries (Task 2) |
| T-06-21 | Denial of service | JSON-looking user_request failing schema validation | medium | mitigate | BeforeValidator turns pre-parsed lists/dicts back into text; rows for '{"a":1}', '[1,2]', '42', 'null' (Task 1) |
| T-06-22 | Tampering | wrapper silently changing other parameters of the 59 tools | medium | mitigate | wrapped vs plain schema comparison over the whole surface (Task 1) |
</threat_model>
