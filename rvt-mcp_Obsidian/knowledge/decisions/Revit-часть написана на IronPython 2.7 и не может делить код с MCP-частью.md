# Revit-часть написана на IronPython 2.7 и не может делить код с MCP-частью

> [!warning] Частично устарело (2026-09-07)
> Целевой движок парка сменился на IronPython 3 — см.
> [[Целевой рантайм Revit-половины — IronPython 3, не 2.7]]. Ограничение
> «не делить код с MCP-частью» и запрет f-строк/async/pathlib остаются в силе
> без изменений. А вот правило импорта хелперов ниже (`from utils import ...`,
> «верхний уровень, не относительно») — **инвертировано**: теперь требуется
> `from .utils import ...`. Читайте этот файл только для истории решения, за
> текущим правилом — в новую заметку.

## Решение

`revit_mcp/` и `startup.py` пишутся на диалекте Python 2.7 под IronPython.
`main.py` и `tools/` — на CPython 3.11+. Код между половинами не переиспользуется
**никогда**, даже когда логика идентична.

## Обоснование

Это не выбор, а вынужденное следствие: Revit API — это .NET, и pyRevit исполняет
скрипты в IronPython 2.7 на CLR внутри процесса Revit. Другого способа дотянуться до
`revit.doc` не существует. Одновременно `pyproject.toml` требует `>=3.11`, потому что
MCP SDK современный async-код.

Попытка «поднять» Revit-половину до Python 3 — это миграция на CPython-путь pyRevit,
а не апгрейд, и краткосрочного плана для неё нет.

## Как это применять

**В `revit_mcp/` запрещено:**

- f-строки → только `"...{}".format(x)`
- `list[str]`, `dict[str, int]` и любые современные тайп-хинты
- `async` / `await`
- `pathlib`
- любые CPython-only библиотеки

**В `revit_mcp/` обязательно:**

- заголовок `# -*- coding: UTF-8 -*-` в начале каждого файла
- `from StringIO import StringIO` вместо `io.StringIO`
- импорт хелперов как `from utils import ...` — верхний уровень, **не** относительно,
  потому что pyRevit кладёт каталог модуля в `sys.path`

**В `tools/` разрешено всё:** `async def`, `list[str]`, f-строки.

## Цена решения

Хелперы дублируются: `revit_mcp/utils.py` и `tools/utils.py` — **два никак не связанных
файла с одинаковым именем**. Первый про ElementId и транзакции, второй про
форматирование ответов. Их легко спутать при чтении логов и стектрейсов.

Более серьёзное последствие: `from utils import ...` делает все 20 модулей маршрутов
неимпортируемыми вне загрузчика расширений pyRevit. Их нельзя юнит-тестировать, нельзя
прогнать линтером с разрешением импортов, нельзя запустить под CPython. Любой другой
`utils` на пути их затеняет.

Именно это блокирует всё тестовое покрытие Revit-стороны — см.
[[Тесты — это самостоятельные скрипты, а не pytest-сьют]] и [[Текущие приоритеты]].
