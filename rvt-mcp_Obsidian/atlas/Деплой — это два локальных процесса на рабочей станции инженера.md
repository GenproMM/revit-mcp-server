# Деплой — это два локальных процесса на рабочей станции инженера

Проект нигде не хостится. Обе половины запускаются на машине пользователя, MCP-сервер
слушает только петлю. Продакшен и разработка тут — одно и то же окружение.

## Предпосылки

| Требование | Детали |
|---|---|
| Windows 10/11 | Revit только под Windows |
| Autodesk Revit | 2024, 2025, 2026 или 2027 |
| pyRevit | Установлен и загружен в Revit |
| `uv` | Пакетный менеджер Python |
| Открытый проект в Revit | Инструментам нужен активный документ |

## Шаг 1 — pyRevit и Routes Server

1. Установить pyRevit из релизов `pyrevitlabs/pyRevit` (`.exe`-инсталлятор, все
   значения по умолчанию).
2. Перезапустить Revit — во вкладках ленты должен появиться **pyRevit**.
3. pyRevit → **Settings** (шестерёнка) → раздел **Routes** слева.
4. Включить **Enable Routes Server** → **Save Settings**, дать pyRevit перезагрузиться.
5. Проверка: `http://localhost:48884/` в браузере отвечает (не «connection refused»).

## Шаг 2 — установка расширения (Revit-половина)

Внутри Revit должны работать `startup.py` и папка `revit_mcp/`.

**Вариант A, из pyRevit (рекомендуемый):** Revit → вкладка pyRevit → Extensions →
найти «MCP Server for Revit Python» → Install → дождаться перезагрузки pyRevit.

**Вариант B, вручную:**

1. Скопировать всю папку репозитория в `%APPDATA%\pyRevit\Extensions\`.
2. Переименовать в `mcp-server-for-revit-python.extension`.
3. pyRevit → Settings → Custom Extensions → добавить путь к `.extension`-папке.
4. Перезагрузить pyRevit или перезапустить Revit.

Дескриптор расширения — `extension.json`: `type: extension`,
`rocket_mode_compatible: True`, без зависимостей.

## Шаг 3 — проверка связи

```
http://localhost:48884/revit_mcp/status/
```

Ожидаемый ответ:

```json
{
  "status": "active",
  "health": "healthy",
  "revit_available": true,
  "document_title": "your_project_name",
  "api_name": "revit_mcp"
}
```

## Шаг 4 — MCP-сервер (CPython-половина)

```bash
git clone <repo>
cd revit-mcp-server
uv sync
uv run main.py
```

## Шаг 5 — подключение клиента

**Claude Desktop / Claude Code** — stdio:

```json
{
  "mcpServers": {
    "revit": {
      "command": "uv",
      "args": ["run", "main.py"],
      "cwd": "/path/to/revit-mcp-server"
    }
  }
}
```

**Cursor / Windsurf и прочие** — HTTP: `uv run main.py --streamable-http`, затем
подключение к `http://localhost:8000/mcp`.

Полный разбор режимов — [[MCP-клиенты подключаются четырьмя транспортами]].

## Отладка вручную

```bash
mcp dev main.py     # MCP Inspector на http://127.0.0.1:6274
```

## Чего нет

- **CI/CD.** Каталога `.github/` не существует, workflow-файлов нет. Тесты гоняются
  руками как скрипты.
- **Аутентификации.** Ни на MCP-сервере, ни на сервере Routes. Модель доверия — «только
  петля». См. [[execute_code даёт неаутентифицированное исполнение кода внутри Revit]].
- **Мониторинга.** Ни Sentry, ни APM. Логи Revit-стороны идут в лог pyRevit; stdio-режим
  MCP-сервера не пишет ничего.
- **Сборки пакета.** `pyproject.toml` без build-backend, проект запускается из исходников.
