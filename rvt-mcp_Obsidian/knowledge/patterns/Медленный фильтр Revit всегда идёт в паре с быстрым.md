# Медленный фильтр Revit всегда идёт в паре с быстрым

## Правило

Revit делит фильтры коллектора на **быстрые** (quick) и **медленные** (slow). Быстрый
работает по записи элемента, не поднимая его в память. Медленный требует раскрыть
элемент и, как правило, посчитать геометрию.

`ElementIntersectsElementFilter` — медленный. Поэтому он **никогда** не применяется в
одиночку: сначала быстрый категорийный фильтр максимально сужает набор, и только потом
раскрывается геометрия.

Это зафиксировано в докстринге модуля `revit_mcp/clash.py` как best-practice-заметка.

## Как это выглядит

```python
hits = (
    DB.FilteredElementCollector(doc)
    .WherePasses(b_filter)                                    # быстрый: ElementMulticategoryFilter
    .WhereElementIsNotElementType()                           # быстрый
    .WherePasses(DB.ElementIntersectsElementFilter(elem))     # медленный — последним
)
```

Порядок в цепочке имеет значение: медленный фильтр ставится **последним**, чтобы он
получил уже суженный набор.

## Дружелюбные псевдонимы категорий

Отдельная часть паттерна: вызывающему не нужно знать точные идентификаторы
`BuiltInCategory`. Модуль держит таблицу псевдонимов:

```python
_FRIENDLY = {
    "walls": "OST_Walls",
    "beams": "OST_StructuralFraming",
    "framing": "OST_StructuralFraming",
    "structural framing": "OST_StructuralFraming",
    "ducts": "OST_DuctCurves",
    "pipes": "OST_PipeCurves",
    ...
}

def _resolve_bic(name):
    n = str(name).strip()
    if not n.startswith("OST_"):
        n = _FRIENDLY.get(n.lower(), n)
    return getattr(DB.BuiltInCategory, n, None)
```

Принимается и то, и другое. Нераспознанные имена собираются в `unknown` и возвращаются
клиенту вместе с подсказкой — см.
[[Коды статусов 400, 404, 500, 503 несут фиксированный смысл]].

Обратите внимание: несколько псевдонимов ведут на одну категорию («beams», «framing»,
«structural framing» → `OST_StructuralFraming`). Это осознанно — модель может назвать
одно и то же по-разному.

## Разумный дефолт области

`_DEFAULT_CATEGORIES` — физические категории архитектуры, конструкций и MEP, которые
интересуют большинство координационных задач. Если категории не заданы вообще,
проверяется этот набор против себя.

## Что здесь всё ещё медленно

> [!warning] O(|A|) полных проходов по документу
> На **каждый** элемент множества A запускается свежий коллектор с медленным фильтром
> по всему документу. На реальной модели множество A — тысячи элементов, и каждый
> запускает полную геометрическую работу.

**Путь исправления:** предфильтровать множество B по `BoundingBoxIntersectsFilter`
(быстрый) **до** применения медленного пересечения, и ограничивать размер множества A
явным параметром `max_elements`, а не только количеством результатов.

Сейчас есть только `max_clashes` (по умолчанию 200) с флагом `truncated` в ответе.

## Ограничение, которое не обойти

Часть коллизий Revit не сообщает **никогда**: самосоединяющиеся элементы (бетон,
соединённый на пересечении) и элементы без телесной геометрии (например, арматура).
Это ограничение Revit, а не дефект инструмента — и оно указано и в докстринге модуля,
и в ключе `note` успешного ответа.
