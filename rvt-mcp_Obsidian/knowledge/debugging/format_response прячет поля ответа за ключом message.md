# format_response прячет поля ответа за ключом message

## Симптом

`start_revit` возвращал структурированный словарь (`status`, `already_running`,
`version`, `message`, ...), но docstring обещал модели все эти поля. При
проверке через `format_response` в вывод попадало только содержимое `message` —
остальные поля пропадали молча.

## Причина

`tools/utils.py:format_response()` в успешной ветке проверяет ключи по
приоритету: `output` → `message` → `result` → `data` → generic-фолбэк.
Если есть `message`, функция возвращает **только его** — это раздел кода,
который существовал для простых ответов вида `{"message": "..."}`, но не
предполагал, что кто-то положит `message` рядом с другими значимыми полями.

Это не баг самой `format_response` — контракт всегда был таким
(см. существующую заметку [[get_revit_model_info показывал данные под ложным
заголовком ошибки]] про соседнюю часть той же функции). Баг был в
предположении нового кода, что словарь пройдёт насквозь.

## Фикс

`process_tools.py` не использует ключ `message` для составных ответов —
переименовано в `outcome` (вместо `status`, чтобы не путать со статусом моста)
и `next_step` (вместо `message`). Оба этих имени проваливаются в
generic-фолбэк `format_response`, который рендерит **все** поля построчно
`Field: value`.

## Урок

Любой новый словарь, который тула возвращает через `format_response`, нужно
собирать в обход зарезервированных ключей `output`/`message`/`result`/`data` —
иначе часть полей молча исчезнет. Общая заметка про этот контракт:
[[Провал ответа определяется только ключом error или явным статусом]] — стоит
дополнить её тем, что и *успешная* ветка сплющивает поля, а не только тем, что
неявный `error` не считается провалом.
