tree (in particular whatever is on the main share when R3 is released) ignores an extra `_mcp` key in
every POST body: no handler iterates, copies, echoes or forwards the parsed body, and none reads
`request.data` outside `parse_request_data`. Run it on the pre-phase tree now and record the result.

Purpose: D-05 (payload first, then ext) is safe only if the extension already on the share tolerates
the envelope the new bridge sends (D-06). RESEARCH Open Question 3 scanned HEAD by hand and found only
rebinding false positives; this makes that check repeatable, rebinding-aware and runnable by the
administrator against the share.

Output: `scripts/scan_envelope_tolerance.py` and its tests; the pre-phase result in the SUMMARY.
</objective>
