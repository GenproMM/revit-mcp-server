# Широкий except Exception используется как поток управления

**Это антипаттерн, но он системный — 60+ вхождений по `revit_mcp/`.**

## Где густо

| Модуль | Вхождений |
|---|---|
| `revit_mcp/analysis.py` | 22 |
| `revit_mcp/building.py` | 13 |
| `revit_mcp/colors.py` | 7 |

Типичная форма — `except Exception: pass` или `except Exception: continue`.

## Почему так вышло — и где это оправдано

Revit API выбрасывает по любому поводу: элемент удалён другим пользователем, у элемента
нет геометрии, свойство недоступно для этого подтипа, семейство заблокировано, элемент
пришёл из связанной модели. Перебирая тысячу элементов, часть пропустить — нормально
и ожидаемо.

Оправданные случаи в проекте:

```python
try:
    name = element.Name
except AttributeError:                       # ← узкое исключение, осознанно
    name = DB.Element.Name.__get__(element)
```

```python
try:
    return int(eid.Value)                    # 2024+
except (AttributeError, TypeError):          # ← перечислены конкретные
    pass
```

Здесь исключение действительно часть контракта API, и типы указаны точно.

## Где это вредит

> [!warning] Настоящий дефект неотличим от ожидаемого промаха
> Опечатка в имени свойства, изменившаяся после апгрейда Revit сигнатура метода,
> `None` там, где ожидался объект — всё это выглядит ровно как «у этого элемента нет
> геометрии, идём дальше».

Три конкретных последствия, уже проявившихся:

1. [[tag_walls молча пропускал стены и возвращал отмечено 0]] — результат стал
   недиагностируемым.
2. [[Пакетные операции возвращают success, скрывая пропущенные элементы]] — ответ
   говорит «успех», скрывая пропуски.
3. [[suppress_warnings глушит собственный сбой и оставляет транзакцию без защиты]] —
   отказ защиты живости стал невидимым.

## Правило при правках

Трогая существующий широкий `except`, **сузьте его**:

```python
# было
except Exception:
    continue

# стало
except (AttributeError, Autodesk.Revit.Exceptions.InvalidObjectException) as e:
    logger.warning("Skipping element {}: {}".format(eid, str(e)))
    skipped.append({"element_id": eid, "reason": str(e)})
    continue
```

Два изменения, оба обязательны:

1. **Конкретные типы исключений** — тогда неожиданное всплывёт наружу.
2. **Лог на уровне warning плюс запись в `skipped`** — тогда пропуск станет видимым.

Не нужно переписывать все 60 вхождений разом. Правило работает при касании: если вы
редактируете функцию, содержащую широкий `except`, — сузьте именно этот.

## Отдельно: `except Exception: pass` в best-effort-хелперах

`suppress_warnings`, `normalize_string` намеренно не выбрасывают, потому что их сбой не
должен ломать вызывающего. Это допустимо, **но они обязаны логировать факт своего
сбоя**. Молчаливый best-effort — это не устойчивость, это невидимая поломка.
