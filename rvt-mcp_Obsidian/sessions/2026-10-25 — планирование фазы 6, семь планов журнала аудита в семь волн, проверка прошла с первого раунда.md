# Планирование фазы 6: семь планов журнала аудита в семь волн, проверка прошла с первого раунда

## Результаты

- `/gsd-plan-phase 6`. Контекст D-01…D-20 из обсуждения, исследования раньше не было. Пользователь выбрал «Исследовать сначала».
- **Исследование** (`06-RESEARCH.md`, уверенность HIGH). Главные выводы прототипированы на этой машине:
  - обёртку инструментов ставит `main.py` (`audit.install_audited_tools(mcp)`), а не `tools.register_tools`, иначе ломаются `test_phase2_inventory` и `test_tool_forwarding_*` (там `names[-1] == "ctx"`);
  - FastMCP 1.9.0 `pre_parse_json` превращает JSON-похожий `user_request` в dict, нужен pydantic `BeforeValidator`;
  - стандартный `RotatingFileHandler` на Windows теряет записи при открытом читателе (WinError 32), нужен свой обработчик сегментов без переименования;
  - блок `outcome` не содержит `status`, ярлык исхода берётся из верхнеуровневого `status` ответа;
  - фейковый Revit в процессе теста проходит настоящую проверку владельца порта, поэтому rollback, partial, 401, 423 и unknown проверяются офлайн через настоящий мост.
- **Стратегия валидации** `06-VALIDATION.md` заполнена из раздела Validation Architecture.
- **Карта паттернов** `06-PATTERNS.md`: 17 файлов, для 16 найден аналог. Для обработчика сегментов аналога нет.
- **Проба граничных случаев** (spec-less): 22 пункта, планировщик разложил их на 19 явных истин и 3 помеченных допущения (AUDIT-05/06/08 не классифицированы).
- **Планы**: 7 планов, 7 последовательных волн. Почти каждый план правит `audit.py` и/или `bridge.py`.
  - 06-01 — сквозной трассер: один вызов → одна строка JSONL → `Audit: call_id` в ответе; `audit.py` в payload.
  - 06-02 — полная схема 1 и таблица исходов.
  - 06-03 — пользователь, аргументы, `user_request`, редактирование секрета, grep файла на секрет.
  - 06-04 — `user_request` во всех инструментах, общий `call_id`, `_mcp.call_id`.
  - 06-05 — ротация и очистка, два экземпляра Revit, два процесса сервера, чистый stdio, документация.
  - 06-06 — одноразовый живой скрипт и его классификатор.
  - 06-07 — живой шлюз руками пользователя (неавтономный).
- **Проверка планов** прошла с первого раунда, только INFO. Проверка была облегчённой (фронтматтер, решения, счётчики).
- Гейты: требования 8/8, решения 20/20, пост-анализ 28/28.
- Коммиты: `e81b68f` (исследование и валидация), `93226d8` (планы, PATTERNS, STATE, ROADMAP).
