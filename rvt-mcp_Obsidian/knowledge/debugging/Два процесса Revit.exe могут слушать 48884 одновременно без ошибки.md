# Два процесса Revit.exe могут слушать 48884 одновременно без ошибки

**Статус:** известное поведение среды, задокументировано в CLAUDE.md ·
найдено при первом самостоятельном запуске Revit на локальной машине для
тестового прогона (без пилотной станции, без сети компании)

## Симптом

После `Start-Process Revit.exe` и ожидания через опрос `/status/` ответы
чередовались — то `revit_available: true` с реальным документом, то
`"error": "No active Revit document"` — при том что видимого второго окна
Revit не было и пользователь ничего не открывал.

## Причина

`Get-NetTCPConnection -LocalPort 48884 -State Listen` показал **два** PID в
состоянии `LISTENING` на `127.0.0.1:48884` одновременно. `tasklist`
подтвердил два процесса `Revit.exe`, оба версии 2024, разница в старте —
31 секунда. Рабочая гипотеза: `RevitAccelerator.exe` (виден в фоновых
процессах с самого начала сессии) прогревает второй скрытый инстанс Revit
самостоятельно.

pyRevit'овский Routes-сервер не выставляет `SO_EXCLUSIVEADDRUSE`/аналог при
биндинге — ОС не мешает второму процессу занять тот же порт, и не выдаёт
никакой ошибки ни одному из них. Дальше каждый входящий запрос уходит **тому
процессу, которого выберет сам стек ОС** — недетерминированно, не по
round-robin и не по какой-либо предсказуемой логике. Открыть модель в одном
инстансе не гарантирует, что следующий запрос попадёт именно в него.

## Диагностика

`netstat -ano | findstr 48884` показывает обе строки `LISTENING`, но не
объясняет, какая учитывается ОС для нового соединения — только
`Get-NetTCPConnection` даёт удобный список `OwningProcess`. Убедиться, что
активен ровно один процесс, до того как доверять любому результату —
`@(Get-NetTCPConnection -LocalPort 48884 -State Listen).Count` должен
вернуть `1`.

## Обход

Закрыть оба процесса (`Stop-Process -Name Revit -Force`), подождать 5-10 с,
запустить ровно один, и **перед первым запросом** подтвердить
`LISTENERS=1` через `Get-NetTCPConnection`. Других надёжных признаков
(заголовок окна, что угодно из `tasklist`) недостаточно — оба процесса
выглядят одинаково снаружи, пока не запросишь именно сетевой стек.

## Урок

> «Порт свободен, приложение не жалуется» не означает «ровно один слушатель».
> Для любого локального HTTP-моста, который тестируется вручную через
> перезапуски, стоит проверять число слушателей явно перед тем как доверять
> первому же 200 OK — иначе результат теста может относиться не к тому
> процессу, который был только что перезапущен с новым кодом.
