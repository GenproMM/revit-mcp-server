# Save и SaveAs выполняются вне транзакции

## Решение

`revit_mcp/document.py` — единственный модуль маршрутов, который **сознательно не
открывает транзакцию**. Это записано в его докстринге как предупреждение.

То же относится к `LoadFamily` в `revit_mcp/placement.py`.

## Обоснование

Revit API не допускает `SaveAs` внутри активной транзакции — вызов упадёт. `LoadFamily`
управляет своей собственной транзакцией и не терпит чужую.

Это стало практической проблемой: до появления отдельного маршрута единственным
способом что-то сохранить был `execute_code`, а он **всегда** оборачивает всё в
транзакцию. Соответственно сохранить модель было в принципе невозможно, и любая работа
терялась при перезапуске или падении Revit.

Отсюда решение сделать выделенный, транзакционно-свободный маршрут `save_document`.

## Логика маршрута

```
если передан file_path:
    создать родительский каталог, если его нет
    SaveAsOptions(OverwriteExistingFile = overwrite)
    ConvertUserVisiblePathToModelPath(file_path)
    doc.SaveAs(...)  →  operation: "save_as"
иначе если doc.PathName пустой:
    400 — «документ ни разу не сохранялся, передайте file_path»
иначе:
    doc.Save()       →  operation: "save"
```

Особый случай, который здесь обрабатывается: документ, созданный **из шаблона**, ещё не
имеет реального пути на диске, поэтому его нельзя `Save`, только `SaveAs`. Проверяется
через `doc.PathName` (и `doc.IsModelInPlace`, если атрибут есть), оба чтения обёрнуты в
`try`/`except`.

## Как это применять

> [!warning] Не оборачивайте новые маршруты персистентности в транзакцию
> Если добавляете что-то вроде `SaveAsCloudModel`, `SynchronizeWithCentral` или
> `LoadFamilySymbol` — сначала проверьте, управляет ли API своей транзакцией сам.

Признак: метод меняет **файл**, а не содержимое модели.

## Проверка

Маршрут был подтверждён сохранением модели Empire State Building высотой 443 м на диск —
см. [[Валидация продукта — сборка Empire State Building в живом Revit 2027]].
