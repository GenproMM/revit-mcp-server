# LLM.txt устарел и описывает структуру на 31 инструмент

**Требует действия.** Файл `LLM.txt` (34 КБ) предназначен именно для ИИ-ассистентов —
то есть ошибочно ориентирует ровно того потребителя, для которого написан.

## Что в нём неверно

**Количество инструментов.** Разделы «Available Tools» перечисляют 31 инструмент по
категориям (Status & Connectivity 2, Model Information 1, View & Image 4, Family &
Placement 3, Building Creation 3, Editing 3, Structure 2, Annotation 2, Analysis 4,
Documentation 3, Color 3, Code Execution 1). Фактически — **48**.

**Структура каталогов.** Описывает раскладку, которой больше нет:

```
revit-mcp-python/                              ← имя проекта другое
├── tools/
│   ├── __init__.py    # Tool registration system (12 modules)   ← сейчас 22
├── revit-mcp-python.extension/                ← такого каталога нет
│   ├── startup.py
│   └── revit_mcp/
```

Фактически `startup.py` и `revit_mcp/` лежат **в корне репозитория**, а не внутри
`.extension`-каталога.

**Отсутствующие модули.** В перечислении нет ни одного из модулей, добавленных
позже: `rooms`, `view_management`, `tags`, `transforms`, `mep`, `parameters`,
`interop`, `detail`, `clash`, `document`. Это 10 модулей маршрутов из 22.

**Отсутствующие возможности.** Ни слова про `check_clashes`, `save_document`,
`load_family`, поддержку Revit 2027, подавление модальных диалогов — то есть про всё,
что делает проект пригодным для работы без надзора.

## Что в нём ценно и стоит сохранить

Основной объём файла — **документация pyRevit Routes**, и она не устарела:

- что такое Routes и зачем;
- создание кастомного HTTP-API-расширения;
- методы запросов, route-параметры, request data, заголовки;
- возврат результатов, callback URL, исключения;
- конфигурация сервера, включая смену порта;
- pyRevit Core API.

Это полезный справочный материал, которого нет в README. Его надо не выбрасывать, а
отделить от устаревшей части.
