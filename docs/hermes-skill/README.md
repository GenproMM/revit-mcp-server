# Скилл Hermes для разработки инструментов

`SKILL.md` в этой папке — **источник правды**, но Hermes его отсюда не видит.

## Куда его класть

Каталог скиллов Гены — отдельный репозиторий:

```
MastermindServices/12_GenproAI_DomainSkills/skills/bim/revit-mcp-tool-dev/SKILL.md
```

Скопировать туда, закоммитить в том репозитории и собрать пакет отдела:

```bash
python scripts/build_pack.py BIM <версия>
```

## Что ещё нужно сделать в том репозитории

На момент написания каталог `skills/bim/` не соответствует собственным правилам
`12_GenproAI_DomainSkills/AGENTS.md`, и это надо закрыть, иначе скилл не
подхватится сканером:

- **Нет `skills/bim/DESCRIPTION.md`** — обязателен для каждого отдела.
- **Нет строки в таблице `README.md`** каталога скиллов.
- **Нужен `evals/`** — обязательный критерий приёмки того репозитория
  (вход + ожидаемый результат). Минимально: задача «добавить читающий
  инструмент» и ожидание, что ассистент запустит `scripts/new_tool.py --get`,
  а не начнёт писать файлы руками.

## Грабли frontmatter

Проверены по `12_GenproAI_DomainSkills/AGENTS.md`:

- **Двоеточие в `description` ломает весь frontmatter.** YAML не парсится,
  Гена откатывается на построчный разбор и молча теряет весь блок `metadata`
  вместе с гейтами. В `SKILL.md` здесь двоеточия нет — не добавляйте.
- `description` **обрезается на 60 символах** в системном промпте.
- `requires_toolsets` — реальный гейт. Выдуманное имя прячет скилл навсегда.
  Допустимые: `terminal, file, code_execution, web, search, vision, browser,
  memory, coding`.
- Блок `genpro:` кодом не исполняется — он для человеческой приёмки.

## Почему копия, а не ссылка

Регламент разработки меняется вместе с кодом этого репозитория: генератор,
состав тестов, имена файлов. Держать источник рядом с кодом — единственный
способ не разойтись. Скилл — это доставка, а не хранилище.

При изменении регламента: правим `SKILL.md` здесь, копируем туда, поднимаем
`version`.
