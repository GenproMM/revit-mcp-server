## Interface from 04-01 (import from `.utils`; do not edit utils.py or textutils.py here)

`commit_and_report(t, swallower)`, `finalize_outcome(commit_result, data, requested, succeeded,
failed)` returning `(payload, http)`, `build_outcome(transaction_status, requested, succeeded, failed,
revit_failures)`, `exception_outcome(t, requested, succeeded, failed)`, `transaction_status_of(t)`.
Route pattern, item convention, `requested` rule: 04-01-PLAN.md. In this plan: delete_elements, input
ids; modify_element, parameter names; export_ifc and link_file, the file path; save_document (no
transaction), the path the document now has or its title.

## Flagged assumptions (spec-less edge probe, TRUTH-02 unclassified edge)

- A3: the IFC exporter's own changes are committed with the export transaction, as today; Autodesk's
  sample rolls them back instead. D-06 says migrate onto `commit_and_report`, not change commit vs
  rollback, so this plan keeps the commit and records the question for the user.
- An id that Revit cascades into another requested id is still reported once in `deleted_ids` (the
  existing de-duplication), and `outcome.succeeded` lists the requested ids as given.
